== Preface

Every recipe in this book is two commands facing each other: a `surl` that listens and a `curl` that talks to it. Both programs are open source and both were written in C# on .NET 10 as a matched pair, so each recipe shows a protocol conversation from both ends.

=== Who This Book Is For

Anyone who needs a server to test against and does not want to install, configure and secure a real one: the person writing a deployment script, the test suite that needs a throwaway mail server, the agent that has to learn a protocol by talking to it.

=== How This Book Is Organised

Recipes run from simple to hard. The first part serves one file over plain Hypertext Transfer Protocol; the last holds protocols so new that the two programs learned them this year. A protocol appears wherever its difficulty puts it, so a protocol's "hello" is early and its authentication is late. Open at any recipe; each stands alone.

=== Conventions Used in This Book

`Constant width` marks commands, options, filenames and anything typed or printed. A line beginning `surl` or `curl` is a command to run; the block after it is what the command prints. Every recipe records the versions of the two programs it was verified against.

=== Getting the Programs

Everything the recipes run can be downloaded; nothing needs building. Every package this book uses is on nuget.org, and one search finds them all: https://www.nuget.org/packages?q=Surly.&includeComputedFrameworks=true&prerel=true[the Surly packages on nuget.org].

[cols="2,3,4",options="header"]
|===
| Package | What it is | How you get it
| `Surly.Surl.Console` | The `surl` program, a .NET tool | `dotnet tool install --global Surly.Surl.Console --version {surly-surl-console-version}`
| `Surly.Curl` | The `curl` program, a .NET tool | `dotnet tool install --global Surly.Curl --version {surly-curl-version}`
| `Surly.Surl.Api` +
`Surly.Curl.Api` +
`Surly.Libcurl` | The C# libraries | Named in each C# recipe{apos}s `#:package` lines; `dotnet run` fetches them
| `Surly.Surl.Mcp` +
`Surly.Curl.Mcp` | The two Model Context Protocol (MCP) hosts, .NET tools | `dotnet tool install --global`, below, or `dnx` in each agent recipe{apos}s `mcp.json`
|===

The search shows each package{apos}s latest version; the recipes were verified against the versions this book names, so install those with `--version`. The link already includes pre-release versions, which the Curl packages need while they are previews.

`curl` is the .NET tool `Surly.Curl` on nuget.org. With .NET 10 installed:

[source,shell,subs="attributes+"]
----
dotnet tool install --global Surly.Curl --version {surly-curl-version}
----

That puts this `curl` on your `PATH` ahead of the one your system came with, which is what the recipes expect, and every `curl` you type runs it while it is installed. `dotnet tool uninstall --global Surly.Curl` gives you your system's `curl` back. To use it for one command without installing it, `dnx Surly.Curl@{surly-curl-version} --yes --` followed by the arguments does the same.

`surl` is the .NET tool `Surly.Surl.Console`, installed the same way: `dotnet tool install --global Surly.Surl.Console --version {surly-surl-console-version}`, or `dnx Surly.Surl.Console@{surly-surl-console-version} --yes --` and its arguments for one command. Its command is `surl`, and `dotnet tool uninstall --global Surly.Surl.Console` removes it.

The C# recipes name their packages at the versions they were verified with, `Surly.Surl.Api` {surly-surl-api-version}, `Surly.Curl.Api` {surly-curl-api-version} and `Surly.Libcurl` {surly-libcurl-version}, and `dotnet run` fetches them from nuget.org. The agent recipes start the two Model Context Protocol (MCP) hosts by name, `surl-mcp` and `curl-mcp`, so install those tools as well:

[source,shell,subs="attributes+"]
----
dotnet tool install --global Surly.Surl.Mcp --version {surly-surl-mcp-version}
dotnet tool install --global Surly.Curl.Mcp --version {surly-curl-mcp-version}
----

Each agent recipe's `mcp.json` starts the same hosts with `dnx` instead, for an MCP client that should not need them installed.

=== For Machines

Do not read this book. The packages the recipes use are at https://www.nuget.org/packages?q=Surly.&includeComputedFrameworks=true&prerel=true, at the versions each recipe names. Read `generated/index.json`, which lists every recipe with its key, its one-sentence problem, its protocols, its options and its exit codes, then read the one recipe you need. `llms.txt` at the book root maps everything else.
