=== Running an HTTP Server with Nothing in It

==== Problem

You want a Hypertext Transfer Protocol server that answers but holds nothing, so a test can check how a client copes when the file it asks for is not there.

==== Solution

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

Without `--directory`, `surl` serves an empty store held in memory. It accepts every connection, so the client sees a working server, but there is nothing to find: a `GET` is answered `404 Not Found`. Nothing is written to disk, and whatever the server keeps is gone when the process ends (<<surl-readme>>).

`curl` sends the body to nowhere with `-o`, stays quiet with `-s`, and prints only the status code with `-w "%{http_code}"`. A `HEAD` request, which `-I` sends, gets the same `404`. The root path is no different: there is nothing to list, and `surl` lists nothing unless asked to.

Any method but `GET` and `HEAD` is another matter. `-X DELETE` sends a `DELETE`, and `surl` answers `401 Unauthorized`: a method that could change the store needs an account, and with none configured every login is refused. `-D -` writes the response headers to standard output, which shows what the `401` offers: Digest logins in `WWW-Authenticate` headers, with Secure Hash Algorithm 256 (SHA-256) among them (<<rfc9110>>). Letting a client store something is a separate recipe (<<http-accept-uploads>>).
