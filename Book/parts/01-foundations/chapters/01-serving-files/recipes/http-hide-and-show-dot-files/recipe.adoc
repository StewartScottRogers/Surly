=== Serving Dot Files on Purpose

==== Problem

You need a Hypertext Transfer Protocol server to serve a file whose path begins with a dot, such as `/.well-known/security.txt`, and `surl` answers it with `404 Not Found`.

==== Solution

Add `--serve-dot-files` to the `surl` command line:

include::.generated/solution.adoc[]

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

`--directory site` serves the files under `site`. By default a file or folder whose name begins with a dot is treated as not there, whatever is inside it (<<http-serve-a-directory>>). That is the safe default because dot names are where secrets and tool state live: `.env`, `.git`, `.ssh`. A directory that was never meant to be published often holds one.

`--serve-dot-files` turns the rule off, and it turns it off for every dot name, not only the one you wanted. With it, `/.env` is served as readily as `/.well-known/security.txt`, which is the reason to give the option only to a server whose directory you have looked at. `curl` with `-s` prints each body as it arrives.

One folder stays hidden whatever the options: `.surl`, where `surl` keeps its own state under the served directory. `-o` and `-w "%{http_code}"` show it answered `404 Not Found` with the option on (<<surl-readme>>).
