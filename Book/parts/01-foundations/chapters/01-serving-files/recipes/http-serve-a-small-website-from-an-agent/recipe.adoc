=== Serving a Small Website from an Agent

==== Problem

You want an artificial intelligence (AI) agent to stand up a small website over Hypertext Transfer Protocol (HTTP) with `start_server`{apos}s files, and confirm with `transfer` that every page, style and image has the `Content-Type` a browser expects.

==== Solution

Write the agent{apos}s side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts `surl-mcp` and `curl-mcp`, calls `start_server` with the site{apos}s text files and its image, then calls `transfer` for each path and reads `Content-Type` from the headers:

==== Discussion

`StdioClientTransport` starts each host by name from `PATH`, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine both to the folder the program runs in. `start_server` starts a server that answers as `surl` would, on the free port that `http://127.0.0.1:0` asks for; its structured content gives the real address in `bound_urls`. Its `files` argument holds the pages, style sheet, script, vector image and data as UTF-8 text, relative path to content, so `css/site.css` is served at `/css/site.css`. An image is bytes, not text, and goes in `files_base64`, the same map with base64 values; here it is the eight-byte Portable Network Graphics (PNG) signature.

`transfer` makes one request with only `url` set and answers in text, as JavaScript Object Notation (JSON). Its `headers` are a list of `name` and `value` pairs; names are case-insensitive (<<rfc9110>>), so the program compares them that way. `surl` names the type from the extension (<<surl-readme>>): `text/html`, `text/css`, `text/javascript`, `image/png`, `image/svg+xml` and `application/json`, with no `charset`, and `application/octet-stream` for `.xyz`, which it does not know.

The body comes back as text when it is valid UTF-8 and as base64 otherwise (<<curl-readme>>): the PNG{apos}s `isBase64` is true, and its `content` is the same base64 the agent gave `start_server`, so the bytes made the round trip unchanged.

There is no index page. The root path is answered `404 Not Found` with no `Content-Type`, and to `transfer` that is an answer, not a tool error, so an agent checking a site reads `statusCode` and opens `/index.html` by name.
