=== Fetching Files with Awkward Names

==== Problem

Your files have spaces, accented letters and a `#` in their names. You want to know how to write each Uniform Resource Locator (URL) so `surl` serves the file, and what a URL written the wrong way gets.

==== Solution

Percent-encode the file name in the URL: `%20` for a space, the two bytes of `é` as `%C3%A9`, and `%23` for a `#`. Three files, three URLs, one `curl`:

==== Discussion

A URL (<<rfc3986>>) has a fixed alphabet. Any other byte in a path is written as `%` and two hexadecimal digits, and `surl` decodes each one once before it looks for the file. The server holds the real names, `my file.txt`, `café.txt` and `a#b.txt`; the URL is only how a client says them. Accented letters are encoded as their bytes in UTF-8, so `é` is two bytes, `%C3%A9`. The digits may be written in lower case: `%c3%a9` reaches the same file.

The trouble is all on the client side, and `curl` does not always tell you. A raw space is the loud case: `curl` refuses the URL as malformed and exits `3` before it sends anything. A raw `#` is the quiet one, because in a URL it starts the fragment, and a fragment is for the client alone and is never sent. `curl` asks for `/a`, which is a different path. Here the folder also holds a file named `a`, so the wrong URL returns a file with a plausible answer and exit `0`; with no such file it would be a `404`. The two `-v` cases show the request line each form sends: `GET /a` for the raw `#`, `GET /a%23b.txt` for the encoded one.

Encoding that is well formed but says the wrong thing is a `404 Not Found`. `%E9` is `é` in Latin-1, a single byte that is not valid UTF-8, so it names no file. In a path a `+` is a plus and not a space, so `my+file.txt` is a different name. And encoding twice is decoded once: `a%2523b.txt` decodes to `a%23b.txt`, a name with the percent sign in it. As ever, `curl` reports each `404` with `-w "%{http_code}"` and exits `0`.

The folder is served with `--directory site`, as in <<http-serve-a-directory>>. `-s` keeps `curl` quiet, `-o` with the null device throws the body away when only the status or the request line matters, and `-v` shows the request line.

How you type the URL depends on the shell, which has its own idea about spaces and `#`. Encoded, a URL has neither, and needs no quoting for them.
