=== Fetching Awkwardly Named Files from an Agent

==== Problem

You want an artificial intelligence (AI) agent to fetch files whose names hold spaces, accented letters and a `#`, with Model Context Protocol (MCP) tool calls. You want it to build each Uniform Resource Locator (URL) with `build_url` and to be able to explain the `404`, or the wrong file, it gets when it skips the encoding.

==== Solution

Write the agent{apos}s side as a C# program on the official MCP software development kit (SDK). It starts `surl-mcp` and `curl-mcp`, seeds the four files with `start_server`, builds each URL with `build_url` and its `UrlEncode` flag, and fetches it with `transfer`:

==== Discussion

`StdioClientTransport` starts each host by name from `PATH`, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine them to the folder the program runs in; `mcp.json` beside this recipe is the same configuration for an agent{apos}s own client. The argument after `--` picks how the URL is built and which name is asked for.

`start_server` seeds the server through `files`, relative path to text, keyed by the real names: `my file.txt`, `café.txt` and `a#b.txt`, plus a plain `a` to show where a raw `#` leads. `build_url` is `curl-mcp`{apos}s URL builder. It sets the parts you give it, `scheme`, `host`, `port` and `path`, and returns `url`. With the flag `UrlEncode`, libcurl{apos}s `CURLU_URLENCODE` without its prefix, it percent-encodes the path as it goes: `%20` for the space, `%C3%A9` for the two UTF-8 bytes of `é`, `%23` for the `#` (<<rfc3986>>). The program prints the path it fetched, so the encoding is what you read. `transfer` takes that `url` and answers `200` for each file.

Without the flag `build_url` sets the path exactly as given, and an agent that skips the encoding meets two different failures. A space makes `transfer` refuse the URL: a tool error whose `failure` is `CurlExit` with `exitCode` 3, the code `curl` gives a malformed URL. A `#` is quieter. It starts the fragment, which is never sent, so the request is for `/a` and the answer is `200` with the file called `a`, not the file the agent meant. An agent that checks only `statusCode` will not notice; it has to read the body.

Encoding that is well formed but says the wrong thing is a `404 Not Found`, which is an answer: `statusCode` 404 with `surl`{apos}s short text body, `404 Not Found`, `failure` null, and not a tool error (<<rfc9110>>). `caf%E9.txt` is `é` in Latin-1, one byte that is not valid UTF-8. A `+` in a path is a plus, so `my+file.txt` is a different name. And a name that is already encoded, `a%23b.txt`, given to `build_url` with the flag has its percent sign encoded again, `a%2523b.txt`, and names no file; encode a name once, from the real one.
