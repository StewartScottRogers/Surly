=== Seeing the Status Line and Headers

==== Problem

You want to see exactly what a Hypertext Transfer Protocol server answered, its status line and headers as well as the body, to check a status code, a content type or a length.

==== Solution

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

`--directory site` makes `surl` serve the files under `site`, so `site/hello.txt` is `/hello.txt`. By default `curl` prints only the body. `-i` puts the response head in front of it: the status line, one header per line, a blank line, then the body. `-s` keeps the progress meter out of the way.

`-I` sends a `HEAD` request instead of `GET`. A server answers `HEAD` with the headers a `GET` would get and no body (<<rfc9110>>), so `curl` prints the head and stops; `Content-Length: 16` still says how long the body would have been.

When one value is all you want, `-w` writes it out after the transfer and `-o` sends the body to nowhere. `%header{server}` is the `Server` header, which `surl` fills with its own name; `%{content_type}` is `text/plain`, because the file ends in `.txt`; `%{size_download}` is the body's 16 bytes. The other headers `surl` sends, `Date` and `Last-Modified`, change with the clock and the file, so no claim here depends on them.

A missing path shows its head the same way, starting `HTTP/1.1 404 Not Found` (<<surl-readme>>).
