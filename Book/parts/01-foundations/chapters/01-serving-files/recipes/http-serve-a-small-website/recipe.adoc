=== Serving a Small Website

==== Problem

You want to serve a folder of pages, styles, scripts and images over Hypertext Transfer Protocol (HTTP) so a browser test gets each with the `Content-Type` its extension names, and to know what an unknown extension comes back as.

==== Discussion

`--directory site` serves every file under `site` at its relative path, so `site/css/site.css` is `/css/site.css` and the page{apos}s relative links resolve as they would on any web server. `surl` sets `Content-Type` from the file{apos}s extension (<<surl-readme>>): `.html` is `text/html`, `.css` is `text/css`, `.js` and `.mjs` are `text/javascript`, `.png` is `image/png`, `.svg` is `image/svg+xml` and `.json` is `application/json`. It looks only at the name; the fixture called `logo.png` is not a picture at all, and it is still `image/png`. The types carry no `charset` parameter.

An extension `surl` does not know, such as `.xyz`, and a file with no extension, such as `README`, are served as `application/octet-stream`, bytes of no stated kind (<<rfc9110>>). A test that needs a type for such a file should rename it to an extension `surl` knows. Images, icons, fonts and modules beyond the six above are typed too: `.jpg` is `image/jpeg`, `.ico` is `image/vnd.microsoft.icon` and `.woff2` is `font/woff2`.

There is no index page. The root path, like any folder, is answered `404 Not Found`, with that line as a plain-text body (`text/plain; charset=utf-8`), not a page, so a test opens `/index.html` by name. Listing a folder is a separate, deliberate choice; see <<http-list-a-directory>>.

On the `curl` side, `--remote-name-all` saves every URL{apos}s body under its own name and `--output-dir fetched` with `--create-dirs` puts those files in a folder of their own, so the terminal shows only what `-w` prints: `%{url.path}`, `%{http_code}` and `%{content_type}` for each URL in turn. `-s` keeps the progress meter out, and `-o` with the null device throws a body away where nothing needs saving.
