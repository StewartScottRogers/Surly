=== Choosing the HTTP Version

==== Problem

You want to test a client against a Hypertext Transfer Protocol version 2 (HTTP/2) server without setting up Transport Layer Security (TLS), or to see which version a request was answered in.

==== Solution

Serve a file with `surl` and fetch it with `curl --http2-prior-knowledge`:

include::.generated/solution.adoc[]

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

One `http` listener answers more than one version of the protocol; nothing on the `surl` side chooses it. `--directory site` serves the files under `site`, and the client decides how to ask (<<surl-readme>>).

Without a version option, `curl` fetches an `http` URL over HTTP/1.1. `-w "%{http_version}"` prints the version the answer came in, `-o` throws the body away and `-s` hides the progress meter.

`--http2-prior-knowledge` tells `curl` the server speaks HTTP/2 without asking first, so it opens the connection with the HTTP/2 preface and `surl` answers in kind. That is the way to test HTTP/2 with no certificate in the picture; over `https` the version is agreed during the TLS handshake instead (<<https-serve-http2>>). `-I` sends a `HEAD` request and prints the head of the answer, which shows how HTTP/2 looks different: HTTP/2 has no reason phrase after the status code, and its header names are lower-case (<<rfc9113>>).

`--http1.0` asks in the oldest version still in use. `surl` answers with an `HTTP/1.1` status line, as a server should when it supports a newer minor version than the request's (<<rfc9110>>), and with `Connection: close`, because an HTTP/1.0 client does not keep the connection open. `-i` shows both.
