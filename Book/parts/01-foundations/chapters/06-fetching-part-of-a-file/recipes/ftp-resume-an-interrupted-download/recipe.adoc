=== Resuming an FTP Download

==== Problem

A download over File Transfer Protocol (FTP) was cut off and left a partial file. You want `curl` to restart from where the partial file ends, using `REST`, and to check that the joined file matches the original.

==== Solution

Run the same download again with `-C -`, which tells `curl` to work out where to continue from the file it finds:

include::.generated/solution.adoc[]

Then compare the file with the server{apos}s. Stop `surl` with kbd:[Ctrl+C].

==== Discussion

`-C -` (`--continue-at -`) makes `curl` look at the output file named by `-o`, take its size as the offset, and ask the server to start there. Over FTP the ask is `REST`, the restart command: `curl` sends `REST 65536` and `surl` answers `350 Restarting at 65536`, and the `RETR` that follows is answered with the rest of the file (<<rfc959>>, <<rfc3659>>). `curl` appends what arrives to the file. Here `update.iso` holds the first 65,536 bytes of a 200,000-byte file, so `-w "%{size_download}\n"` prints `134464`, the missing bytes and no more, and `cmp` finds the joined file identical to the server{apos}s. `surl` serves a file from `--directory` with nothing to switch on, and `--allow-anonymous` lets `curl` log in without an account.

With no local file there is no offset: `-C -` sends no `REST` and downloads the whole 200,000 bytes, so one command line serves for a first attempt and for every retry. Without `-C`, `curl` does not resume. It starts at byte `0` over the partial file, and 200,000 bytes come again.

`-C` also takes a number, the byte to start after: `-C 100000` asks for everything after the first 100,000 bytes, and the 100,000 that arrive are the end of the file. The first 100,000 bytes of the original followed by them are the whole file.

The partial file is trusted, not checked. `curl` counts the bytes it has and does not compare them with the start of the original. A partial file of 65,536 zeros is resumed as readily as the real one: 134,464 bytes arrive, the length is 200,000, exit is `0`, and only `cmp` finds that the file is not the server{apos}s. That is why the comparison belongs in the check. When the partial file may be a different version, compare a checksum of the whole.

`-s` keeps the progress meter away and `-S` still prints errors; `-v` shows the commands, here the `REST`. A download that is cut off by a dropped connection, and one that retries itself, is in <<ftp-resume-a-dropped-download>>.
