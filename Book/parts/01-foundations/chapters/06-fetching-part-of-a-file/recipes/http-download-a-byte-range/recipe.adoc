=== Fetching a Byte Range

==== Problem

You want only bytes 100 to 199 of a large file served over Hypertext Transfer Protocol (HTTP), not the whole thing, and you want to know what comes back when the range lies past the end of the file or names several ranges at once.

==== Discussion

`-r 100-199` sends a `Range: bytes=100-199` header (<<rfc9110>>). Both ends are included, so that is 100 bytes, and the first byte of the file is byte 0. `records.txt` here is thirty lines of ten bytes each, which makes the arithmetic visible: byte 100 starts `record 10`, and byte 199 is the newline that ends `record 19`.

`surl` serves ranges of any file it serves from `--directory`, with no option to turn them on. A range it can serve is answered `206 Partial Content` with a `Content-Range` header that names the bytes sent and the length of the whole file, `bytes 100-199/300`. `-w` prints the status, that header (`%header{content-range}`) and the bytes received; `-o` sends the body to nowhere and `-s` keeps `curl` quiet. A range need not name both ends: `-r 290-` runs from byte 290 to the end, and `-r -20` is the last 20 bytes. A range that ends past the end of the file is cut there, so `-r 280-999` gets the last 20 bytes and says so in its `Content-Range`.

A range that starts past the end is a request the server cannot meet. `surl` answers `416 Range Not Satisfiable` with `Content-Range: bytes */300`, the one way it can tell you how long the file is, and a short body that repeats the status line, 26 bytes of text and none of the file. To `curl` that is an answer like any other, and it exits `0`; with `-f` it exits `22`, as for any status of 400 or more.

Several ranges in one `-r`, separated by commas, are not glued together. `surl` answers `206` with a `multipart/byteranges` body: each range is a part with the file's `Content-Type`, its own `Content-Range` and its bytes, between boundary lines, and `curl` writes that body out as it comes. A program that wants the bytes alone has to take the parts apart, or ask for one range at a time.

A range the server cannot make sense of, such as `-r 200-100` with its end before its start, is ignored as the standard says it may be, and the whole file comes back with `200`. A script that asked for a range and checks only the exit code would not notice; check for `206`.
