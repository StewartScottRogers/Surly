=== Explaining a 405

==== Problem

Your artificial intelligence (AI) agent tried to upload a file with a Hypertext Transfer Protocol (HTTP) `POST` and got `405 Method Not Allowed`. You want it to read the response's `Allow` header and explain the fix: the server must allow uploads, and the client must send the file with `PUT` and a login.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts a server with `surl-mcp`{apos}s `start_server`, sends the request with `curl-mcp`{apos}s `curl` tool, and turns the final status and `Allow` into an explanation:

==== Discussion

`start_server` starts a server on a free port, `listen_urls` `http://127.0.0.1:0`, and `arguments` are `surl`{apos}s own options: `--user alice:s3cret` gives it one account, and `--allow-uploads`, in the `-on` scenarios only, lets a logged-in client write files. The answer's `bound_urls` names the port the program sends to.

The `curl` tool runs `curl` with the arguments given, confined to the program's folder by `CURL_MCP_ROOT`. `--digest -u alice:s3cret` logs in with Digest (<<rfc7616>>): `curl` sends the request once without the login, takes the server's `401` challenge and sends it again with the answer. `-D -` writes every response head to standard output, both the `401` and the final one, so the agent reads the last head. `-d "a note"` makes the request a `POST` with that body, and `-T notes.txt` a `PUT` of the fixture file; `-s` keeps the progress meter out of standard error, and `--max-time 10` bounds the call. A `405` is not a tool error: `curl` without `-f` exits `0`, and the status is in the head.

`surl` is secure by default (<<surl-readme>>), and the two refusals say different things. Without `--allow-uploads` a logged-in `POST` is `405 Method Not Allowed` (<<rfc9110>>) with `Allow: GET, HEAD`: nothing that writes is offered at all, so the fix is on the server's side, and a logged-in `PUT` to the same server gets the same `405`. With `--allow-uploads` the `POST` is still `405`, because `surl` takes files by `PUT` only, but `Allow` now reads `GET, HEAD, PUT`, and the fix is on the client's side. The agent tells them apart by whether `Allow` names `PUT`, which is the header's purpose: it lists what the server would accept at that URL. Followed, the advice works: a logged-in `PUT` to the server with uploads on is `201 Created`, and `read_file`, which reads a path from the server's store directly, finds `a note` at `/notes.txt`.

A `405` needs a login first. `surl` judges the login before the method, so the same `POST` with no login is `401 Unauthorized` with `WWW-Authenticate` challenges and no `Allow`: the server does not tell a stranger which methods it offers. An agent that sees `401` should log in and try again before concluding anything about methods. `--allow-anonymous` would skip the login, and is a loosening for tests only.
