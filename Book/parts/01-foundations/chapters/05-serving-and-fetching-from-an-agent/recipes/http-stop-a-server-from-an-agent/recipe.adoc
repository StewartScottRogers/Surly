=== Stopping a Server from an Agent

==== Problem

Your artificial intelligence (AI) agent started a test server and is done with it, and it needs to find the server, stop it, and know it stopped cleanly.

==== Solution

Call `list_servers` to see what is running, then `stop_server` with the server's ID:

==== Discussion

`start_server` starts a Hypertext Transfer Protocol (HTTP) server through `surl-mcp`, one of the two programs' Model Context Protocol (MCP) servers, and answers its `server_id` and `bound_urls`, saved here as `{{server}}` and `{{url}}`.

`list_servers` takes no arguments and lists the servers this host started that are still running, each with its `server_id`, the `bound_urls` it got, and `exchange_count`, how many exchanges it has recorded. An agent that lost track of an ID finds it here by its URL.

`stop_server` takes the `server_id` and stops that server. Its answer is the exit code `surl` would have exited with, as `exit_code` and `exit_code_name`: `0`, `Ok`, for a server stopped when asked. A start that fails answers the same pair inside a tool error, as <<http-serve-and-fetch-from-an-agent>> shows.

Stopping releases the port. `transfer`, from `curl-mcp`, then fails to connect: a tool error whose `failure` carries `curl`'s exit code `7`, and no `statusCode`, because nothing answered. A new `start_server` can bind the same URL at once; it gets an ID of its own, and `list_servers` shows it with its own `exchange_count`, 1 after one fetch.

A stopped server is gone, not paused. Stopping its ID again is a tool error, `no running server has ID`, and so is `get_exchanges` on it: what its clients sent goes with it, so an agent reads the exchanges it needs before it stops the server, not after.
