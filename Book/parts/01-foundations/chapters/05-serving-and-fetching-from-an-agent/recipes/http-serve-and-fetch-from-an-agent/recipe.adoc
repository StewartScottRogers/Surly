=== Serving and Fetching Files from an Agent

==== Problem

You want an artificial intelligence (AI) agent to stand up a throwaway Hypertext Transfer Protocol (HTTP) server with a file in it and fetch that file back, with tool calls and no shell.

==== Solution

Call `surl-mcp`'s `start_server` with a listen URL on port 0 and the file's content, then call `curl-mcp`'s `transfer` on the URL it bound:

==== Discussion

`surl-mcp` and `curl-mcp` are the two programs' Model Context Protocol (MCP) servers. An agent's MCP client starts each as a process on standard input and output; `mcp.json` beside this recipe is that configuration.

`start_server` starts a server that answers as `surl` with the same options would. `listen_urls` is `surl`'s listen URLs, and port 0 asks the system for a free port, so two agents never fight over 8080. The answer echoes `listen_urls` as given and adds `bound_urls`, the URLs actually listening, with the real port; the next call fetches from `bound_urls`, never from what was asked for. `files` puts content in the server's store in memory, relative path to UTF-8 text. The answer's `server_id` is what every later tool takes to name this server.

`transfer` makes one request described by fields rather than a command line: `url` is the only one this recipe needs. It answers `statusCode`, `headers` as a list of `name` and `value` pairs, and `body` with its `content` as text and `isBase64` false when the bytes are valid UTF-8. A `404 Not Found` (<<rfc9110>>) is an answer, not a failure: the call is not a tool error, `failure` is null and `statusCode` is 404. The agent reads the status; nothing is thrown at it.

The two hosts are surly in the same direction. A second server on an address and port already in use is a tool error whose answer carries `surl`'s own exit code, `45` (`BindFailed`), and its message, so an agent can act on the code as a script acts on `surl`'s. A listen host that is not loopback, such as `0.0.0.0`, is refused outright: exposing a test server to the network is a decision for whoever starts `surl-mcp`, with `--allow-non-loopback`, not for the agent driving it. `transfer` refuses `file:` URLs and says to use the `curl` tool, which confines local files to its root (see <<http-run-curl-from-an-agent>>).
