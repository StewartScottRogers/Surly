=== Looking Up a Word from an Agent

==== Problem

You want an artificial intelligence (AI) agent to serve a small glossary and look a word up in it over DICT, the Dictionary Server Protocol, through `curl-mcp`{apos}s `curl` tool, with no shell.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `start_server` with a `dict` listen URL and one file per word, then runs `curl -s` on the word's URL through `curl-mcp`{apos}s `curl` tool:

==== Discussion

`StdioClientTransport` starts each host by name, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine them to the program's folder. The argument after `--` is the DICT path to ask for.

`start_server` starts a server that answers as `surl dict://127.0.0.1:0/` would. Its `files` are the glossary: each file at the root is a headword, its name the word and its text the definition, in the one database the server has, `surl`. Port 0 takes a free port, and the program builds the URL from `bound_urls` in the structured content `start_server` answers.

The `curl` tool runs `curl`{apos}s own command line in-process: `args` is the command line without the program name, here `-s` and `dict://127.0.0.1:<port>/d:surly`. `d:` asks for a definition, the DICT `DEFINE` command (<<rfc2229>>), and `m:` for the headwords that match, `MATCH`; with no strategy named the match is by prefix, so `m:surl` lists both `surl` and `surly`. The tool answers in text, as JavaScript Object Notation (JSON): `exitCode` is the code `curl` would have exited with, and `standardOutput`{apos}s `content` is what it would have printed, the server's whole reply with its numbered status lines. The reply is kept as sent, every line ended by carriage return and line feed (CR LF); the program prints it with plain line ends.

A word with no file is answered `552 no match`. To `curl` any DICT reply is a successful conversation, so `exitCode` is still 0 and the call is not a tool error; an agent reads the status lines to know whether it found the word. The program prints whether the call was a tool error and exits 1 if it was.
