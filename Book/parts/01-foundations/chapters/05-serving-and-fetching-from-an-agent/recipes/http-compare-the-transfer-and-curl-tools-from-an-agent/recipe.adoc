=== Choosing transfer or curl

==== Problem

Your artificial intelligence (AI) agent can fetch a URL with `curl-mcp`{apos}s `transfer` tool or with its `curl` tool, and you want to know what each answers for the same file, so the agent picks the one whose answer it can use.

==== Solution

==== Discussion

`start_server` on `surl-mcp` starts a Hypertext Transfer Protocol (HTTP) server on a free port with `hello.txt` in memory, and answers `bound_urls`. Both `curl-mcp` tools answer in text, a JavaScript Object Notation (JSON) object the program parses; they differ in what is in it.

`transfer` describes the request with fields, `url` here, and answers the response taken apart: `statusCode`, `headers` as a list of `name` and `value` pairs (`Content-Type` is `text/plain`), `body` with its `content`, and `info` with the timings and the version. Nothing has to be parsed out of text, and a status is a number to compare. A `404 Not Found` (<<rfc9110>>) is an answer like any other: `statusCode` 404, a short `text/plain` body that says `404 Not Found`, and not a tool error.

`curl` takes `args`, the arguments of a `curl` command line, and answers what that command would have done: `exitCode`, `standardOutput` and `standardError`. With `-s` and a URL, `standardOutput` is the body and nothing else; the status is not there. That hides a missing file: without `-f`, `curl` exits `0` and `standardOutput` holds the error page, `404 Not Found`, which reads like the content of a file. Add `-f` and the call is a tool error, `exitCode` `22`, `failure` text `curl exit code 22 (HttpReturnedError)`, and `-w "%{http_code}"` still prints `404` into `standardOutput`, which is how an agent gets the status out of the `curl` tool.

What `curl` has that `transfer` lacks is the rest of the command line. `-o downloads/hello.txt` with `--create-dirs` writes the body to a file, inside `CURL_MCP_ROOT`, the only place the tool may write (<<http-run-curl-from-an-agent>>); `transfer` only ever returns the body in its answer. The same goes for the HTTP version options, `-w` timings, globbing and resuming: any option is there, at the price of reading the result out of text.

So: an agent that needs to judge a response, its status, a header, the body, calls `transfer` and reads fields. An agent that needs a file on disk, or an option `transfer` has no field for, calls `curl`, and adds `-f` and `-w` so that a failure shows.
