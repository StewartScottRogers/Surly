=== Reading a File Back from an Agent

==== Problem

You want an artificial intelligence (AI) agent to read a file straight from a test server's store and check that the bytes and content type a client fetched over Hypertext Transfer Protocol (HTTP) are what the server holds.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts a server with `surl-mcp`{apos}s `start_server`, fetches a path with `curl-mcp`{apos}s `transfer`, reads the same path with `read_file`, and compares the two:

==== Discussion

`StdioClientTransport` starts each host by name, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine them to the program's folder. The argument after `--` is the request path to fetch and read.

`start_server` puts files in the server's store: `files` as UTF-8 text, `files_base64` as bytes, here the start of a Portable Network Graphics (PNG) image. It answers in structured content, a JavaScript Object Notation (JSON) element, with the `server_id` that `read_file` needs and the `bound_urls` to fetch from.

`transfer` is the client's view: `url` is the bound URL and the path, and the answer, in text as JSON, carries `statusCode`, the `headers` as `name` and `value` pairs, and the `body`, as text or, with `isBase64` true, as base64.

`read_file` is the server's view. It takes the `server_id` and the file's request path and answers in structured content: `path`, `byte_count`, `content_type`, the type the server sends the file with, and the content, as `text` when the bytes are valid UTF-8 and as `base64` when they are not. The program turns both answers into bytes and compares them, then compares the `Content-Type` header with `content_type`: they agree for plain text, for the PNG image and for a Markdown file in a folder. When a test fails, this is how an agent tells a server that held the wrong bytes from a client that mangled the right ones.

What a client cannot fetch, `read_file` cannot read either. A path with no file, a folder such as `/docs`, and a dot file such as `/.env` given at start are all `404 Not Found` (<<rfc9110>>) to `transfer` and a tool error to `read_file`, `No file at` the path. The program prints whether its last call was a tool error and exits 1 if it was.
