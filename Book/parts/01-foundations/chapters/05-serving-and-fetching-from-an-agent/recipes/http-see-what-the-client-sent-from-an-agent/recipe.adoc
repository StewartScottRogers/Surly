=== Reading the Client's Request from an Agent

==== Problem

Your artificial intelligence (AI) agent is testing a client and needs to see the exact request it put on the wire, headers and all, not only what the client printed.

==== Discussion

`start_server` starts a Hypertext Transfer Protocol (HTTP) server through `surl-mcp`, one of the two programs' Model Context Protocol (MCP) servers. This recipe listens on a fixed port, shown as 8080, rather than port 0, only so the `Host` line can be printed exactly; an agent would use port 0 and read the port from `bound_urls`. `transfer`, from `curl-mcp`, is the client under test: one `GET` for `hello.txt`.

`get_exchanges` answers what each client sent to the server and what the server sent back, byte for byte, oldest first. Each exchange has an `exchange_id` counting from 1, the `listen_url` and `scheme` it came through, and `chunks`: each with a `direction` (`received` from the client, `sent` to it), the `layer` (`wire`, the bytes on the connection) and the `data`, as text when the `encoding` is `text`, as it is here. The first chunk is the whole request: request line, `Host`, `Accept: */*`, and the blank line that ends the header section (<<rfc9110>>). There is no `User-Agent` line: `transfer` sends none when not asked to. The response follows in later chunks, its body last.

The `curl` tool is the second client. Its `-s` keeps it quiet, and `-A` names the `User-Agent` it sends, which the second exchange shows on the wire as `User-Agent: surly-reader`.

The record grows with every request, so `get_exchanges` pages it. `after_exchange_id` asks for the exchanges after one already read, and `has_more` false says the agent has the rest. `max_exchanges` caps one answer, and `has_more` true says to ask again. `scheme`, matched without regard to case, and `listen_url`, spelled as `bound_urls` spells it, keep only what came through that kind of listener or that one listen URL; on a server with one listener, they keep everything. A server ID this host is not running is a tool error, `no running server has ID s9`.
