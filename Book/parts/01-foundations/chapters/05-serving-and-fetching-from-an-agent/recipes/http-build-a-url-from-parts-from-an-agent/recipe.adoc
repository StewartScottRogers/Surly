=== Building a URL from Parts

==== Problem

Your artificial intelligence (AI) agent has a host, a port, a path and a query in hand, some with spaces in them, and you want it to assemble a URL with every part correctly encoded rather than gluing strings together.

==== Solution

Write the agent's side as a C# program on the Model Context Protocol (MCP) software development kit (SDK): it starts a server with `surl-mcp`, passes the parts to `curl-mcp`{apos}s `build_url` with the `UrlEncode` and `AppendQuery` flags, fetches the result with `transfer`, and asks the server what it received:

==== Discussion

`start_server` on `surl-mcp` starts a Hypertext Transfer Protocol (HTTP) server on a free port holding `reports/q3 sales.csv`, a name with a space in it, and answers its `bound_urls` in structured content; the program takes the host and port from there. It prints the port as `PORT` so the output does not change from run to run.

`build_url` is `curl`{apos}s URL interface as a tool (<<curl-readme>>): each argument is one part of the URL, `scheme`, `host`, `port` (as text), `path`, `query`, and the tool sets only the parts given and answers, in text, a JavaScript Object Notation (JSON) object with `url` and `failure`. It does not encode anything unless asked. `flags` asks: `UrlEncode` percent-encodes what is not allowed raw in each part (<<rfc3986>>), so the space in the path becomes `%20`, and in the query, where a space traditionally becomes `+`, `north east` becomes `north+east`. `AppendQuery` treats the query as one `name=value` pair and keeps its first `=`; without it, `UrlEncode` encodes the `=` too, as `%3D`, and the query is no longer `region` set to a value.

`transfer` fetches the URL and answers `statusCode` `200`. `get_exchanges` on `surl-mcp` answers what the server recorded, each exchange with its `chunks`; the first chunk received is the request head, and its first line is `GET /reports/q3%20sales.csv?region=north+east HTTP/1.1`, the URL as built.

Without `flags`, `build_url` sets the parts as given and returns a URL with raw spaces in it. That is not a URL `curl` will send: `transfer` fails as a tool error, `failure` of kind `CurlExit` with exit code `3`, a malformed URL, and `get_exchanges` shows that no request reached the server.

The tool refuses parts that cannot make a URL, before anything is sent. A port of `eighty` is a tool error whose `failure` is `UrlRefused` and whose text names the part, `port`, and the parser{apos}s reason, `BadPortNumber`; parts with no `scheme` are refused as `NoScheme`. Either way `url` is null, so an agent that checks `failure` before fetching never sends a half-built request.
