=== Listing a Server's Files from an Agent

==== Problem

You want an artificial intelligence (AI) agent to see what a running test server holds, file by file and folder by folder, before it decides what to fetch over Hypertext Transfer Protocol (HTTP).

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts a server with `surl-mcp`{apos}s `start_server`, calls `list_files` on `/`, and fetches each text file the listing names with `curl-mcp`{apos}s `transfer`:

==== Discussion

`StdioClientTransport` starts each host by name, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine them to the program's folder. The argument after `--` picks the scenario.

`start_server` puts the files in the server's store in memory: `files` as UTF-8 text and `files_base64` as bytes, here a short Portable Network Graphics (PNG) header. Its structured content, a JavaScript Object Notation (JSON) element, carries the `server_id` every later tool call names and the `bound_urls` to fetch from.

`list_files` takes the `server_id` and a folder's `path`, written as a request path: `/` for the root, `/docs` for a folder. It answers in structured content with `entries`, one per child, in ordinal order of name with folders and files mixed: each has a `name` and a `kind`, `folder` or `file`, and a file has its `byte_count`. It lists one level: `/docs` shows the folder `archive`, not what is in it. A dot file such as `.env` is not listed, as the server never serves it, so the listing is what a client could fetch.
`limit` caps how many entries come back, and `has_more` says whether there were more; asking again with `after_name` set to the last name seen continues from there, so an agent can walk a large folder a page at a time.

The program decides from the listing: it fetches each entry whose `kind` is `file` and whose name ends in `.txt` with `transfer`, whose `url` is the bound URL and the name, and prints the status and `body`{apos}s `totalBytes`, which match the listed `byte_count`.

`list_files` refuses what it cannot answer with a tool error and a line of text. A folder that is not there is `No folder at /nope.`; a path without its leading `/` is not a request path at all and is refused as `NotRooted`. The program prints whether its last call was a tool error and exits 1 if it was.
