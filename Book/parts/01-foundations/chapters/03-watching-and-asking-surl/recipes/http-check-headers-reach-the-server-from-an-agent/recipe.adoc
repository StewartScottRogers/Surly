=== Checking Headers Arrive from an Agent

==== Problem

Your artificial intelligence (AI) agent calls a Hypertext Transfer Protocol (HTTP) service that needs an application programming interface (API) key and a trace ID header. You want the agent to send them with Model Context Protocol (MCP) tool calls and confirm, from what the server recorded, that they arrived as sent.

==== Solution

Write the agent's side as a C# program on the official MCP software development kit (SDK): it starts `surl-mcp` and `curl-mcp`, calls `start_server`, sends the request with `transfer` and its `headers` field, then reads the request head back with `get_exchanges`:

==== Discussion

`surl-mcp` and `curl-mcp` are the two programs' MCP servers; the program starts each by name from `PATH` with `StdioClientTransport`, confined to the folder it runs in by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. `mcp.json` beside this recipe is the same configuration for an agent's own client. The argument after `--` picks the scenario.

`start_server` starts a server on a free port with one file in memory and answers `server_id`, which names the server in later calls, and `bound_urls`, the URL to send to. `surl-mcp` records every exchange of a server it started, with nothing to switch on.

`transfer` makes one request. Its `headers` field is a list of objects with `name` and `value`, the counterpart of `curl -H`, sent in the order given after the `Host` and `Accept` headers `curl-mcp` adds of its own. `transfer` sends no `User-Agent` unless its `userAgent` field names one, and that one goes after `Host`, not among your headers. The program builds the list as `JsonObject` values, which the SDK serializes as they are.

`get_exchanges` answers the server's exchanges, oldest first, each with its `chunks`: the bytes received and sent, as text when they are. The first chunk with `direction` `received` holds the request, and everything before the first blank line is its head. That is what the program prints, one header a line, so the agent compares the request as the server saw it with the request it meant to send.

`transfer` sends a header named twice twice, in order, and merges nothing, so a server that keeps only one of them sees only one of your values. An empty `value` removes the header, as `curl -H "X-Api-Key:"` does on the console: it is not sent at all. The same holds for a header `curl-mcp` adds of its own, so an empty `Accept` leaves the request with no `Accept`. To send a header empty, the name and a colon with nothing after it, add `sendEmpty` `true` to its object, the counterpart of `curl -H "X-Api-Key;"`.

`surl` serves the file whatever the request carries, so every `statusCode` here is `200`; a missing or wrong header shows only in `get_exchanges`.
