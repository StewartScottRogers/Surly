=== Logging Every Exchange surl Serves

==== Problem

A client says it got the wrong answer from `surl`, and you want a record of what each request asked for and what `surl` sent back, kept in a file you can read afterwards.

==== Solution

Start `surl` with `-v` and `--log-file`, then make the request:

Stop `surl` with kbd:[Ctrl+C], then read the log file.

==== Discussion

`-v` raises the log level to verbose: a line for every event in an exchange, each line tagged with the exchange's number, `#1`, `#2` and so on. Lines marked `<` are what `surl` received, lines marked `>` are what it sent, and lines marked `*` are what it decided. For a Hypertext Transfer Protocol (HTTP) request that means the request line it got, a line saying what it served and from which file, then the status line it answered with. Ask for a path that is not there and the `*` line says so, naming the file it looked for, before the `404 Not Found` goes out. That line is usually the answer to "why did it say 404".

`--log-file surl.log` appends the log to that file instead of writing it to standard error. Here the file is inside `site`, which `--directory site` serves, only so that the checks below can fetch it with `curl`; keep yours outside the served folder, since anyone who can reach the listener can otherwise read every request in it. A log file that cannot be opened, such as one in a folder that does not exist, stops `surl` before it listens, with exit code `23`. Failure lines are not part of the log: they go to standard error whatever `--log-file` says, so a script that starts `surl` sees them where it expects them.

From quietest up, the levels are none, error, info (the default), verbose and trace (see <<http-trace-every-byte>>). At the default level a `surl` that cannot start writes one `surl: (N)` line, whose number is its exit code; `https` (HTTP over Transport Layer Security) with no certificate is `58`. `-s` silences that line too, so only the exit code is left. `-s` with `-S` (show errors) is the error level: the failure line and nothing else, which is what a quiet script usually wants. `--log-level` sets a level by name, so `--log-level none` is `-s`; a name `surl` does not know is a refused command line, exit `2`, written even under `-s`, because a command line that cannot be read has no level yet. When several level options are given, the last one wins, so `-v -s` is silent.

On the client side, `-s` keeps `curl` quiet, `-o /dev/null` throws the body away, and `-w "%{http_code}"` prints only the status code, to show the `404`.
