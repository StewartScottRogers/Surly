=== Checking Headers Reach the Server

==== Problem

Your client must send an application programming interface (API) key and a trace ID header with every Hypertext Transfer Protocol (HTTP) request. You want to send them with `curl -H`, see them arrive at the server byte for byte, and know how `curl` replaces, drops or repeats a header.

==== Discussion

`-H "Name: value"` adds one header to the request, and `curl` takes as many as you give. It sends them as typed, after the three headers it adds of its own: `Host`, `User-Agent` and `Accept`. A header is a line of the request head (<<rfc9110>>); nothing checks that the server wanted it, so the only way to know it arrived is to look at the other end.

`--directory site` serves the files under `site`. `--trace-ascii site/trace.txt` makes `surl` write every byte it receives and sends to that file, the request head included, each line led by its offset. It is in the served folder here only so that the cases can fetch it with `curl`; in real use, keep it outside. The cases after the Solution fetch `hello.txt` with their own headers and then `trace.txt`, both in one `curl` command, kept quiet with `-s`: `-o` sends the first answer to nowhere, and the second, the trace, comes out on standard output, by then holding the request just made. Each case sends its own `X-Trace-Id`, so its request is easy to pick out of the trace.

A `-H` header with the name of one of `curl`{apos}s own replaces it rather than adding a second: `-H "User-Agent: billing/2.1"` leaves one `User-Agent` in the request, the one given. A name with a colon and nothing after it, `-H "Accept:"`, drops that header, and the request goes without an `Accept`. To send a header with an empty value, end the name with a semicolon: `-H "X-Api-Key;"` arrives as `X-Api-Key:` and nothing more.

Your own headers are not deduplicated. Two `-H` options of the same name send two headers, and a server that reads only the first, or only the last, sees one of your values, not both. A header that arrives twice is the usual sign that a wrapper script and its caller both added it.

`surl` accepts every header here and answers `200`; it serves the file whatever the request carries, so a wrong or missing header shows up only in the trace, never in the answer.
