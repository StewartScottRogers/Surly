=== Asking surl for Help as an Agent

==== Problem

You are an artificial intelligence (AI) agent, or you are writing the instructions for one, and you need to learn how to drive `surl` from the program itself, in a form you can parse, rather than from a web page that may describe another version.

==== Discussion

`--aihelp` writes help in Markdown, meant to be read by a program as much as by a person, and exits `0`. With no topic it writes an overview that ends in a table of topics, each with a line saying what it covers. With a topic, such as `surl --aihelp exit-codes`, it writes that page alone; `surl --aihelp all` writes the overview and then the topic pages, `amqp` to `xmpp`, in one go, for an agent that wants to read everything once and keep it. A topic name is matched in any case. An unknown topic is not an error: `surl` says it does not know it, lists the topics, and exits `0`, so an agent that guessed wrong gets the menu instead of a dead end.

A topic page has five sections in a fixed order, About, Schemes, Options, Exit codes and Examples, and a section with nothing to say holds the line `Nothing for this topic.` rather than going missing. An agent can therefore split a page on its `##` headings and know what it has. The option table has a column saying whether an option loosens security: `--self-signed`, for one, is marked `yes, for tests only`. A protocol topic's examples give the `surl` command, what it prints, and an upstream `curl` command that reaches it, which is what an agent writing a test usually wants next.

The `exit-codes` topic is the one to read before scripting `surl`: a table giving each exit code its name, its meaning and what to do next. <<surl-read-the-exit-codes>> walks through three of them.

Help is not log output. `-s` silences the log, but `surl -s --aihelp exit-codes` still writes the page to standard output, so an agent that always passes `-s` loses nothing.

The help comes from the binary that will do the serving, so it describes that build and no other; a reader without the binary has the project's README instead (<<surl-readme>>).
