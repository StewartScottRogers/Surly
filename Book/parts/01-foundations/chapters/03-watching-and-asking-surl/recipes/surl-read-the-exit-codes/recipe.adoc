=== Reading surl's Exit Codes

==== Problem

Your script starts `surl`, and instead of serving it exits at once; you want to know from its exit code why, and what to do about it.

==== Solution

Read the `surl: (N)` line on standard error: the number in it is the exit code. Here a second `surl` is started on a directory the first one already holds:

==== Discussion

A `surl` that exits as soon as it starts has refused to start, and its exit code says why. Unless told to be quiet, it also writes one line to standard error, `surl: (N)` and a reason, where `N` is that same code. The recipe sends standard error to standard output with `2>&1` only so the line shows up beside the command.

`124` means another `surl` holds the data directory. `--directory site` takes a lock on `site`, so two servers never write the same files at once; the second exits and the first carries on serving as before. Stop the first, give the second another `--directory`, or leave `--directory` off to serve from memory. The help table gives the same three ways out.

`1` means a listen URL names a scheme this build does not serve. `file` is a good example: `curl` can fetch `file://` addresses, but there is nothing for a server to listen with. `--version` makes `surl` list the schemes the build does serve, on its `Protocols:` line, and exit `0`.

`58` means a secure listen URL has no certificate. `https`, Hypertext Transfer Protocol over Transport Layer Security, refuses to start without one rather than invent one quietly, because a certificate the client never agreed to trust is a decision for the person running it. The line names both ways out: `--cert` with a real certificate, or `--self-signed` for a throwaway one in a test.

`-s` silences the 124 line, so only the exit code is left, and the 1 line as well: a scheme that is not served counts, like a held directory, as a failure found once the command line is read, which is what `-s` quiets. Adding `-S` (show errors) brings the 124 line back, which is the usual choice for a script that wants quiet when things work and a reason when they do not. Either way, the code is the same.

When the code is not one of these, `--aihelp exit-codes` makes `surl` write the table: each code with its name, its meaning and what to do next (see <<surl-ask-for-help-as-an-agent>>).
