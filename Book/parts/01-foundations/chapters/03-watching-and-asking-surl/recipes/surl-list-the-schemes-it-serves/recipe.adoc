=== Listing the Schemes surl Serves

==== Problem

Before you write a test you want to know which schemes this `surl` serves and which this `curl` speaks, so that you do not plan around one that either lacks.

==== Solution

Ask each program for its version. `surl --version` lists the schemes it serves, and `curl -V` the protocols `curl` speaks; the first is shown, and the second is the same question put to `curl`:

include::.generated/solution.adoc[]

Run `curl -V` beside it and compare the two Protocols lines by eye or with a diff.

==== Discussion

`surl` takes `--version`, or `-V` for short, and prints three lines and exits `0`: the version and the platform it was built for, a `Protocols:` line, and an `Extended:` line. A scheme on either line is one `surl` takes as a listen URL (`surl ftp://127.0.0.1:8080/`). `Protocols:` holds the classic schemes, `http`, `https`, `ftp`, `tftp` and `dict` among them, each with the secure variants where there is one, such as `ftps`. `Extended:` holds more, `redis` and `kafka` among them. The platform in the first line, `win-x64` here, is the build{apos}s and differs on Linux and macOS.

`curl -V` does the same for `curl`: a version line, the `Release-Date:`, a `Protocols:` line and a `Features:` line, `SSL` among them. The features say what a build can do rather than what it speaks, and which are present depends on the platform. `curl` reads `file`, which `surl` does not serve; and `surl` serves `socks5`, which `curl` does not speak as a scheme. So the two lists are not the same list, and a test that needs both a server and a client for a scheme needs the scheme on both.

A scheme on neither line is refused. `surl carrier-pigeon://127.0.0.1:0/` exits `1` and says `Protocol "carrier-pigeon" not supported` on standard error; `curl` exits `1` too, unsupported protocol, and `-s` keeps its message quiet, so the exit code is the only answer.
