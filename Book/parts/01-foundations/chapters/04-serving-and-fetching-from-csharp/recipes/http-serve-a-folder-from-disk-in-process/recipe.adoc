=== Serving a Folder from Disk

==== Problem

Your .NET test or tool has a real folder of files, and you want `Surl.Api` to serve that folder over Hypertext Transfer Protocol (HTTP) from inside your process, knowing what the server writes into it and what it will never hand out.

==== Solution

Set `DataDirectory` on the options to the folder, start the server on port 0, and fetch a file at its path relative to the folder:

==== Discussion

`SurlServerOptions.DataDirectory` is `surl --directory`: every file under the folder is served at its path relative to it, so `site/hello.txt` is `/hello.txt`. A relative path is taken from the program's current directory. `ListenUrls` holds `http://127.0.0.1:0`, and port 0 takes a free port; `SurlServer.StartAsync` returns once it is bound and `BoundUrl` names it. The client is `CurlClient.Create()`, each request a `CurlRequest`, and `SendAsync` returns a `CurlResponse` with `StatusCode`, `ReasonPhrase` and the `Body` as a stream.

The folder is served as it is now, not as it was at start: a file the program writes into `site` while the server runs is served on the next request.

The server keeps its own state in the folder it serves, under `.surl`, and holds a lock file there while it runs. `.surl` is never served: `/.surl/lock` and `/.surl/` are both `404 Not Found`, though the lock file is on disk. Because of that lock, one folder has one server. A second `StartAsync` on the same `DataDirectory` throws `SurlServerStartException` with `ExitCode` `124`, `DataDirectoryInUse`, the code a second `surl --directory site` process exits with; give each server its own folder.

A server serves a folder or the in-memory `Files`, not both. Setting both makes `StartAsync` throw `ArgumentException` before anything binds; this program exits 2 when it does.
