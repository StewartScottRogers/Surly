=== Choosing the HTTP Version in C#

==== Problem

You want a C# client to ask for HTTP/1.0, HTTP/1.1 or HTTP/2 (the versions of the Hypertext Transfer Protocol) with prior knowledge, and to see which version a server run with `Surl.Api` answered in.

==== Solution

Set `HttpVersion` on the request's `CurlHttpOptions`, send it with a `CurlClient`, and read `Version` from the `CurlResponse`; the server's record of the exchange shows what it was asked:

==== Discussion

`SurlServerOptions` puts `hello.txt` in the in-memory `Files` store on a free port, and `RecordExchanges` has the running `SurlServer` keep the bytes of each exchange in `Exchanges`; the program prints the first line it received. `CurlRequest` carries the method and URL, and its `Http` property a `CurlHttpOptions` record whose `HttpVersion` is the version to ask for. The values of the `HttpVersion` enumeration are `curl`{apos}s options under other names: `Http10` is `--http1.0`, `Http11` is `--http1.1`, `Http2` is `--http2` and `Http2PriorKnowledge` is `--http2-prior-knowledge`. Set on a request, it holds for that request only; `CurlClientOptions.Http` sets it for every request a client makes (<<curl-readme>>). The program makes one `CurlClient` per version so that each request opens its own connection and its own exchange.

`CurlResponse.Version` is the version the answer came in, as a `System.Version`. It is not always the one asked for. An HTTP/1.0 request reaches the server as `GET /hello.txt HTTP/1.0`, and `surl` answers with an HTTP/1.1 status line and `Connection: close`, so `Version` is `1.1`: a server may answer in the highest 1.x version it speaks, and the `close` is what tells an HTTP/1.0 client the connection ends with the body (<<rfc9110>>). A test that wants proof the client sent 1.0 has to look at what the server received, not at the response.

With `Http2PriorKnowledge` the client assumes the server speaks HTTP/2 over plain `http://` and starts with the HTTP/2 connection preface, which begins `PRI * HTTP/2.0` (<<rfc9113>>); there is no HTTP/1.1 request first. `surl` serves HTTP/2 on the same listener as HTTP/1.1, and `Version` is `2.0`.

`Http2` without prior knowledge does it the polite way on `http://`: an ordinary HTTP/1.1 request carrying `Upgrade: h2c`, which `surl` accepts, so the response to that same request comes back as `2.0`. Either way ends in HTTP/2 against `surl`. The difference is what the server is tested on: prior knowledge checks that it speaks HTTP/2 from the first byte, the upgrade that it accepts the switch.
