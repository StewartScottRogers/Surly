=== Running Two Servers in One Program

==== Problem

Your C# test talks to two services over Hypertext Transfer Protocol (HTTP), and you want two independent stand-ins for them, each with its own files and its own port, inside the test program.

==== Discussion

A `SurlServer` is one `surl`, and nothing stops a program from running several: each `SurlServer.StartAsync` call takes its own `SurlServerOptions` and returns a server with its own listener, store and lifetime. `ListenUrls` of `http://127.0.0.1:0` asks the operating system for a free port each time, so the two servers get two different ports and neither needs to know the other is there. `BoundUrl` is where each one ended up; that is the address to hand to the client of each service, in place of whatever the configuration would have said in production.

`Files` is each server's own in-memory store, path to bytes. The `orders` server holds `orders.json` and the `stock` server `stock.json`, and the stores are not shared: asked for the other service's file, each answers `404 Not Found` with a short body that says the same, which a `CurlClient` returns as an ordinary `CurlResponse` rather than an exception. One `CurlClient` serves for both, since a client is not tied to a server; it sends a `CurlRequest`, method and URL, to whichever address it is given.

Each server stops on its own: `StopAsync` returns the `SurlExitCode` that `surl` would have exited with, `Ok` for both here.

Port 0 is what keeps the two apart. Give the second server the address and port the first one bound, as a test does when it hard-codes a port, and `StartAsync` throws `SurlServerStartException` whose `ExitCode` is `BindFailed`, `surl`{apos}s exit code `45`. The first server is unharmed and still stops with `Ok`.
