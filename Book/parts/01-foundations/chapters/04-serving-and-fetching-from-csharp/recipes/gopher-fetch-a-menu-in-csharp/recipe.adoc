=== Fetching a Gopher Menu from C#

==== Problem

==== Discussion

`SurlServer` is the server in this process and `SurlServerOptions` is its command line as properties. `ListenUrls` holds `gopher://127.0.0.1:0`, port `0` taking a free one, and `server.BoundUrl` has the port it took. `Files` is an in-memory store, where `notes/today.txt` makes a folder, and `ListDirectories` is the spelling of `surl --list-directories`, which Gopher needs to answer a menu for a folder. `RecordExchanges` makes the server keep what it received, so the program can print it. `SurlServer` stops when the `await using` ends.

`CurlClient` sends a `CurlRequest`, and a Gopher URL is an ordinary `GET`: `Body` of the `CurlResponse` is the server{apos}s whole answer. In a Gopher URL the character after the first slash is the item type and is not sent (<<rfc1436>>), so `0/hello.txt` sends the selector `/hello.txt`, and the program prints what the server received to show it. The empty path sends an empty selector, which names the served folder, and the answer is its menu.

A menu is one line per entry, each ended by CR LF: the item type and a display name, then the selector, the host and the port, separated by tabs, and a last line holding a dot. The program splits on those and prints each entry. A file is type `0` and a folder type `1`, and the entry for `notes` carries the selector `/notes`; the entries of `/notes` carry their full selectors, `/notes/today.txt`, so any entry can be fetched by putting its type and selector back after the server{apos}s address. The host and port in an entry are the ones the server is listening on. The dot file is in the store and not in the menu.

Gopher has no status, so a miss is not an error. A selector that names nothing, and the dot file that is never served, are each answered with an error menu of a single type `3` line, `Nothing is served at this selector.`, which does not echo the selector, with the host `error.host` and port `1` that Gopher uses for a line that points nowhere. It arrives as an ordinary response and `SendAsync` throws nothing, so a program that fetches an entry has to look at the first character of what came back, as this one does. With `ListDirectories` off, the root and a folder get that error menu as well, and a file is still served: the option changes only what a folder does, and it is off by default.
