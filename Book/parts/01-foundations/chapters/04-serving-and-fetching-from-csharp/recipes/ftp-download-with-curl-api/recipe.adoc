=== Downloading over FTP from C#

==== Problem

Your C# program fetches files over File Transfer Protocol (FTP). You want `Curl.Api` to log in with an account and read a file from a `Surl.Api` FTP server in the same process.

==== Discussion

`SurlServer` is the server in this process and `SurlServerOptions` is its command line as properties. `ListenUrls` holds `ftp://127.0.0.1:0`, port `0` taking a free one, and `server.BoundUrl` has the port it took. `Files` is an in-memory store, and `Accounts` takes a `SurlAccount`, a name and a password, the spelling of `surl --user alice:wonderland`. `RecordExchanges` makes the server keep what each client sent, one `SurlExchangeRecord` for each control connection, whose `Received` bytes are the client{apos}s side of it. `SurlServer` stops when the `await using` ends.

`CurlClient` sends a `CurlRequest` and returns a `CurlResponse` whose `Body` is a stream; the program reads it as text. `CurlRequest.Authentication` takes a `CurlAuthenticationOptions` with `UserName` and `Password`, the spelling of `curl -u alice:wonderland`. The recorded control connection, with the password masked, shows the conversation FTP (<<rfc959>>) has under the call: `USER` and `PASS`, `PWD`, then `EPSV` to open a passive data connection, `TYPE I` for a binary transfer, `SIZE` to learn how big the file is, and `RETR` to fetch it.

A login that fails is an exception. The wrong password, and a request with no `Authentication` at all, are each refused, and `SendAsync` throws a `CurlException` whose `Code` is `LoginDenied`, which is `curl` exit `67`. A server with an account does not let an unnamed client in: anonymous logins need `AllowAnonymous`, which is off by default and loosens `surl`.

`AllowPlaintextAuthentication` loosens it in another way, and the program sets it on. FTP sends the password as it is, so `surl` does not trust one that arrives over a plain connection unless it is told to: with the property left off, the right password is refused unchecked, with the same `LoginDenied`. The way to let accounts log in over FTP without that is to serve it over Transport Layer Security (TLS), as in <<ftp-protect-the-login-with-tls>>.

A file that is not there throws a `CurlException` with `Code` `RemoteFileNotFound`, `curl` exit `78`. A dot file the server holds is never served and gets the same answer, so a client cannot tell a hidden file from a missing one.
