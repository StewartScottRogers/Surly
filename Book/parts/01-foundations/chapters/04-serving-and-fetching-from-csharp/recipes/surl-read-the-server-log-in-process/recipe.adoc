=== Reading the Server Log in Process

==== Problem

Your C# test runs its server in-process, so there is no `surl` process whose output you could read. You want to capture what the server logs, start-up warnings included, and print it when the test fails.

==== Solution

Give `SurlServerOptions.Log` a synchronized `StringWriter` and `LogLevel.Verbose`; when the test fails, stop the server and print what the writer holds:

==== Discussion

`SurlServerOptions.Log` is any `TextWriter`; the server writes to it, byte for byte, what `surl` writes to its standard error: start-up warnings, the `Listening on` line for each listen URL, and the exchange log (<<surl-readme>>). With `Log` unset, nothing is written anywhere. The server writes from its own threads, so the program wraps the `StringWriter` in `TextWriter.Synchronized` and keeps the inner writer to read from. It reads only after `await using` has stopped the server, when every exchange has ended and been logged, down to `Exchange 1 ended`.

`LogLevel`, in the `Surl.Output` namespace, is `surl`{apos}s `--log-level`. At `LogLevel.Verbose`, `surl -v`, the log shows the request as received, one line per header with the line end written as `\r\n`, then the event that decided the answer, `GET /summary.csv: 404, nothing exists at` and the path the server looked in, then the response as sent. That is what a failing test needs, and the passing test prints none of it. At `LogLevel.Info`, the level when none is set, the log holds the warning, the `Listening on` line and one line saying an exchange opened, on which listener and from which address, and nothing about what was asked or answered. At `LogLevel.Error`, `surl -s -S`, the log here is empty: errors only, and the warning is not one.

The warning is the first line of the log. This server has an account, a `SurlAccount` named `alice`, so it would answer a request with no login `401 Unauthorized`; `AllowAnonymous`, `surl`{apos}s `--allow-anonymous`, makes it accept requests with no login, and a server started that way says so every time it starts, `surl: warning: --allow-anonymous: every request and login is accepted without checking credentials`. The option is here so the test can fetch without logging in, and so the log has a warning to show. Without it there is no warning, and the same request is `401`, logged as `GET /summary.csv: 401, a login is needed`. A captured log is a way to see that a test server was started looser than intended.

The test itself is plain: a `CurlClient` sends a `CurlRequest` for `summary.csv`, which the server does not have, and the `CurlResponse` is `404` where the test expects `200`. Fetch `report.csv` instead and the test passes and prints only `PASS`.
