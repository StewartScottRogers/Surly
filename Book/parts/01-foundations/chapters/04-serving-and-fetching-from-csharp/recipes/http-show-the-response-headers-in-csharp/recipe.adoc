=== Reading Response Headers in C#

==== Problem

==== Discussion

`SurlServerOptions` puts `hello.txt` in the in-memory store `Files`, and `ListenUrls` asks for a free port; `SurlServer.StartAsync` returns once the server is bound, and `BoundUrl` is its address. `CurlClient.SendAsync` sends the `CurlRequest`, method and URL, and returns a `CurlResponse` as soon as the status line and headers have arrived, so everything the program prints before the blank line is there before a byte of the body has been read.

`Version` is a `System.Version`, `1.1` here; `StatusCode` and `ReasonPhrase` are the rest of the status line. `Headers` is a list of name and value pairs, not a dictionary: every header of the final response, in the order received, with its casing and any duplicates (<<curl-readme>>). `surl` sends `Date`, `Server` with its own name, `ETag`, `Last-Modified`, `Content-Type` from the file{apos}s extension and `Content-Length` (<<surl-readme>>). `ETag` is an entity tag, a quoted token that changes when the file does (<<rfc9110>>). `Date` changes with the clock, and `ETag` and `Last-Modified` with the file, so no claim depends on their values. Header names are case-insensitive (<<rfc9110>>); to find one, compare names with `StringComparison.OrdinalIgnoreCase` rather than looking for an exact spelling.

`Body` is the body, read here to its end. Ask with `HEAD` instead of `GET` and the server sends the same headers, `Content-Length: 16` included, and no body, so `Body` ends at once. A `404 Not Found` has a shorter head: `Date`, `Server`, `Content-Type: text/plain; charset=utf-8` and `Content-Length: 14`, with no `ETag` and no `Last-Modified`, since there is no file to describe. Its 14-byte body is `surl`{apos}s own short text, `404 Not Found`.
