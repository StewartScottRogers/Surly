=== Passing Any surl Option Through

==== Problem

The `surl` option you need, such as `--max-request-head`, has no property on `SurlServerOptions`. You want to give it to your in-process server from .NET in `surl`{apos}s own words, and know what happens when the option is one the library will not take.

==== Solution

==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties, but not every option has one. `AdditionalArguments` takes the rest: a list of strings, each one argument as a shell would split it, so `--max-request-head` and `1000` are two entries. `--max-request-head` is the largest Hypertext Transfer Protocol (HTTP) request head the server reads, in bytes. With it at 1000, an ordinary request is `200 OK`, and the same request carrying a 2000-character `X-Trace` header is refused with `431 Request Header Fields Too Large` (<<rfc6585>>). Without the argument the server keeps its much larger default, and both requests are served. `surl --aihelp` lists every option and its default (<<surl-readme>>).

The program{apos}s server also has `AllowUploads` and an account, a `SurlAccount` named `alice`, because uploads need a login; each `CurlRequest` the `CurlClient` sends logs in with Digest through `CurlAuthenticationOptions`, and the program prints the status line of each `CurlResponse`. With the properties alone, a `PUT` of a new file is `201 Created`. `AdditionalArguments` are read after the properties, as a later option on a command line wins over an earlier one, so `--no-allow-uploads` there turns `AllowUploads` back off and the same `PUT` is `405 Method Not Allowed`. That order is useful for a shared options builder that a test adjusts; it is also a way to contradict yourself without noticing, so prefer the property when there is one.

Two kinds of option are refused, at different moments. Options that belong to a host, `--log-file` here, are refused before anything starts: `SurlServer.StartAsync` throws `ArgumentException`, and the message names the property to use instead, `SurlServerOptions.Log`. The list in the library{apos}s documentation also has `--help`, `--aihelp`, `--manual`, `--version`, `--trace` and `--trace-ascii`. An option `surl` itself refuses, such as `--max-request-head abc`, whose value is not a number, fails the start as the `surl` command line would: `SurlServerStartException` with `ExitCode` `FailedInit`, `surl`{apos}s exit code 2, and `Lines` holding `surl`{apos}s own message without its `surl:` prefix. In both cases nothing listens and there is no server to stop.
