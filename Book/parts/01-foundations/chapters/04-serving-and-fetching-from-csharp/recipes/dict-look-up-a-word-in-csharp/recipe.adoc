=== Looking Up a Word from C#

==== Problem

Your C# program needs the definition of a word from a Dictionary Server Protocol (DICT) server. You want to ask for it with `Curl.Api`, against a `Surl.Api` server in the same process whose headwords are files.

==== Discussion

`SurlServer` is the server in this process and `SurlServerOptions` is its command line as properties. `ListenUrls` holds `dict://127.0.0.1:0`, port `0` taking a free one, and `server.BoundUrl` has the port it took. `Files` holds content in memory: each key is a headword and its bytes the definition, in one database named `surl`, the way each file under `--directory` is on the console (see <<dict-look-up-a-word>>). `SurlServer` stops when the `await using` ends.

`CurlClient` sends a `CurlRequest`, and a DICT URL is an ordinary `GET`: the path says what to ask, and the `Body` of the `CurlResponse` is the server{apos}s whole reply, status lines included. DICT ends its lines with CR LF, which the program prints as plain new lines; the greeting carries a message number that counts up per connection, so the program blanks it. The reply to `d:surly` is the `220` greeting and `250 ok` every answer starts with, then `150` and `151` naming the word and its database, the definition, a line holding a dot, and `250 ok` and `221 bye`.

`m:surl` asks which headwords match: with no strategy named, the server matches by prefix, so `surl` and `surly` are both listed under `152 2 matches found`. A third and fourth part of the path name the database and the strategy, `*` meaning every database, and `m:surly:*:exact` lists `surly` alone. `show:db` lists the databases, and the server has one.

A miss is not an error to the library. A word with no file is answered `552 no match`, a database the server does not have, as in `d:surly:wordnet`, is `550 invalid database`, and each arrives as a normal response: `SendAsync` throws nothing, and the program has to read the status line. `StatusCode` is `0` for every reply, because DICT has no status line of the kind HTTP has; the numbers are in the body. A dot file and a folder are never headwords, so `d:.secret` and `d:more` are both answered `552 no match` although the store holds them.
