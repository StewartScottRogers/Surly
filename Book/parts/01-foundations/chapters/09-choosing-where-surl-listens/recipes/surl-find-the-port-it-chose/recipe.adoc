==== Discussion

Port 0 in a listen URL asks the operating system for any free port. Once it is listening, `surl` writes a line to standard output for the listen URL, `Listening on http://127.0.0.1:53124/`, with the port it got in place of the 0. The line is the signal that the server is ready, so the script waits for it rather than sleeping and hoping. The port is the digits between the last `:` and the final `/`; the script keeps the whole URL as well, so `curl` connects to exactly the address `surl` bound. `--directory site` serves the folder, and `curl -s` keeps `curl`{apos}s progress meter out of the output.

The script sends `surl`{apos}s standard output to `listening.txt`, where the line lands, and its standard error, where `surl` logs each exchange and writes why it refused to start, to `surl.log`, so neither mixes with what `curl` prints.

A wait with no way out is a hung test. The loop checks on each pass that `surl` is still running. If it is not, `surl` refused to start, wrote why to standard error and exited with a code that says what went wrong; the script prints the message and exits with the same code. An address the machine does not have, such as `192.0.2.1`, is refused with `45`, `BindFailed`, and no `Listening on` line at all.

`-s` silences `surl`, the `Listening on` line included. A script that waits for the line must not pass `-s`; this one gives up after about five seconds by the clock, not after a count of tries, so a slow machine does not stretch the wait, and exits 1.
