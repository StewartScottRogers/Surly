=== Finding the Port surl Chose in C#

==== Problem

Your C# test fixture starts its server on port 0 so that parallel test runs never collide, and you want to read the ports it actually got from `BoundUrl` and `BoundUrls` and build every client URL from them.

==== Discussion

`SurlServerOptions.ListenUrls` is `surl`{apos}s listen URLs as a list; port 0 asks the operating system for any free port. `SurlServer.StartAsync` returns once every listener has bound, so there is no line to wait for, as there is with the `surl` process: the ports are already on the server. `BoundUrls` holds one URL per listen URL, in the order given, each with the port it got in place of the 0 and a trailing `/`. `BoundUrl` is the first of them, which is all a fixture with one listener needs. Both are `Uri` values, so `$"{bound}hello.txt"` appends a path without doubling the slash. `ListenUrls` is left as given, port 0 and all: building a client URL from it would send the client to port 0.

Each port-0 listen URL is its own listener with a port of its own, so two listen URLs give two ports, and the client reaches the same files through either. `CurlClient.Create()` makes the client, `CurlRequest` is the method and URL, and `CurlClient.SendAsync` returns a `CurlResponse` with the status in `StatusCode` and the bytes in `Body`.

A start that `surl` would refuse throws `SurlServerStartException` from `StartAsync`, with `ExitCode` the code `surl` would have exited with and `Message` its message, and nothing is left bound. An address the machine does not have is `45`, `BindFailed`, followed by the platform's reason; a listen URL with a path, such as `http://127.0.0.1:0/hello.txt`, is `3`, `MalformedUrl`, because a listen URL names where to listen and nothing more. Either way there is no server, so there are no bound URLs to read. The program returns the code, as `surl` would.
