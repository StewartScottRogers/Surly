=== Listening on IPv6 Loopback from an Agent

==== Problem

You want an artificial intelligence (AI) agent to start a server on both the Internet Protocol version 4 (IPv4) and version 6 (IPv6) loopback addresses with Model Context Protocol (MCP) tool calls, and to fetch the same file from each.

==== Solution

Write the agent{apos}s side as a C# program on the official MCP software development kit (SDK). It starts `surl-mcp` and `curl-mcp`, calls `start_server` with one listen URL for each address, and calls `transfer` on each URL the server bound:

==== Discussion

`StdioClientTransport` starts each host by name from `PATH`, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine them to the folder the program runs in; `mcp.json` beside this recipe is the same configuration for an agent{apos}s own client. The argument after `--` picks the scenario.

`start_server` takes `listen_urls` as a list, and an IPv6 address in one is written in square brackets (<<rfc3986>>): `http://[::1]:0`. `::1` is the loopback address of IPv6 (<<rfc4291>>), a different address from `127.0.0.1`, so each is its own listener. Port 0 asks the system for a free port; the answer{apos}s `bound_urls` lists the real URL for each listen URL, in order, and the two ports differ. The agent fetches from `bound_urls`, as it does in <<http-serve-and-fetch-from-an-agent>>.

`transfer` answers in text, as JSON. Its `info` holds `primaryIp`, the address the answer came from, so the agent can show the request really went over IPv6: `127.0.0.1` for the first URL and `::1` for the second, both `200`.

A server listening only on `[::1]` is closed to IPv4. `transfer` to `127.0.0.1` at the same port has nothing to connect to: `failure` is `CurlExit` with `exitCode` 7 and the call is a tool error. That is how an agent shows an IPv6-only server, and a client that must fall back.

The bare address is wrong on both sides. A listen URL `http://::1:0` is a tool error carrying `surl`{apos}s own exit code, `exit_code` 3 and `exit_code_name` `MalformedUrl`, and nothing is bound. A request URL written the same way never reaches `curl`: `transfer` refuses it as an `InvalidRequest`, not an absolute URL with a scheme, again a tool error.

A listen URL on `[::]`, every IPv6 address, is refused before it is bound: the host is not loopback, and exposing a test server to the network is for whoever starts `surl-mcp`, with `--allow-non-loopback`, not for the agent driving it. The answer is a `refused` text instead of an exit code.
