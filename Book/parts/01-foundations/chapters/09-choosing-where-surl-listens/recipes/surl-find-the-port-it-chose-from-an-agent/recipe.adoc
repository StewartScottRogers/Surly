=== Finding the Bound Port from an Agent

==== Problem

You want an artificial intelligence (AI) agent to start a Hypertext Transfer Protocol (HTTP) server on port 0, so it never fights another agent or test for a port, and to build every URL it fetches from the `bound_urls` that `start_server` answers.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts `surl-mcp` and `curl-mcp`, calls `start_server` with two port-0 listen URLs, and calls `transfer` on each URL in `bound_urls`:

==== Discussion

`StdioClientTransport` starts each host by name, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine them to the program's folder. The argument after `--` picks the scenario.

`start_server` takes `surl`{apos}s listen URLs in `listen_urls`; port 0 asks the operating system for a free port, and each listen URL gets a port of its own. `surl-mcp` answers in structured content, a JavaScript Object Notation (JSON) element. `listen_urls` comes back exactly as given, port 0 and all, so it is no use for building a client URL. `bound_urls` has one entry per listen URL, in the same order, with the real port in place of the 0 and a trailing `/`, so the agent appends a path and has a URL. There is nothing to wait for: `start_server` answers once the server is listening, and `bound_urls` is the agent{apos}s equivalent of `surl`{apos}s `Listening on` lines.

`list_servers` takes no arguments and lists every server this `surl-mcp` started and that is still running, each with its `server_id` and the same `bound_urls`. An agent that has lost `start_server`{apos}s answer, or a later step that was never given it, finds the ports there.

`transfer` is `curl-mcp`{apos}s one-request tool; `url` is the only field this recipe needs, and it answers in text, as JSON, with `statusCode` and the `body`.

A listen URL that `surl` would refuse is refused the same way: `start_server` is a tool error whose structured content carries `surl`{apos}s `exit_code` and `exit_code_name`, and whose text is `surl`{apos}s message. A path, as in `http://127.0.0.1:0/hello.txt`, is `3`, `MalformedUrl`, because a listen URL names where to listen and nothing more. No server started, so there is no `bound_urls` to read; the program prints whether the call was a tool error and exits 1 if it was.
