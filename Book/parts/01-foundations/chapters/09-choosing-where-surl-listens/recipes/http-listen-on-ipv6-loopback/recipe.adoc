=== Listening on IPv6 Loopback

==== Problem

You want `surl` on `[::1]` as well as `127.0.0.1`, and `curl` to reach each, so you can test a client that has only an Internet Protocol version 6 (IPv6) address, or one that tries both.

==== Discussion

`surl` takes as many listen URLs as you give it, and an IPv6 address in one is written in square brackets, as in any Uniform Resource Locator (<<rfc3986>>): `http://[::1]:8080/`. `::1` is the loopback address of IPv6 (<<rfc4291>>), the counterpart of `127.0.0.1`; the two are different addresses and `surl` binds each on its own. Listing both at one port means a client may use either and the file, which comes from the one `--directory`, is the same.

Brackets are not optional. Without them the colons of the address are taken for a port, and the URL is malformed: `curl` exits `3`, and `surl` refuses the same mistake in a listen URL at once, exit `3` with `URL rejected`, so a typo does not leave you with a server that listens somewhere else. The full form, `[0:0:0:0:0:0:0:1]`, is the same address.

Which address answered is not always obvious, since a client that is told `localhost` may try either. `-w "%{remote_ip}"` says: `127.0.0.1` for the first URL and `::1` for the second. With `-o` for each URL, the bodies go to nowhere and only the addresses print. The `Host` header of a request to the second keeps the brackets and the port, `[::1]:port`, which is what `-v` shows.

A `surl` that listens only on `[::1]` is closed to IPv4. The same port on `127.0.0.1` has no listener, and a client sent there fails to connect, exit `7`. That is how you test an IPv6-only client, or one that must fall back to the other address.

`-g` is `curl` turning off globbing, the expansion of `[1-2]` and `{a,b}` in a URL. It is not needed for the address: `curl` recognises an IPv6 address in the host part and leaves it alone. It matters when the path has brackets of its own. Without `-g`, `f[1-2].txt` is a range and `curl` fetches `f1.txt` and `f2.txt`; with `-g`, it is a file name with brackets in it, which does not exist and is `404`. Use `-g` when you want the brackets literally.

`-s` keeps `curl` quiet, and `--directory` is the folder `surl` serves; see <<http-serve-a-directory>>. This recipe needs a machine with an IPv6 loopback.
