=== Failing on a 404 from an Agent

==== Problem

You want an artificial intelligence (AI) agent to tell a missing file from an empty one over Hypertext Transfer Protocol (HTTP), reading the status from `curl-mcp`{apos}s `transfer` tool and the exit code from its `curl` tool with `--fail`.

==== Discussion

`StdioClientTransport` starts each host by name from `PATH`; `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine both to the folder the program runs in. `start_server` starts a server that answers as `surl` would, on a free port, and its `files` holds `empty.txt` with no bytes in it. Its structured content gives the real address in `bound_urls`. A path not in `files` is answered `404 Not Found`, with an empty body (<<surl-readme>>).

`transfer` makes one request from fields, here only `url`, and answers in text as JavaScript Object Notation (JSON). A `404` is an answer, not a failure (<<rfc9110>>): `statusCode` is 404, `failure` is null and the call is not a tool error. The body is `surl`{apos}s short error text, `404 Not Found` and a newline, which an agent that looked only at the body could save as if it were the file; the empty file that is there gives an empty body and `statusCode` 200. So an agent using `transfer` reads `statusCode`, not the body.

The `curl` tool runs `curl` with `args`, as a script would. `-f` makes `curl` exit `22` on a status of 400 or more, and `curl-mcp` reports a nonzero exit as a tool error whose `failure` has kind `CurlExit` and whose `exitCode` is 22 (<<curl-readme>>). `-w "%{http_code}"` still prints `404` on standard output, and `-s` keeps the progress meter out of it. For the empty file the same call exits `0`, prints `200` and is not a tool error. An agent that only watches for tool errors therefore needs `-f`; without it a `404` is a clean exit `0`.
