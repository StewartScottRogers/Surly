=== Recovering from Taken Ports from an Agent

==== Problem

Your artificial intelligence (AI) agent asks for a server on a fixed port, and sometimes something else already holds it. You want the agent to see `start_server` refuse the port, read why from the answer, and start again on port 0, all with Model Context Protocol (MCP) tool calls.

==== Solution

Write the agent's side as a C# program on the MCP software development kit (SDK): it calls `start_server` on the port, reads `exit_code` `45` from the refusal, calls `start_server` again on port 0, and fetches from the URL that one bound with `transfer`:

==== Discussion

The program starts both hosts by name with `StdioClientTransport`, each confined to the folder it runs in by `SURL_MCP_ROOT` or `CURL_MCP_ROOT`; `mcp.json` beside the recipe is the same configuration for an agent's own client. The argument after `--` picks the scenario. The something else is a plain `TcpListener` the program starts on the loopback address before asking `start_server` for its port.

`start_server` starts a Hypertext Transfer Protocol (HTTP) server on the `listen_urls` given, with `files` in memory, and answers in structured content. A start `surl` would refuse is a tool error, `IsError` set, and its structured content carries `surl`{apos}s own exit code, `exit_code` `45`, with `exit_code_name` `BindFailed`; its text is `surl`{apos}s message, `surl: (45) Could not bind http://127.0.0.1:8080/: Address already in use`, naming the listen URL that failed. An agent acts on the code, as a script acts on `surl`{apos}s exit status: `45` means the port is taken, and port 0, which asks the operating system for a free one, fixes it.

The second `start_server` asks for port 0. Its `bound_urls` names the port the server bound, neither the taken one nor 0, and `transfer` fetches the file from that URL, `200`. The agent fetches from `bound_urls`, not from the URL it asked for. On a port nothing holds, the first `start_server` binds the port asked for and there is nothing to recover from.

Only `45` is worth that retry. A port that is not a port at all, `70000`, is a tool error too, but with `exit_code` `3`, `MalformedUrl`, and `URL rejected`; port 0 would not fix the agent's mistake, so this one stops and says so.
