=== Failing on a 404 in C#

==== Problem

Your .NET program downloads a file over Hypertext Transfer Protocol (HTTP) and must treat a `404` as a failure, and you want it to check the status `Curl.Api` returns and throw with a clear message instead of saving an empty file.

==== Solution

==== Discussion

`SurlServerOptions` puts one file, `report.txt`, in the in-memory store `Files`, and `ListenUrls` asks for a free port on the loopback address; `SurlServer.StartAsync` returns once it is bound, and `BoundUrl` is its address. A path not in `Files` is answered `404 Not Found` (<<surl-readme>>).

`CurlClient.SendAsync` sends the `CurlRequest` and returns a `CurlResponse` as soon as the status line and headers are in. A `404` is a response (<<rfc9110>>), so nothing throws (<<curl-readme>>): the program has to look at `StatusCode` itself, the `curl -f` of this library. `DownloadAsync` does that before `File.Create`, so a missing file leaves nothing on disk, and throws `DownloadFailedException`, the program{apos}s own type, whose message names the method, the URL, `StatusCode` and `ReasonPhrase`. The top of the program catches it, writes the message to standard error and exits `22`, the code `curl -f` exits with. The type, the message and the exit code are the program{apos}s choices.

For a file that is there, the status is `200`, `Body` is copied into the file, and the program exits `0`. Drop the check, as `--no-check` does, and the trap appears: the `404`{apos}s body, empty from `surl`, is saved as a file of 0 bytes and the program reports success, as `curl` without `-f` would.
