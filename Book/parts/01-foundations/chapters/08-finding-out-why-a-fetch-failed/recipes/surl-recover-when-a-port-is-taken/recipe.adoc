=== Recovering When a Port Is Taken

==== Problem

Your test asks `surl` for a fixed port, and sometimes something else already holds it. You want to recognise that failure by its exit code and message, start `surl` again on port 0, and read the port it chose.

==== Solution

==== Discussion

Here the something else is another `surl`, `holder`, started on the port first. A listener that cannot bind its address and port makes `surl` write `surl: (45) Could not bind http://127.0.0.1:8080/: Address already in use` to standard error and exit `45` at once. `45` is `BindFailed`, and `surl --aihelp exit-codes` gives the next step for it: another port, or port 0 and the `Listening on` line. The message names the listen URL that failed.

The script starts `surl` serving `site` with `--directory site`, in the background, and waits for one of two things: a `Listening on` line on standard output, or `surl` exiting. Once the line is there, it reads the URL from it and asks for it with `curl`, `-o /dev/null` dropping the reply, until an answer comes, since the line can be written a moment before the port takes connections, and a fetch in that moment fails with exit `7`. If `surl` has exited, `wait` hands the script its exit code. On `45` the script prints the message and starts again on port 0, which asks the operating system for a free port. The `Listening on` line then names the port `surl` bound, not 0, and the script fetches `hello.txt` there with `curl`, which `-s` keeps quiet. On a port nothing holds, the first start succeeds and the script never falls back.

Only `45` means the port is taken. Any other code is a different mistake that port 0 would not fix, so the script passes it on: a port that is not a port at all, `70000`, is exit `3`, `URL rejected`. A test that retried on every failure would hide that. The script also gives up, with exit `1`, if `surl` neither listens nor exits within five seconds, or its port does not answer within five more.

Port 0 from the start avoids the clash altogether (see <<surl-find-the-port-it-chose>>). A fixed port is still what some tests want, such as one an application under test is configured with, and this is the way back when it is taken.
