=== Failing a Script on a 404

==== Problem

Your shell script downloads a file over Hypertext Transfer Protocol (HTTP) and must stop when the file is missing, and you want `curl` to turn a `404` into a nonzero exit code, print the status, and say what went wrong.

==== Solution

Give `curl` `-f` and print the status with `-w`; a missing file makes it exit `22`:

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

`--directory site` makes `surl` serve the files under `site`; `site/report.txt` is there, `missing.txt` is not, and `surl` answers it `404 Not Found` with that same text as a short body (<<surl-readme>>).

To `curl`, a `404` is an answer like any other (<<rfc9110>>): without `-f` it exits `0`, and `-o` saves the error text, `404 Not Found`, where the download should be, which the next step of a script will read as if it were the report. `-f` turns any status of 400 or more into exit `22`, and the script can test that, with `|| echo download failed` here, or `|| exit 1`, or `set -e`.

`-w "%{http_code}\n"` prints the status after the transfer, whether it failed or not, so a log shows `404` and not only a bare `22`. `-s` keeps the progress meter quiet and, alone, would hide the error message too (<<curl-manual>>); `-S` brings that message back on standard error: `curl: (22) The requested URL returned error: 404`. For a file that is there, the same command exits `0`, prints `200` and saves the file.

`--fail-with-body` exits `22` in the same way but still writes the body of the error reply, which helps when a server explains itself in an error page. `surl`{apos}s explanation is short: its `404` body is the line `404 Not Found`, 14 bytes as `%{size_download}` shows, and `--fail-with-body` writes it to standard output before the `-w` line (<<curl-manual>>).

`-f` is about the status, not the file: a `503 Service Unavailable` exits `22` too. The second server here answers every request for `/report.txt` with `503` because of `--fault "error;scheme=http;path=/report.txt;reply=503"`, an option that makes `surl` misbehave on purpose for a test and warns about it when it starts (<<surl-readme>>); it is not the default because such a server looks broken to every other client. That server has no `--directory` and no files: the fault answers before any file is looked up.
