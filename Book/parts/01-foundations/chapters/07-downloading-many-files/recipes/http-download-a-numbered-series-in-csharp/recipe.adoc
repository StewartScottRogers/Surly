=== Downloading a Numbered Series in C#

==== Problem

Your C# job downloads a numbered series of files over Hypertext Transfer Protocol (HTTP), `report-1.csv` to `report-12.csv`, and some numbers are missing. You want it to fetch them in turn with one shared client, save the ones that are there, and report which numbers were `404`.

==== Discussion

The program hosts its own server with `SurlServer`: `SurlServerOptions.Files` holds the series in memory with two gaps, 4 and 9, on a free port that `BoundUrl` names. `RecordExchanges` is on only so that the program can count connections at the end.

`curl` on the console has globbing, `[1-12]` in the URL; `Curl.Api` does not, and needs none: a `for` loop builds each `CurlRequest` from the number, which also lets the job decide what to do with each answer. `CurlClient.SendAsync` returns a `CurlResponse` for a `404` as for a `200`, and throws for neither, so the loop reads `StatusCode`, adds the number to `missing` for a `404`, and otherwise copies `Body` into `reports/report-N.csv`. Nothing is written for a missing number, unlike `curl -o` without `-f`, which writes an empty file.

Each `Body` is read to its end and disposed before the next request, even the empty one of a `404`. That leaves the connection free, and the one client sends every request of the series over it: the server records one exchange for all twelve. Create the client once for the job and dispose it at the end.

The job exits `1` when any number was missing and `0` when none was, its own choice of codes, so a scheduler can tell a complete series from a gappy one. Unlike `curl -f` over a glob, whose exit code is the last transfer's, the job looks at every answer.
