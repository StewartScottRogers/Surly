=== Choosing Where Downloads Land

==== Problem

You are fetching several files over Hypertext Transfer Protocol (HTTP) and want each saved under a name and in a folder you choose, with `-o`, `-O`, `--output-dir` and `--create-dirs`, instead of having the bodies fill the terminal.

==== Solution

==== Discussion

`--directory site` makes `surl` serve the files under `site`, so `site/docs/guide.txt` is `/docs/guide.txt`. By default `curl` writes a body to standard output; each of the options here sends it to a file instead, and applies to one URL, the one after it on the line.

`-o handbook.txt` saves the body under the name given, whatever the URL calls it. `-O` saves it under the last part of the URL{apos}s path: `/reports/2026/summary.txt` becomes `summary.txt`, not `reports/2026/summary.txt`. `--output-dir downloads` puts both in `downloads`, and `--create-dirs` makes that folder when it is not there. `-w "%{filename_effective}\n"` prints the path each body was written to, once per URL, and `-s` keeps the progress meter off the terminal, so nothing else appears there.

`-o` takes a path as well as a name, and `--create-dirs` makes every missing folder on it, so `-o archive/2026/11/guide.txt` builds the tree. Without `--create-dirs`, a folder that does not exist is a write error: `curl` exits `23`, and `-S` (with `-s`) prints its message, starting `curl: (23)`. A missing `--output-dir` fails the same way.

With many files, one `-O` per URL gets tedious; `--remote-name-all` gives every URL on the line an `-O`. When the path ends in a slash, `-O` takes the last folder name, so `/docs/` is saved as `docs`; the bare root names nothing, and `curl` saves its body as `curl_response`. Both are folders, which `surl` answers `404 Not Found`, so both files are empty. An existing file is overwritten without a question (<<curl-manual>>).

Saving to a file does not make a missing file an error. A `404` is a complete answer (<<rfc9110>>), so `curl` writes its body, which from `surl` is empty, to the named file and exits `0`. A script that must not mistake an empty file for a download needs `-f`; see <<http-fail-a-script-on-a-missing-file>>.
