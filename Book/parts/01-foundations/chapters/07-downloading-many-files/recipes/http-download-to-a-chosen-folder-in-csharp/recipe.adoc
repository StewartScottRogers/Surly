=== Choosing Where Downloads Land in C#

==== Problem

Your .NET program downloads several files over Hypertext Transfer Protocol (HTTP) into a folder tree it builds, and you want each response body streamed to its own file, nothing saved for a file the server does not have, and the files checked on disk.

==== Solution

==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties: `ListenUrls` holds `http://127.0.0.1:0`, a free port, and `Files` is the in-memory store, path to bytes, so `docs/guide.txt` is served at `/docs/guide.txt`. `SurlServer.StartAsync` returns once the listener is bound, and `BoundUrl` is its address ending in `/`.

`CurlClient.SendAsync` sends a `CurlRequest`, the method and URL, and returns a `CurlResponse` once the status line and headers have arrived. `Body` is the body still arriving; `CopyToAsync` streams it into a `FileStream` as it arrives, which is the program{apos}s `curl -o`. The file name is the program{apos}s choice: here the URL{apos}s whole path under `downloads`, so `reports/2026/summary.txt` keeps its folders, where `curl -O` would keep only `summary.txt`. The checked files hold exactly the bytes served, 10 and 12 of them.

`File.Create` does not make folders. `Directory.CreateDirectory` on the target{apos}s folder first is the program{apos}s `--create-dirs`; leave it out and `File.Create` throws `DirectoryNotFoundException`, which the program reports and turns into exit `23`, the code `curl` exits with when it cannot write.

A path the server does not have is answered `404 Not Found` (<<rfc9110>>), and to `Curl.Api` that is an ordinary `CurlResponse`; nothing throws (<<curl-readme>>). The program checks `StatusCode` before it opens a file, so no empty file is left behind, and exits `22`, as `curl -f` would. That check and those exit codes are the program{apos}s, not the library{apos}s. The server is stopped when `await using` disposes it (<<surl-readme>>).
