=== Downloading a Numbered Series

==== Problem

A server publishes `report-1.csv` to `report-12.csv` over Hypertext Transfer Protocol (HTTP), and some months are missing. You want all of them in one command, each saved under its own name, and a list of the numbers that were not there.

==== Solution

==== Discussion

`[1-12]` in the URL is `curl`{apos}s globbing: one command line becomes twelve requests, `report-1.csv` to `report-12.csv`, made in order. Quote the URL so that no shell reads the brackets first. `#1` in `-o` is replaced by what the first bracket stood for in that request, so each answer gets its own file; without it, all twelve would overwrite one. `--create-dirs` makes `reports/` if it is not there.

`-f` turns a `404` into a failed transfer, and `-w` prints its format after each transfer. `%{onerror}` at the start of the format means "print the rest only if this transfer failed", so the output is the list of missing paths, `%{url.path}`, and nothing for the ten that arrived. Without `%{onerror}`, `-w "%{http_code} %{url.path}\n"` prints all twelve with their status, which is the report to keep if you want the whole picture. `-s` keeps `curl`{apos}s own error messages out of the list.

Do not trust the exit code to find the gaps. With `-f`, `curl` exits with the result of the last transfer: the series here exits `0` because `report-12.csv` was there, and the same command over `[1-4]`, whose last number is missing, exits `22`. `--fail-early` changes that: `curl` stops at the first failure and exits `22`, and nothing after it is fetched. Use it when one gap makes the rest worthless.

Without `-f`, a missing number is a successful conversation to `curl`, and `-o` writes the `404`{apos}s body, `surl`{apos}s short `404 Not Found`, to `report-4.csv`. A file being there then proves nothing; the status does.

`-O` names each file from its URL instead, `report-8.csv` for `report-8.csv`, and `--output-dir` puts them in a folder. `%{filename_effective}` is the name `curl` wrote to, which reports the gap as a local path rather than a URL.

`surl` serves the files under `site`, given by `--directory`, and answers a path it does not have with `404`; it knows nothing of series, and each request is judged on its own.
