=== Downloading a Numbered Series from an Agent

==== Problem

You want an artificial intelligence (AI) agent to fetch a numbered series of files over Hypertext Transfer Protocol (HTTP), `report-1.csv` to `report-12.csv`, with one Model Context Protocol (MCP) tool call, and to report the numbers that were missing.

==== Solution

Write the agent's side as a C# program on the official MCP software development kit (SDK): it starts `surl-mcp` and `curl-mcp`, calls `start_server` with the series, then calls the `curl` tool with one globbed URL and reads the missing paths from its standard output:

==== Discussion

`surl-mcp` and `curl-mcp` are the two programs' MCP servers; the program starts each by name from `PATH` with `StdioClientTransport`, confined to the folder it runs in by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. `mcp.json` beside this recipe is the same configuration for an agent's own client. The argument after `--` picks the scenario.

`start_server` starts a server on a free port holding the series in memory, with two gaps, 4 and 9; the program builds the URL from the first of its `bound_urls`.

The `curl` tool runs `curl` with the arguments given, so the globbing is `curl`{apos}s own: `report-[1-12].csv` becomes twelve requests in order. `-O` names each file from its URL, `--output-dir reports` puts them in `reports/` under the root, and `--create-dirs` makes the folder. `-f` turns each `404` into a failed transfer that writes no file, `-s` keeps `curl`{apos}s messages out, and `-w "%{onerror}missing %{url.path}\n"` prints a line only for a transfer that failed. The answer is text holding JavaScript Object Notation (JSON); the agent reads `standardOutput.content`, one `missing` line per gap, and lists the paths. The program also counts the files in `reports/`, ten, which it empties first so the count is this run's.

`exitCode` here is `0`, though two numbers were missing: with `-f`, `curl` exits with the last transfer's result, and `report-12.csv` was there. The agent must read the list, not the exit code. Add `--fail-early` when one gap makes the rest worthless: `curl` stops at `report-4.csv` and exits `22`, which `curl-mcp` reports as a tool error with a `failure` of kind `CurlExit`, having saved only the three before it.

On the console, `-o "reports/report-#1.csv"` names each file from the glob. `curl-mcp` refuses that before `curl` runs: it checks every output path against `CURL_MCP_ROOT`, and a name with `#1` in it is not known until `curl` fills it in. That is the host being careful with the agent's files; `-O` with `--output-dir` gives the same names and can be checked.

`transfer` is the other way to fetch with `curl-mcp`, but it does not glob. It sends the brackets as part of the path, and the server answers `404`. For a series through `transfer`, the agent makes one call per number.
