=== Downloading FTP Folders from an Agent

==== Problem

You want an agent to list a folder on a File Transfer Protocol (FTP) server, decide which entries are files, and fetch each one into its root.

==== Solution

Start an FTP server through `surl-mcp` that may list folders, list the folder through `curl-mcp` twice, once with `-l` for the names and once without for the types, skip the subfolders, fetch each file, and check it with `read_file`:

==== Discussion

`start_server` of `surl-mcp` takes `listen_urls`, here `ftp://127.0.0.1:0` for a free port; `files`, a map from name to text, where a name with slashes makes the folders; and `arguments`, `surl`{apos}s own words. `--allow-anonymous` lets `curl`{apos}s anonymous login in, so it is for a test on your own machine only. `--list-directories` lets a client list a folder, which `surl` refuses unless asked. The answer holds the `server_id` and `bound_urls`.

The `curl` tool of `curl-mcp` runs real `curl` options: `args` is the list of words, and the answer holds `exitCode`, `standardOutput` and `standardError`, each with its `content`. `-s` keeps the progress meter away. `-l` on a URL that ends in `/` answers the names only, one a line, in order (<<rfc959>>): a subfolder is a name like any other, `archive` here, and the dot file is not there, since `surl` does not serve dot files. The same URL without `-l` answers the long listing, and a folder{apos}s line starts with `d` where a file{apos}s starts with a dash. The agent keeps the names of the `d` lines, and skips them. Line ends are carriage return and line feed, which the program strips.

Each remaining file is one more `curl` call with `-o out/pub/<name>`, and `--create-dirs` makes the folder. `curl-mcp` is confined to its root, the folder named by `CURL_MCP_ROOT`, so the files land there and the program can read them back. `read_file` of `surl-mcp`, given the `server_id` and a path that starts with `/`, answers what the server holds as `text`; the local copy and that text are the same for all three files, and the root holds those three files and nothing else. The same routine on `pub/archive` fetches its one file; descending is a decision the agent makes, not something the listing does.

A nonzero exit code reaches the agent as a field of the answer, and the program reads it either way. A server started without `--list-directories` refuses the listing: exit code `19`. A subfolder asked for as if it were a file is `78`, file not found, the same as a name that has gone since the listing and as a dot file asked for by name. An agent has to check the code of each file, so that one gone file is not mistaken for a copy.
