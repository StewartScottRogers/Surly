=== Limiting Download Speed

==== Problem

You want to download a large file over Hypertext Transfer Protocol (HTTP) slowly, as if over a poor link, to see how your code behaves when the bytes trickle in, and to measure the speed you actually got.

==== Solution

Serve the file with `surl`, fetch it with `curl --limit-rate`, and have `-w` print the size, the average speed and the time taken:

==== Discussion

`--limit-rate 25k` caps the average speed of the transfer at 25 kibibytes a second, 25600 bytes; `k`, `m` and `g` are powers of 1024, and a bare number is bytes. `curl` does the slowing on its own side, by pausing between reads, so the server needs nothing: `surl` here is the plain `--directory site` server of every other recipe, sending as fast as the client will take. Fetched over loopback with no limit, the same 100000 bytes arrive in well under two seconds; with the limit they take two seconds or more.

`-w` prints its format once the transfer is done. `%{size_download}` is the bytes received, `%{speed_download}` their average in bytes a second over the whole transfer, and `%{time_total}` the seconds from start to finish. Read `speed_download` as an average over the whole transfer, not a ceiling held at every moment; the cases below ask only that it stays under 50000, twice the limit, and that the time is two seconds or more. `-s` keeps the progress meter off the screen and `-o big.bin` keeps the bytes out of it.

The limit holds for every transfer on the command line, not for the command as a whole: two URLs under one `--limit-rate 25k` each take two seconds or more, each at its own average under 50000.

A slow link is where timeouts bite, which is often what this test is for. `--max-time 1` on the same limited transfer gives up after one second, before the file is complete, and `curl` exits `28`, the operation timed out. `-w` still runs: `%{http_code}` is the `200` the transfer started with, and `%{exitcode}` the `28` it ended with. A program that treats the `200` alone as success has a partial file and does not know it.
