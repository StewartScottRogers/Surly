=== Walking Gopher Menus from an Agent

==== Problem

You want your agent to start at a Gopher server's root menu, follow a directory entry to its own menu, fetch a file from it, and recognise the error menu when a selector names nothing.

==== Solution

The program starts `surl-mcp` and `curl-mcp`, calls `start_server` for a Gopher server that lists directories, and calls `transfer` for each menu and file, taking each next selector from the menu line it just read. It takes a scenario name as its argument, so each claim below runs the same file:

==== Discussion

`start_server` takes `listen_urls`, here `gopher://127.0.0.1:0` for a free port, `arguments`, the `surl` options as a list, and `files`, a map from path to text that the server holds in memory. `["--list-directories"]` in `arguments` is the option of that name: it turns on menus for folders, and it is off unless asked for, like every option that widens what a peer may see. The program starts a second server with an empty `arguments` over the same files, to show what the option governs. The answer carries `bound_urls`, the addresses with their real ports, and the program reads the first.

`transfer` is the plain fetch of `curl-mcp`: it takes a `url` and answers JSON text, from which the program reads `body.content`. In a Gopher address the character after the slash is the item type, and it is not sent: `.../1/notes` sends the selector `/notes`. `surl` does not check the type either, so a file asked for as a menu comes back as a file and a folder asked for as a file as its menu. Gopher has no status, so there is nothing to read but the body, and the answer reports no failure for a selector that names nothing.

A menu is lines of tab-separated fields: type, display name, selector, host, port, each line ended by `\r\n`, and a final line holding a dot. A type `1` line is a folder, a type `0` line a file, and the second field is the selector to send next, written in full from the served root, so `/notes/archive`, not `archive`. The `walk` scenario asks for the root with `1`, follows the first type `1` line of each menu until one has none, then fetches the first type `0` line it finds. A trailing slash changes nothing: the answers for `notes/` and `notes` are equal.

Whether a selector names a missing file or a missing folder, the answer is the same fixed error menu: one type `3` line, `Nothing is served at this selector.`, which does not repeat the selector. An agent that acts on a menu must read the first character of each line, since no failure is reported. With `--list-directories` off, the root and the folders give that error menu too, so a walk cannot start, but a file whose selector is already known is still served.
