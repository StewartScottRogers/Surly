=== Holding a Telnet Session in C#

==== Problem

Your C# code talks to a line-based service over Telnet, and you want a test that holds a session with surl{apos}s Telnet server, checks that every line comes back and that `quit` ends the session, and reads what the server was told about the client.

==== Solution

Start a `SurlServer` on a Telnet listen URL, send it three lines ending in `quit` as the body of a `Curl.Api` request, and read the response until the server closes the connection:

==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties. `ListenUrls` holds `telnet://127.0.0.1:0`, port 0 asking the system for a free port, and `SurlServer.StartAsync` returns once the listener is bound. `SurlServer.BoundUrl` is the address it got, and the program sends its request there. `Log` is a `TextWriter` that receives what `surl` would print, and a `LogLevel` of `Verbose` is `-v`; the program reads the log back at the end of one scenario.

`CurlClient` sends a `CurlRequest` whose `Body` is the lines, each ending in a carriage return and line feed. A body on a request to a `telnet://` URL is sent to the server as `curl -T` sends a file; the program makes it a `PUT`. On the console `curl` sends what it reads from standard input (<<telnet-hold-a-line-session>>), and from an agent the `curl` tool takes `stdin` (<<telnet-hold-a-line-session-from-an-agent>>). `CurlClient.SendAsync` returns a `CurlResponse` as soon as the session opens, and its `Body` is the stream of what the server sends.

Telnet (<<rfc854>>) starts with the two ends agreeing on options, bytes that begin with `255`. `Curl.Api` answers them itself and leaves them out of the `Body`, so what the program reads is the text: a banner line, then each line echoed, then `bye`. Send `quit`, or `QUIT`, which is matched without regard to case, and the server says `bye` and closes the connection, so `ReadAsync` returns `0`. Anything after `quit` is never read. A session that never sends it stays open: the program stops waiting after a second of silence and says so, and a real client needs a timeout of its own for that case. The limit on a line is `--max-line`, 8,192 bytes by default; a line of 9,000 characters is answered `line too long` and the connection closes, without `bye`.

`CurlRequest` takes `Telnet`, a `CurlTelnetOptions`, which is `curl -t` as a property: its `TelnetOptions` is a list of `NAME=value` options, and `TTYPE=vt100` sets the terminal type the client reports. In the last scenario the body is empty and the program reads only the banner, then disposes the response, which ends the session. The server{apos}s verbose log then holds `The client{apos}s terminal type (TERMINAL-TYPE) is vt100.`
