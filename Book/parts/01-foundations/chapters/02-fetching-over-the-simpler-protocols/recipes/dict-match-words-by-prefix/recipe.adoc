=== Finding Words That Match

==== Problem

Your Dictionary Server Protocol (DICT) server{apos}s headwords are files, and you want to list the words that start with a prefix, then fetch the definition of the one you pick.

==== Solution

Serve a directory of word files over DICT, and ask `curl` for a match with an `m:` URL that names the prefix strategy:

include::.generated/solution.adoc[]

Stop `surl` with kbd:[Ctrl+C]. The definition of one of the words is fetched with `d:` and its name; the checked claims below do that.

==== Discussion

`--directory words` is the dictionary: each file directly in `words` is a headword, its name the word and its bytes the definition, in one database named `surl` (<<dict-look-up-a-word>> shows the whole conversation). `curl` turns the path of the URL into the command and prints the server{apos}s whole reply, status lines included, so after the greeting and the first `250 ok` you read `152 2 matches found`, one line for each match with its database and the word, and a line holding a dot.

The path is `m:` and the word to match, then the database and the strategy, separated by colons. `*` means every database, and naming it, `m:ap:surl:prefix`, gives the same answer. The strategy decides what a match is. `prefix` lists every headword that starts with the word, so `ap` finds `apple` and `apricot`, and `banana` is not there. `exact` matches whole words only, so the same `ap` is answered `552 no match`. Leaving the strategy out gives `prefix`, so `m:ap` is the same list as the solution.

`show:strat` asks which strategies the server offers, and it offers two, `exact` and `prefix`. A strategy it does not offer, `suffix` for instance, is answered `551 invalid strategy` and a pointer to `SHOW STRAT`, the command that lists them. Words are matched as they are written, so `m:AP` finds nothing. Every one of these answers, a `552` and a `551` included, leaves `curl` exiting `0`, since to `curl` any DICT reply is a successful conversation; the check for a miss is the status line, not the exit code.

Picking one word from the list, `d:apricot` defines it: `150` and `151` name the word and its database, and the file{apos}s bytes follow, ended by a dot line, `250 ok` and `221 bye`. The `<2@surl>` in the greeting counts up for each connection, so the checks allow any number. `-s` hides `curl`{apos}s progress meter; DICT replies end their lines in CR LF, which the checks read as plain new lines (<<rfc2229>>).
