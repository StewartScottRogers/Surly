==== Discussion

Trivial File Transfer Protocol (TFTP) is file transfer at its barest: one request to read or write a file, sent over User Datagram Protocol (UDP) rather than Transmission Control Protocol (TCP), with no login, no listing and no way to ask what is there. `surl tftp://127.0.0.1:8080/` listens on UDP port 8080; nothing listens on TCP.

`--directory site` serves the files under `site` at their relative paths, so `site/hello.txt` is `tftp://127.0.0.1:8080/hello.txt`. `curl` writes what it reads to standard output, or with `-o copy.txt` to that file, byte for byte. `-s` keeps its progress meter and error messages quiet, so a failure shows only as the exit code.

TFTP has no login, so `surl` has nothing to check but the file. A file that is not there is answered with TFTP error 1, and `curl` exits `68`, file not found. A file whose name begins with a dot is never served, and gets the same answer, so a peer cannot tell a hidden file from a missing one.

A write, which `-T` asks for by sending a local file (`curl -T upload.txt`), is answered with TFTP error 2, access violation, and `curl` exits `69`. `surl` accepts writes only with `--allow-uploads` (see <<ftp-list-and-upload>> for uploads on a server that has a login), and keeps it off by default, as it keeps off every option that widens what a peer may do (<<surl-readme>>). Over TFTP that matters more than most: the protocol cannot ask who is writing, so with uploads on, anyone who can reach the port can write into the served directory.

Exit `0` means the whole file arrived (<<curl-readme>>).
