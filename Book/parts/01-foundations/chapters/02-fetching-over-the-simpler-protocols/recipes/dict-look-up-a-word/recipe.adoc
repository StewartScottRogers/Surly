=== Looking Up a Word with DICT

==== Problem

You want to look up a word's definition over the DICT dictionary protocol from a local server, with the definitions kept as plain files you can edit.

==== Solution

Put one file per word in a directory, its name the word and its contents the definition, serve the directory over DICT, and ask `curl` to define the word:

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

DICT, the Dictionary Server Protocol, is a line-based protocol over Transmission Control Protocol: the client sends a command such as `DEFINE` or `MATCH`, and the server answers with numbered status lines and, between them, the text asked for, ended by a line holding a dot. `curl` turns the Uniform Resource Locator (URL) into the command and prints the server's whole reply, status lines included, so what you read is the conversation itself:

[source,text]
----
220 surl DICT server <mime> <2@surl>
250 ok
150 1 definitions retrieved
151 "surly" surl "Files served by surl"
bad-tempered and unfriendly
.
250 ok
221 bye
----

The `220` greeting and the first `250 ok` come before every answer, and `250 ok` and `221 bye` after it. The number in angle brackets in the greeting may differ on your machine; the check allows any.

`--directory words` is the dictionary. `surl` serves one database, named `surl`, in which each file directly in `words` is a headword: its name is the word and its bytes are the definition. A file whose name begins with a dot is never a headword, nor is a folder, so `words` can hold notes and subfolders without them leaking into lookups.

The path of the URL says what to ask. `d:surly` defines `surly`; `m:surl` asks which headwords match `surl`, and with no strategy named `surl` matches by prefix, so it finds both `surl` and `surly`. A third and fourth part name the database and the strategy: `m:surly:*:exact` matches exactly in every database. `show:db` lists the databases, which here is the one.

To `curl`, any reply is a successful conversation, so it exits `0` whatever the answer: a word with no file is `552 no match`, and a database other than `surl`, such as `d:surly:wordnet`, is `550 invalid database`. Read the status lines, not the exit code, to know whether the word was found. `-s` keeps `curl` from printing its progress meter.
