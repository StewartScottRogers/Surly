=== Walking Gopher Menus in C#

==== Problem

Your .NET code needs to read a Gopher server's root menu, follow a directory entry to its own menu, fetch a file from it, and tell the error menu from a real answer.

==== Solution

Start a Gopher server in the test process with `Surl.Api`, fetch menus with `Curl.Api`, and let each menu line give the selector for the next fetch. The program takes a scenario name as its argument, so each claim below runs the same file:

==== Discussion

`SurlServerOptions.Files` puts three files in the server's memory under `/`: `hello.txt`, `notes/today.txt` and `notes/archive/2025.txt`. The folders exist because their files do. `ListenUrls` of `gopher://127.0.0.1:0` takes a free port, and `ListDirectories = true` is the property for `--list-directories`: it turns on menus for folders. The second server in the program has it off, which is how the last cases show what the option governs. Both are `SurlServer` objects, and `server.BoundUrl` is their address as a `Uri`, so `.Port` is the real port.

`CurlClient` sends each fetch as a `CurlRequest` with `HttpMethod.Get`. The method is only the way the library asks for a transfer; over Gopher the request is one line, the selector. In the Gopher address the character after the slash is the item type, and it is not sent: `.../1/notes` sends `/notes`. `surl` does not check it either, so a file asked for as a menu comes back as a file, and a folder asked for as a file as its menu. In a `CurlResponse`, `StatusCode` is `0`, because Gopher has none, and the menu or file is the `Body` stream, read here with a `StreamReader`.

A menu is lines of tab-separated fields: type, display name, selector, host, port, ended by `\r\n`, with a final line holding a dot. Split on `"\r\n"`, not on `'\n'`. A type `1` line is a folder and a type `0` line a file, and its second field is the selector to send next: `/notes/archive`, written in full from the served root. The `walk` scenario fetches the root menu with `1`, follows the first type `1` line until a menu has none, then fetches the first type `0` line it finds. It needs no path building of its own. A trailing slash changes nothing: the answers for `notes/` and `notes` are equal.

Nothing throws when a selector names nothing. Whether it is a missing file or a missing folder, the body is the fixed error menu, one type `3` line, `Nothing is served at this selector.`, which does not repeat the selector, and the response is otherwise as good as any other. Check the first character of each line you act on. With `ListDirectories` off, the root and the folders answer that same error menu, so a walk cannot start, while a file whose selector is already known is still served.
