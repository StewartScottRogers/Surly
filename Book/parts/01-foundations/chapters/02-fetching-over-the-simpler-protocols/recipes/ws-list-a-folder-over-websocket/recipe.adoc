=== Listing a Folder over WebSocket

==== Problem

You have a WebSocket client and a folder on the server, and you want the client to receive the folder's listing as a message, and to know what it gets when the server has not been told to list folders.

==== Discussion

A WebSocket (<<rfc6455>>) begins as an HTTP request that asks to be upgraded. `surl` answers an upgrade for a file with `101 Switching Protocols` and sends the file as one message (see <<ws-receive-a-file-as-a-message>>). `--list-directories` extends that to a folder: the upgrade is accepted and the listing is sent as one text message, one entry per line, a folder with a slash after its name. `curl` writes the message to standard output, so the listing is what the solution prints. The sub-folder `notes` is listed the same way whether or not the path ends in a slash, and a path that is a file is still sent as the file.

`--directory site` serves the folder `site`, and `-s` keeps `curl`{apos}s progress meter out of the output; `-o` writes to a named file, here the null device, when only the answer matters, and `-w "%{http_code}"` prints the HTTP status of the upgrade, `101` when it was accepted and `404` when it was refused. The listing is one text message in one frame. The server's own log says so: `surl` is run with `-v`, which logs every exchange, and `--log-file logs/surl.log`, which writes the log to that file instead of the terminal, and a second `surl` serves the `logs` folder over HTTP so a case can read the log back; reading it from the folder it is written in would add to it with every read. The line the case picks out names the path, the size of the listing, 17 bytes, and the frame count, 1.

The listing leaves out names that begin with a dot, as every `surl` file server does, and asking for such a file is a `404`.

`--list-directories` loosens `surl`: it is off by default. Without it the server refuses the upgrade itself, answering `404 Not Found` before any WebSocket exists, so no message is sent. `curl` does not treat an upgrade answered with anything but `101` as success: it exits `22`, without `-f` as well. A file on the same listener is still sent, so the option changes only what a folder does. A path that is neither a file nor a folder gets the same `404` on either listener, which is why the `404` on its own does not tell a client whether listings are off.

The recipe runs three `surl` listeners on free ports, shown in the book as 8080 to 8082: one that lists folders, one that does not, and the log reader. The cases that chain commands with `&&` or `|` need a POSIX shell (Git Bash on Windows).
