=== Holding a Telnet Session

==== Problem

You want to send lines to a line-based service from a file and read what it sends back, until the session ends, as a scripted check of a client that speaks lines over Telnet.

==== Solution

Serve Telnet with `surl`, put the lines to send in a file that ends with `quit`, and let `curl` carry the session:

Stop `surl` with kbd:[Ctrl+C].

==== Discussion

Telnet (<<rfc854>>) is a plain Transmission Control Protocol (TCP) connection that carries text both ways, with a way for each end to agree on terminal options first. `surl telnet://127.0.0.1:8080/` listens on port 8080 and, once a client has connected and the options are settled, sends a one-line banner, echoes each line it is sent, and ends the session when a line says `quit`, with `bye`. `curl` has no command for Telnet beyond the URL: it sends what it reads from standard input, and writes what the server sends to standard output. `-T session.txt` names a file for it to read in place of standard input, so the session is the file, and `-s` keeps the progress meter out of the output.

The file must end with `quit`. The server ends the session, and `curl` ends when the server does, so a file with no `quit` leaves the connection open after the last echo. `curl` then waits, and only `-m`, its time limit, stops it: it exits `28`, the timeout code, with everything echoed so far already written. A script that holds a session this way should always set `-m` as a safeguard against a missing `quit`. `quit` is matched in any case, and what follows it is never read.

The server reads the session a line at a time, and a line has a limit: `--max-line` is the longest line it accepts, 8,192 bytes unless changed. Past it the server answers `line too long` and ends the session, and `curl` exits `0`, because the connection closed normally; the missing `bye` is how the script tells. A second `surl` here is started with `--max-line 10` to show it.

Before the first line, client and server negotiate options. `curl -t TTYPE=vt100` sets the terminal type `curl` will report and `-t NEW_ENV=USER=ann` an environment variable, and the server notes what it was told. That is not in the output, which is only the echo, but with `-v` and `--log-file surl.log` it is in the server{apos}s log, so a test of a client that is supposed to announce its terminal can read the log back and check that it did (<<surl-readme>>).
