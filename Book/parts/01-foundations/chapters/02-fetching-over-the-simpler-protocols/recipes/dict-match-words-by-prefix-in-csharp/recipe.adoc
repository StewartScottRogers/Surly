==== Discussion

`SurlServer` is the server in this process and `SurlServerOptions` is its command line as properties. `ListenUrls` holds `dict://127.0.0.1:0`, port `0` taking a free one, and `server.BoundUrl` has the port it took. `Files` holds content in memory: each key is a headword and its bytes the definition, in one database named `surl`.

`CurlClient` sends a `CurlRequest`, and a DICT URL is an ordinary `GET`: the path says what to ask, and the `Body` of the `CurlResponse` is the server{apos}s whole reply, status lines included, which DICT ends in CR LF and the program prints as plain new lines. The path is `m:`, the word to match, then the database and the strategy, separated by colons, `*` meaning every database. With `prefix` the server lists every headword that starts with the word: `ap` gives `apple` and `apricot` under `152 2 matches found`, one line each with the database, and not `banana`. Leaving the strategy out gives `prefix`. The program reads the first word off the list and asks `d:apple`, which is answered `150` and `151` naming the word and its database, the definition, and a dot line.

A miss is not an error to the library. `exact` matches whole words only, so `m:ap:*:exact` is answered `552 no match`; a strategy the server does not offer, `suffix` for instance, is answered `551 invalid strategy`; and `m:AP` finds nothing, since words are matched as written. Each is a normal response, so `SendAsync` throws nothing and the program has to read the status line, as the `nothing to pick` branch does. `show:strat` is how a client learns what it may ask: the server offers `exact` and `prefix`.
