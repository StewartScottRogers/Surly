==== Discussion

Gopher is older than the web and simpler: the client opens a Transmission Control Protocol connection, sends one line, the _selector_, and the server sends back either a file or a _menu_ and closes. A menu is one line per item, its fields separated by tabs: a one-character item type followed by the name to show, then the item's selector, host and port, so a client can fetch any item by connecting where the line says and sending its selector. The last line holds a dot. What `curl` printed for this recipe's directory reads, with the tabs shown as spaces and the port your run used:

[source,text]
----
0hello.txt    /hello.txt    127.0.0.1    8080
1notes        /notes        127.0.0.1    8080
.
----

Type `0` is a file and type `1` is another menu. `surl` reads the selector as a path into the served directory: `--directory site` makes the empty selector mean `site` itself, `/hello.txt` the file `site/hello.txt`, and `/notes` the folder `site/notes`.

A folder is answered with a menu only because of `--list-directories`. It is off by default, as is every option that widens what a peer may do (<<surl-readme>>): a menu names every file in the folder, and a server that lists nothing gives away only the selectors a peer already knows. With it on, a file whose name begins with a dot is still left out of the menu and still not served.

In a Gopher Uniform Resource Locator (URL), the character after the host's slash is the item type the client expects, and `curl` does not send it: `gopher://127.0.0.1:8080/0/hello.txt` sends the selector `/hello.txt` and prints the file byte for byte, and `gopher://127.0.0.1:8080/1/notes` fetches the `notes` menu, whose lines carry their full selectors, `/notes/today.txt`. The URL with no path sends the empty selector, which is why the Solution needs no type.

Gopher has no status code. A selector that names nothing, a dot file, and anything else `surl` will not serve are all answered with the same fixed error menu, a single type `3` line that does not repeat the selector back, so a peer learns nothing from the refusal. To `curl` that is a successful transfer, and it exits `0`: read the first character of the answer, not the exit code, to know whether you got what you asked for. `-s` keeps `curl` from printing its progress meter.
