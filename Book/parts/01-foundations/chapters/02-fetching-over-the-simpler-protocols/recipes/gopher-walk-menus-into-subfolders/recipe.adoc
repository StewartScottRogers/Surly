==== Discussion

`--directory site` serves the folder `site` as the root of the menu tree, and `-s` keeps `curl` from printing its progress meter, so only the answer reaches the script. A Gopher server answers one line, the _selector_, with either a file or a _menu_. Each menu line is tab-separated: an item type, the name to show, the selector to send to fetch the item, a host and a port. Type `0` is a file and type `1` is another menu. The selector on a line is all a client needs to go one level down, and `surl` writes it in full, from the served root: the entry for the archive folder in the `notes` menu reads `/notes/archive`, not `archive`. So a client never builds a path itself. The script cuts the second tab-separated field out of the line with `awk`, sends it, and reads the next menu. The first `curl` call asks for `/1`, which sends an empty selector, and `surl` answers with the menu of the served directory.

`curl` writes the selector it sends from the part of the Uniform Resource Locator (URL) after the item type: `gopher://127.0.0.1:8080/1/notes` sends `/notes`. The type is not sent. `surl` does not check it either, so a file asked for as a menu still comes back as a file, and a folder asked for as a file comes back as its menu. The type in a URL is a hint for a client that must decide how to show the answer; for a script, the type at the start of each menu line is what to read. A trailing slash makes no difference: `/1/notes/` is the same menu as `/1/notes`.

A selector that names nothing is not a failure to Gopher, which has no status codes. Whether it is a missing file or a missing folder, `surl` answers a single type `3` line, `Nothing is served at this selector.`, which does not repeat the selector back, and `curl` exits `0`. A script that walks menus must check the first character of each line it takes, as the script above does by asking for a type `1` or a type `0`. Reading the exit code would never show the miss.

Folders appear in a menu only because of `--list-directories`, which is off by default like every option that widens what a peer may see (<<surl-readme>>). Without it, the root and every folder answer the error menu, so a walk finds nothing to start from. A file is still served to a client that already knows its selector, as the last two cases show: the option governs listing, not serving.
