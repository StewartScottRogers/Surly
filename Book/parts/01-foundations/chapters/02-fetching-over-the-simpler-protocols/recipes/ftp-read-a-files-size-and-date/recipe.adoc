=== Reading an FTP File's Size and Date

==== Problem

Before downloading a file over File Transfer Protocol (FTP) you want to know how big it is and when it was last changed, so you can decide whether to fetch it, and you want the copy you do fetch to carry the server's date.

==== Discussion

FTP (<<rfc959>>) has no headers, so `curl -I` builds them from two commands. `SIZE` asks for the length in bytes, and `surl` answers `213` and the number; `MDTM` asks for the modification time, and `surl` answers `213` and 14 digits, year, month, day, hour, minute and second in Coordinated Universal Time. `curl` turns them into `Content-Length` and `Last-Modified`, the date written as HTTP writes it. Both commands are sent before any transfer would start, and no data connection is set up at all: the file is not downloaded, `-I` is the option that asks for headers only. `--directory site` serves the files under `site` at their relative paths. `-v` shows the commands, `-s` keeps the progress meter away, and `-o` sends a body to a named file.

`setup:` gives `site/hello.txt` a time in the past with `touch -t`, 2 January 2024, so the date is not the moment the example ran. `touch -t` reads local time, which is why the claim allows the day to land on the 1st, 2nd or 3rd.

`-R` (`--remote-time`) is the other half. `curl` asks for the time before it downloads and, when the transfer is done, gives the local file that time. The script downloads the file with `curl -s`, once with `-R` and once without, and asks whether the copy is older than `marker.txt`, a file written at the start: with `-R` it is, with the server's 2024 time, and without it the copy is dated when it was written and is not. That is how a sync tool tells a changed file from an unchanged one: compare the server's time and size with the local copy{apos}s.

A file that is not there is answered `550` to `SIZE`, and `curl -I` exits `78`, remote file not found, printing nothing (<<curl-readme>>).

`--allow-anonymous` lets `curl`{apos}s anonymous login in. It accepts every login, checking nothing, which is fine for a test on your own machine and nowhere a stranger can connect; `surl` warns on start while it is on. A second `surl` started without it refuses the login before any command, and `curl` exits `67`, login denied (<<surl-readme>>).
