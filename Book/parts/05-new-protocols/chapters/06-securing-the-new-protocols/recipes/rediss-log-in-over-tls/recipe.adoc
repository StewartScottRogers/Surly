=== Logging In to Redis over TLS

==== Problem

Your cache client authenticates, and the password must not cross the network in clear. You want the login refused over plain Redis, accepted over Transport Layer Security (TLS), and a wrong password told apart from no password at all.

==== Solution

Serve the cache with a certificate and give it an account with `--user`; `curl` logs in with `-u` and trusts the certificate with `--cacert`. The `openssl` line makes the certificate and key. The `curl` command sets a key and reads it back in one run:

==== Discussion

A Redis client logs in with its first command, `HELLO`, which carries a user name and a password (<<redis-resp>>). On plain `redis://` that password crosses the network readable, so `surl` does not take it: the right password over `redis://` is answered `WRONGPASS`, as if it were wrong. The password is not checked at all. `--allow-plaintext-auth` would take it, and this recipe shows the option working on a third server so that the default can be seen as a choice; it loosens security (<<surl-readme>>).

`rediss://` wraps the same conversation in TLS, which is already negotiated when `HELLO` is sent (<<rfc8446>>). Nothing is loosened: `--user alice:s3cret` is the account, `--cert server.pem` the certificate and `--key server.key` its private key. On the `curl` side, `-u alice:s3cret` is the login and `--cacert server.pem` the certificate to trust; the path of a Redis URL is the command, so `SET/greeting/hello` and `GET/greeting` are two commands, and giving two URLs runs them in order in one process. `-s` hides the progress meter while `-S` still prints an error (<<curl-readme>>). Without `--cacert`, `curl` does not trust a certificate that signed itself, never sends the login and exits `60`.

The refusals are told apart by Redis's own error text, which `curl` prints after `Redis server answered HELLO with error:`. A wrong password and a user name `surl` has no account for are both `WRONGPASS`, the same answer for both, so a client cannot learn which user names exist. A connection that sends no login is `NOAUTH`, the answer a client gets when it did not try to log in. `curl` exits `67` for each, so the exit code alone does not tell them apart and the first word of the message does.
