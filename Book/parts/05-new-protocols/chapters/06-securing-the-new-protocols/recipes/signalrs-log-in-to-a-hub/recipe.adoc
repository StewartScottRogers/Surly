=== Logging In to a SignalR Hub

==== Problem

Your SignalR client logs in to its hub. You want the negotiate refused without a login, and accepted with one over Transport Layer Security (TLS), where the password is not readable on the network.

==== Solution

Serve the hub with a certificate and give it an account with `--user`; `curl` logs in with `-u` and trusts the certificate with `--cacert`. The `openssl` line makes the certificate and key. The `curl` command calls the hub's `Echo` method:

==== Discussion

A SignalR client opens with an HTTP request, `negotiate`, and only then moves to a WebSocket, so the login is judged on that first request, as an HTTP login: `-u alice:s3cret` is the user name and password for it (<<rfc7617>>, <<signalr-hub-protocol>>). `signalrs://` is the same hub inside TLS, negotiated before that request is sent (<<rfc8446>>). Nothing is loosened: `--user alice:s3cret` is the account, `--cert server.pem` the certificate and `--key server.key` its private key. On the `curl` side, `--cacert server.pem` is the certificate to trust, `-d` is the one message sent after the handshake, here an invocation of `Echo` (type 1) whose result `curl` writes alone, and `-s` hides the progress meter while `-S` still prints an error (<<curl-readme>>). Without `--cacert`, `curl` does not trust a certificate that signed itself, never sends the login and exits `60`.

A hub with an account and no `--allow-anonymous` refuses every negotiate that does not carry the right login. Over TLS a wrong password, a user name `surl` has no account for and no login at all are all HTTP `401`, and `curl` exits `22` with `The negotiate request failed with HTTP status 401.` The status does not say which of the three it was.

Plain `signalr://` answers differently. The password would cross the network readable, so `surl` refuses to check it: the right password is answered `403`, forbidden, rather than `401`, unauthorized. A client with no login at all is still `401` over plain. `--allow-plaintext-auth` would take the password and loosens security (<<surl-readme>>); this recipe shows it working on a third server so that the default can be seen as a choice.
