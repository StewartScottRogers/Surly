=== STOMP Logins over TLS in C#

==== Problem

Your Simple Text Oriented Messaging Protocol (STOMP) client logs in with a user name and password, and the password must not cross the network in clear. You want the login refused over plain STOMP, accepted over Transport Layer Security (TLS), and a wrong password told from no password at all, from a C# test with `Surl.Api` and `Curl.Api`.

==== Solution

The program hosts the broker in-process, sends a message as a client and asks the broker what its queue holds. The arguments after `--` pick the scenario: the scheme, the user name and the password, then optional words. The certificate and key come from the `openssl` line, run first:

==== Discussion

`SurlServerOptions` takes the same choices as the `surl` command line: `Accounts` holds one `SurlAccount` for `--user alice:s3cret`, `CertificateFile` and `KeyFile` are `--cert` and `--key`, `Queues` names a queue that exists from the start, and `AllowPlaintextAuthentication` is `--allow-plaintext-auth`, which loosens security and is set in only one case (<<surl-readme>>). Port 0 takes a free port, and `BoundUrl` is the real address.

The client is a `CurlClient` made from `CurlClientOptions`, whose `Tls` is a `CurlTlsOptions`; a `CurlRequest` goes in. A `POST` with a `CurlContent` `Body` sends a message to the destination in the URL path, `queue/jobs`; `CurlAuthenticationOptions` carries the login, as `-u` does, and `CertificateAuthorityFile` in `CurlTlsPeerOptions` is `--cacert`, the certificate to trust (<<curl-readme>>). A send is not acknowledged, so the call can return before the broker has applied it: the program waits, for at most ten seconds, for the end of the client's exchange with `WaitForEventAsync` and a `SurlEventQuery`, and then `Messages.BrowseQueueAsync` reads the queue as a `SurlQueuePage` without taking anything. The right password over `stomps` leaves one message, `hello`.

A refused login is not a response but an exception: `SendAsync` throws `CurlException` with code `67` and `STOMP server sent ERROR: Authentication failed` in its message (<<stomp12>>). A wrong password, a user name with no account and no login at all are the same refusal, so the message gives a client nothing to learn from. Plain `stomp` refuses the right password in the same words, because the server does not check a password that crosses the network readable; setting `AllowPlaintextAuthentication` makes the same login send the message. Without a certificate authority file, the client does not trust the self-signed certificate and the exception is code `60`, `PeerFailedVerification`, before any login is sent (<<rfc8446>>).
