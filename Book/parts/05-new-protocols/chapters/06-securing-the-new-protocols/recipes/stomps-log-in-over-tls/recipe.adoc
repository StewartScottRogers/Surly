[[stomps-log-in-over-tls]]
=== Logging In to STOMP over TLS

==== Problem

Your Simple Text Oriented Messaging Protocol (STOMP) client logs in with a user name and password, and the password must not cross the network in clear. You want the login refused over plain STOMP, accepted over Transport Layer Security (TLS), and a wrong password told from no password at all.

==== Solution

Serve the broker with a certificate and give it an account with `--user`; `curl` logs in with `-u` and trusts the certificate with `--cacert`. The `openssl` line makes the certificate and key. The `curl` command sends a message to a queue and, after `--next`, subscribes and receives it:

==== Discussion

A STOMP client logs in in its first frame, `CONNECT`, carrying `login` and `passcode` headers, and the server answers with `CONNECTED` or an `ERROR` frame (<<stomp12>>). On plain `stomp://` that password crosses the network readable, so `surl` does not take it: the right password over `stomp://` is answered with `ERROR` and `Authentication failed`, as if it were wrong. `--allow-plaintext-auth` would take it, and this recipe shows the option working on a third server so that the default can be seen as a choice; it loosens security (<<surl-readme>>).

`stomps://` wraps the same conversation in TLS from the first byte, which is already negotiated when `CONNECT` is sent (<<rfc8446>>). Nothing is loosened: `--user alice:s3cret` is the account, `--cert server.pem` the certificate and `--key server.key` its private key. On the `curl` side, `-u alice:s3cret` is the login and `--cacert server.pem` the certificate to trust; `-d hello` sends a message to the destination in the path, `/queue/jobs`, and with no `-d` the same URL subscribes and writes each message body it receives. `--next` starts a second transfer on the same command line, so its options are given again. A subscription has no end of its own, so `-m 3` stops it, exit `28`, with the message already written, and `-s` hides the progress meter while `-S` still prints an error (<<curl-readme>>). Without `--cacert`, `curl` does not trust a certificate that signed itself, never sends the login and exits `60`.

Every refusal is the same: `curl` exits `67`, writes nothing and prints `STOMP server sent ERROR: Authentication failed`. A wrong password, a user name `surl` has no account for and a client with no login at all are indistinguishable, which gives a client nothing to learn from. Plain `stomp://` refuses the right password in the same words.
