=== Calling gRPC over TLS in C#

==== Problem

Your gRPC client always uses Transport Layer Security (TLS), and your C# test needs a `grpcs` server it can call with a certificate it trusts, and the failure when it does not trust it, with `Surl.Api` and `Curl.Api`.

==== Discussion

gRPC (<<grpc-http2>>) runs over version 2 of the Hypertext Transfer Protocol (HTTP/2, <<rfc9113>>), and `grpcs` is the same inside TLS (<<rfc8446>>). The `openssl req` in setup writes a self-signed certificate for `127.0.0.1` to `server.pem` and its key to `server.key`, in the folder the program runs in. `SurlServerOptions` is `surl`{apos}s command line as properties: `CertificateFile` and `KeyFile` are `--cert` and `--key`, `Accounts` holds the `SurlAccount` that `--user alice:s3cret` would make, and port 0 in the listen URL takes a free port. Without a certificate there is no `grpcs`: `SurlServer.StartAsync` throws `SurlServerStartException` with `ExitCode` `CertificateProblem`, the `58` `surl` would exit with.

The client is a `CurlClient` made with `CurlClientOptions`. Its `Tls` is a `CurlTlsOptions`, and `Origin` a `CurlTlsPeerOptions` whose `CertificateAuthorityFile` is `server.pem`: the client trusts the certificate as its own authority, as `curl --cacert` does. The `CurlRequest` carries `CurlAuthenticationOptions` with the user name and password, as `curl -u`, and over TLS the server checks them. `SendAsync` returns a `CurlResponse` whose `Body` is the reply as JavaScript Object Notation (JSON).

Without `CertificateAuthorityFile` the client cannot verify the certificate, and `SendAsync` throws `CurlException` with `Code` `PeerFailedVerification`, `curl`{apos}s exit code `60`. The same happens when the URL names `localhost`: the certificate names only `127.0.0.1`, and trust does not cover a name it lacks. The exception{apos}s `Message` is the TLS library{apos}s wording, so a test should check `Code`.

A wrong password is refused with `grpc-status 16 (UNAUTHENTICATED)`, thrown as `HttpReturnedError` (`22`). The same login to a plain `grpc` listener is refused without being checked, `grpc-status 7 (PERMISSION_DENIED)`, because the password would travel in clear; that is why the client stays on TLS. The message says the server did not answer reflection because `Curl.Api`, like `curl`, first asks the server for the method{apos}s types, and that is the request refused.

The request message is the `POST`{apos}s `Body`, as JSON: `Curl.Api` sends `{"message":"hello"}` as the request message, and `Echo` answers it back, which the program prints on one line with `JsonNode`. A `GET` has no body and sends the empty message, and the reply is `{}`. The same call from the framework{apos}s `HttpClient` is in <<grpc-test-a-failing-call-in-csharp>>, and with `curl -d` on the console in <<grpcs-call-over-tls>>.
