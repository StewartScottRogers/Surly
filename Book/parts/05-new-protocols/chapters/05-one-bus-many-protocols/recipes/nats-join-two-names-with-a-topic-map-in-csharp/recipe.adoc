=== Mapping Topics between Protocols in C#

==== Problem

Two teams named the same stream differently: the orders service publishes on the NATS subject `orders.created`, and the shop reads the Message Queuing Telemetry Transport (MQTT) topic `shop/orders/new`. You want a C# test, with `Surl.Api` and `Curl.Api`, to host a server whose topic map makes one name mean the other, both ways.

==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties (<<surl-readme>>). `ListenUrls` holds a `nats://` and an `mqtt://` URL on port 0, so the system picks two free ports, and `server.BoundUrls` gives them back in that order. One server is one message bus for both protocols. `AllowAnonymous` is `--allow-anonymous`, clients with no login, and `Topics` is `--topic`: `#;retain` keeps the last message on every topic for a later subscriber. `TopicMaps` is `--topic-map`: `nats:orders.created=mqtt:shop/orders/new` says that the NATS name on the left means the topic the MQTT name on the right has, each written as a scheme, a colon and a name in that scheme{apos}s own spelling.

Each team{apos}s client is a `CurlClient`. A publish is a `CurlRequest` with `HttpMethod.Post`, the subject or topic as the URL{apos}s path (<<nats-protocol>>, <<mqtt311>>), and the payload as its body, `CurlContent.FromBytes`. An MQTT subscribe is a `HttpMethod.Get`: the `CurlResponse` body is the retained message as the topic{apos}s length in two bytes, the topic and the payload, and the server then ends the session, so the program reads the body to its end and skips the topic. The NATS publish of `paid` to `orders.created` comes back from `shop/orders/new`.

The other way needs a NATS subscriber in place before the publish, since NATS keeps nothing for a late one. The program starts a `GET` of `orders.created?count=1`, which ends after one message, without awaiting it, then publishes `shipped` over MQTT to `shop/orders/new` every 200 milliseconds until the subscriber has its message, for at most ten seconds. The subscriber{apos}s body is the payload and a newline, as `curl` writes it.

With no map, `surl` turns a NATS subject into an MQTT topic by swapping dots for slashes, so the same publish lands on `orders/created`, and `shop/orders/new` answers an empty body: nothing kept. A map joins names, not filters: `nats:orders.*` is refused, and `StartAsync` throws `SurlServerStartException`, whose `ExitCode` is `surl`{apos}s `2` and whose first line is `surl`{apos}s message, `not a valid name for nats`. Without `AllowAnonymous` the NATS publish with no login is refused, `-ERR 'Authorization Violation'`, and `SendAsync` throws `CurlException` with code `67`: `surl` asks for a login by default.
