=== From Kafka to MQTT from an Agent

==== Problem

A Kafka producer and an MQTT 5 subscriber must agree on one topic named two ways. You want an agent to check that a Kafka record on `shop.orders` is delivered to the MQTT subscriber of `shop/orders`.

==== Solution

The program starts both hosts and a server with Kafka and MQTT 5 on one bus, produces a record with the `curl` tool, subscribes with it over MQTT, and reads the store with `read_retained_message` and `read_log`:

==== Discussion

`start_server` takes the listen URLs, here `kafka` and `mqtt5` on free ports, which one server puts on one message bus, and in `arguments` `surl`{apos}s own options (<<surl-readme>>). MQTT 5 is version 5.0 of the publish and subscribe protocol MQTT. `--topic "shop/#;retain"` keeps the last message on every topic under `shop/`, so a subscriber that comes after the record can be sent it; `--mqtt5-disconnect-after-retained` ends an MQTT 5 subscribe once the kept messages are sent, so the subscriber{apos}s `curl` ends; `--allow-anonymous` lets both clients in with no login, a loosening for a test on your own machine. It answers a `server_id` and the `bound_urls`.

The `curl` tool runs `curl`{apos}s own arguments and answers `exitCode`, `standardOutput` and `standardError` as JavaScript Object Notation (JSON). Kafka names a topic with dots and MQTT with slashes, so the Kafka topic `shop.orders` is the MQTT topic `shop/orders`. `-d "order-1001 placed"` to `kafka://.../shop.orders` produces one record (<<kafka-protocol>>), exit `0`; a `curl` with no `-d` to `mqtt5://.../shop/orders` subscribes and is sent the kept record, the payload alone (<<mqtt5>>, <<curl-protocols>>). `-s` keeps the progress meter out, `-S` keeps an error in, and `-m 10` is a ceiling on each call.

The store tools read the bus without a client, and they name topics the MQTT way. `read_retained_message` of `shop/orders` answers the kept message as `text`, and `read_log` of `shop/orders` answers the topic{apos}s Kafka log, its `records` each with an `offset`, here `0`, and `text`. `read_log` of `shop.orders`, the Kafka spelling, is a tool error, `No log for topic shop.orders.`: nothing was written under that name. An agent that reads the log behind a Kafka topic with a dot in it passes the slashed name.

The bus works the other way round too. `publish_message` with `topic` `shop/orders`, the test{apos}s own publish, appends a record that a Kafka consumer of `shop.orders`, a `curl` with no `-d`, reads as a line.

Without `--allow-anonymous` a producer with no login is disconnected: `curl` exits `56`, `Connection disconnected`.
