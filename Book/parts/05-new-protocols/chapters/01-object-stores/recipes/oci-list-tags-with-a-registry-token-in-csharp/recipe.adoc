=== Listing Registry Tags in C#

==== Problem

Your deploy tool lists a container repository{apos}s tags, which needs a Bearer token from the registry{apos}s token endpoint, and you want a C# test with `Surl.Api` and `Curl.Api` to fetch the token with a Basic login, read the tag list with it, and see the `401` without it.

==== Solution

==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties (<<surl-readme>>). `ListenUrls` holds `oci://127.0.0.1:0`, a registry on a free port that speaks the OCI Distribution Specification over Hypertext Transfer Protocol (HTTP) (<<oci-distribution>>). The listener is Transport Layer Security (TLS) from the first byte (<<rfc8446>>), and `SelfSigned` makes the server generate a certificate, `SelfSignedCertificatePem`, which the client trusts through `CurlTlsOptions` and `CurlTlsPeerOptions` with `CertificateAuthorityBlob`. `Accounts` holds Alice{apos}s `SurlAccount`. `Files` seeds the in-memory store before the start: the repository `demo/app` is a folder in OCI image layout, whose `index.json` lists one manifest under the tags `latest`, `1.0` and `1.1` (<<oci-image-spec>>). The client reaches the registry at `https://` and the port of `BoundUrl`, since the token and the tag list are two separate HTTP requests.

Each `CurlRequest` is a `HttpMethod.Get` from one `CurlClient`, and `CurlAuthenticationOptions` says how it logs in. Without it, the tag list is a `CurlResponse` whose `StatusCode` is `401`, and its `WWW-Authenticate` header says where to get a token: `Bearer realm="https://127.0.0.1:PORT/token",service="surl",scope="repository:demo/app:pull"` (<<rfc6750>>). The password itself is no use there: with `UserName`, `Password` and `HttpAuthenticationMethods.Basic`, the tag list is `401` too. The token endpoint is the one place that takes it. A Basic login (<<rfc7617>>) at `/token?service=surl&scope=repository:demo/app:pull` is answered `200` with JavaScript Object Notation (JSON) holding the `token` and `expires_in`, `300` seconds; a wrong password is `401` and no token.

With the token in `XOAuth2Bearer` and `HttpAuthenticationMethods.Bearer`, `Curl.Api` sends `Authorization: Bearer` and the tag list is `200`, `{"name":"demo/app","tags":[...]}`, in lexical order whatever the order of `index.json`. A token is good only for the scope it was issued for: one scoped to `repository:other/app:pull` is refused for `demo/app`{apos}s tags, `403 DENIED`. Refusals here are responses, not exceptions, since the requests are plain HTTP. A long list comes in pages: with `n=2` the registry gives two tags and a `Link` header whose `rel="next"` URL, `last=1.1`, asks for the page after; that page holds `latest` and no `Link` header, so the test stops.
