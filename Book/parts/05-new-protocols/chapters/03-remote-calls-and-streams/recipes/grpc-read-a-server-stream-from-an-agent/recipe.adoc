=== Reading gRPC Streams from an Agent

==== Problem

==== Discussion

`start_server` starts a server and answers its `bound_urls`; `listen_urls` of `grpc://127.0.0.1:0` takes a free port and `arguments` of `--allow-anonymous` lets a call with no credentials in. The built-in `surl.test.Echo` service has the method `Expand`, which answers `count` replies, each with the request{apos}s `message` and its own `index`.

The `curl` tool runs `curl`{apos}s own arguments and answers JSON: `exitCode`, and the replies in `standardOutput`, the error text in `standardError`. `-s` keeps `curl` quiet and `-S` still shows an error. The request is JSON given with `-d` and the types come from the server{apos}s reflection. The replies are JSON objects in the order sent; the first has no `index` because its value is `0`. A stream with no replies, `count` `0` or none, is exit code `0` with empty output, so an agent should not read empty output as a failure.

A `count` above 1000 is refused `INVALID_ARGUMENT`, `request field out of range`, and the answer is a tool error with exit code `22`, as every status other than `OK` is. A stream that ends in a failure keeps what arrived first: `count` 3 with `statusCode` 13, `INTERNAL`, answers the three replies in the output and `grpc-status 13 (INTERNAL): boom` in the error, exit code `22`, so an agent reads both.

Replies are in the output as they arrive. With `delayMilliseconds` holding each of ten back 300 milliseconds, `-m 1` stops the call after a second: the tool answers exit code `28`, timed out, with some of the replies in the output and not all ten. `curl` also sends `-m` to the server as the `grpc-timeout` header, which would end the call at the same moment, so `-H` `grpc-timeout:`, with nothing after the colon, leaves it off (<<grpc-time-out-a-slow-call-from-an-agent>>).
