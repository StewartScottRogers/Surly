=== Sending to a Queue over STOMP

==== Problem

A test needs a local STOMP broker with a queue to send a message to and take it back from, with `curl` and nothing else installed.

==== Solution

Start `surl` on a `stomp` listen URL that accepts anonymous clients and ends a connection idle for a second, send to `/queue/orders` with `curl -d`, and subscribe to the same destination with a plain `curl` of its URL:

==== Discussion

STOMP, the Simple Text Oriented Messaging Protocol, is a text protocol for message brokers: a client sends a `CONNECT` frame, then `SEND` frames to a destination, or a `SUBSCRIBE` frame, after which the broker sends it a `MESSAGE` frame for each message (<<stomp12>>). STOMP 1.2 leaves what a destination means to the broker. `surl` on a `stomp` listen URL is a STOMP broker, an extended server of `surl`{apos}s that upstream curl has no client for; the Curl port has one (<<curl-protocols>>). In the URL `curl` takes, the path is the destination, kept whole. With `-d paid`, `curl` sends `paid` to it and exits; without `-d`, it subscribes and writes the body of each message, with nothing between one body and the next, until the broker closes the connection (<<curl-readme>>). `--next` lets one `curl` command send and then subscribe, with the options of the first transfer reset for the second.

`surl` gives a destination its meaning by its prefix (<<surl-readme>>). `/queue/orders` is the queue `orders`: it is made by the first send that names it, it keeps every message nobody has taken yet, and each message goes to one subscriber only. So the Solution can send first and subscribe second: the message waits in the queue. A second subscriber then finds the queue empty, and two messages sent one after the other come back in the order sent, `firstsecond`. `/topic/news` is a topic instead: a message goes to the subscribers that exist when it is sent, and a subscriber after it receives nothing. Any other destination, such as `/orders`, is answered with an `ERROR` frame, `Unknown destination`, and `curl` exits `8`, a reply it could not use. A URL with no destination at all is refused by `curl` itself, exit `3`, before it connects.

A subscription from `curl` ends only when the broker closes the connection, and a queue's broker has no reason to: more messages may come. `--idle-timeout 1` gives it one. It makes `surl` close a connection on which no byte has moved for a second, so once the queue is empty the subscription ends and `curl` exits `0` with what it wrote. On a `surl` with the default idle timeout of 120 seconds, the subscriber writes the message and waits, and `-m 2`, `curl`{apos}s limit on the whole transfer, ends it with exit `28`, a timeout, the message still written. Against a broker you do not control, use `-m`.

`surl` shares one message bus among its messaging servers, and a queue is the bus's (<<surl-readme>>). On a `surl` that also serves AMQP 1.0, the address `orders` is the same queue: what STOMP sends to `/queue/orders`, an AMQP 1.0 receiver of `amqp1://127.0.0.1:8083/orders` takes, and what AMQP 1.0 sends there, a STOMP subscriber takes (<<amqp10>>).

`--allow-anonymous` is in the Solution because every STOMP `CONNECT` needs a login, and `curl` sends none unless given `-u`, which it sends as `login` and `passcode`. Without it, `surl` answers an `ERROR` frame, `Authentication failed`, and closes, and `curl` exits `67`, login denied. A broker that takes anonymous clients lets anyone who can reach it read and write every queue, so it is not the default, and `surl` warns on start while it is on. The way in without it is an account, `--user alice:s3cret`, and `curl -u alice:s3cret`. But `stomp://` has no encryption, so `surl` refuses that password unchecked, the right one included, with the same `ERROR`. `--allow-plaintext-auth` loosens that for a test: the password is then checked, the right one is accepted and a wrong one refused, `67`. It warns on start too. The secure way is `stomps://`, the same broker over Transport Layer Security (TLS) from the first byte, which needs a certificate (<<surl-readme>>).

In the checked claims, `-s` silences `curl`{apos}s progress meter and error messages, and `-S` puts the error message back, so the `ERROR` frame's message shows on standard error.
