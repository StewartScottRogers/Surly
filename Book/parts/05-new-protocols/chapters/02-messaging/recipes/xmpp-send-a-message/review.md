# Review: xmpp-send-a-message
Verdict: accept with fixes
Checked against local builds on 2026-11-19 (not releases): surl 1.0.0 (Surl commit 71807f05f), Curl port 8.22.0 (Curl commit 82913be53d): 11 of 11 cases pass on windows (six runs, five of them side by side with the two other recipes).
## Findings
1. Fitness (1), for the author: the Solution sends to alice's own bare JID. surl stores no messages (ADR-0114 decision 5), and the Curl port's XMPP client holds a stream only while it sends and never receives, so with `curl` alone the only recipient that is online is the sender's own stream; a message to bob is `service-unavailable` (case `nobody-online`). The Discussion says so and points a reader to a chat client for bob. A delivery to another person cannot be a case with these two programs.
2. Program findings, left out of the recipe and reported to the lead: (a) `--allow-anonymous` does not make surl offer SASL `ANONYMOUS` on `xmpp` (plain, or after STARTTLS with `--self-signed`), against ADR-0114 decision 3; curl without `-u` exits 67 "does not offer SASL ANONYMOUS". Under `--allow-anonymous`, a PLAIN login as alice is logged in as `anon-<hex>@127.0.0.1`, not alice. (b) `surl --user alice:s3cret xmpp://127.0.0.1:0/` with no certificate and no loosening starts and offers an empty `<stream:features/>`, where ADR-0114 decision 2 says it fails at start with 58. The `no-login` claim is made only for this recipe's server, which has no `--allow-anonymous`.
3. Fixed: removed "sent with SASL `PLAIN` inside TLS", seen only in surl's `-v` log; SCRAM is not offered under the default `--auth`, which this recipe does not claim either.
4. Truth: TLS is shown by `untrusted-certificate` (exit 60 without `--cacert`, so curl did upgrade with STARTTLS unasked) and `xmpps`; the loosening by `clear-password-allowed`, and the client-side guard by `ssl-reqd-refuses-clear` (exit 64).
5. Bibliography, for the author: message routing to a bare JID and `service-unavailable` for an offline user are RFC 6121 section 8.5; only RFC 6120 is in the bibliography, so the Discussion cites `surl-readme` for routing. Adding `rfc6121` would let it cite the rule itself.
6. Reader: XMPP, XML, SASL, JID and TLS spelled out at first use. The generated Solution output block ends with an empty line, as for any solution that prints nothing.
