=== Expiring a Redis Key from an Agent

==== Problem

Your cache sets keys with a time to live and must treat an expired key as missing. You want an artificial intelligence (AI) agent to set a key to expire, read it before and after, and see it read back as null, with Model Context Protocol (MCP) tool calls and no shell.

==== Solution

Write the agent{apos}s side as a C# program on the official MCP software development kit (SDK): it starts `surl-mcp` and `curl-mcp`, starts a Redis server, sets a key with `set_key` and `expire_ms`, reads it with `read_key` and the `curl` tool, waits, and reads it again:

==== Discussion

The program starts `surl-mcp`, the MCP server for `surl`, and `curl-mcp`, the one for `curl`, by name from the path, over standard input and output, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT` (<<mcp-spec>>). The argument picks the scenario. `start_server` takes `listen_urls`, here one `redis` listener on a free port, and answers the `server_id` and, in `bound_urls`, the URL it bound. `arguments` passes `surl`{apos}s own options: `--user alice:s3cret` is the account a client logs in with, and `--allow-plaintext-auth` lets that password cross a `redis://` connection, which has no encryption. That loosening is for a test on one machine; the console recipe shows the refusal without it (<<redis-expire-a-key>>).

`set_key` sets a string key as a `SET` would, with no client and no login, and `expire_ms` is its life in milliseconds, the `PX` of the console recipe. Leave it out and the key has no limit. The tool{apos}s schema bounds it: below `1` or above `31536000000`, 365 days, never reaches `surl`, and the host answers an invalid-params error that names the bound. The keys live in memory and go when the server stops (<<surl-readme>>).

`read_key` reads the key back with no client. While the key lives it answers its `text` and `expires_at`, a time; a key with no limit has no `expires_at`. After the expiry the key is gone, and `read_key` is a tool error, `No such key.`, the same as for a key never set. An agent that wants to know a key has expired reads that, and does not look for an empty value.

The `curl` tool plays the client. It takes `curl`{apos}s own arguments, and the URL path is the Redis command and its arguments: `GET/session`, `TTL/session`, `EXPIRE/session/1000` (<<curl-readme>>, <<curl-protocols>>, <<redis-resp>>). `-u alice:s3cret` logs in, and `-s` keeps the progress meter out of the answer. `curl-mcp` answers in text that is JavaScript Object Notation (JSON), with `exitCode` and `standardOutput.content`, which the program parses. While the key lives `GET` answers its value and `TTL` a positive number of seconds. After the expiry `GET` answers null, which `curl` writes as an empty line and exit `0`, so the program prints `null`, and `TTL` answers `-2`, Redis{apos}s word for no such key. A key with no limit answers `-1`, and `EXPIRE`, which takes seconds, puts one on it and answers `1`. The two views agree, one by a tool error and one by an empty line.
