==== Discussion

`surl` reads the zone from `--directory`, the master file `site/.surl/dns/example.test.zone`, named for its apex (<<surl-readme>>, <<rfc1035>>). It holds the apex{apos}s SOA and NS records and one A record, `api`, the orders service, at `127.0.0.1`; `status.txt` in the same folder is what the `http://` listener on the second port serves.

`--dns-transport tls` makes the `dns://` listener DoT alone: TLS from the first byte, then each DNS message behind a two-byte length, as over TCP (<<surl-readme>>). TLS needs a certificate, `--cert server.pem` with `--key server.key`, which `openssl` made before the server started, naming `127.0.0.1`. Without one `surl` will not start, exit `58`, and tells you to give `--cert` or `--self-signed`. Plain TCP and TLS cannot share a port, since the first bytes of a connection could be either: `--dns-transport tcp,tls` on one port is refused, exit `2`.

The script is the client. Its lookup is `curl`{apos}s `dns://` URL, the server and then the name, with `--dns-transport tls` to speak DoT and `--cacert server.pem` to trust the test server{apos}s certificate, which is its own authority, so verification stays on; `-s` keeps the progress meter out, `-S` keeps an error in, and `--max-time 10` bounds each call. The answer is dig-like text, `NOERROR` with the A record `api.example.test.`, TTL `300`, `127.0.0.1`, a tab between fields. The script takes the address from the one A line with five fields and calls the service with `--resolve`, which makes `curl` connect `api.example.test` on that port to that address while the URL keeps the name (<<curl-manual>>). The answer is the status file.

A name under the apex that the zone does not hold, `old-api.example.test`, is answered `NXDOMAIN`; the script finds no address, says so, exits `6` as `curl` does for a name it cannot resolve, and makes no call. Without `--cacert` the lookup itself fails, exit `60`: `curl` cannot verify a certificate the test made.

`curl` has a resolver of its own for DoT, `--dns-over-tls host:port`, which looks up every transfer{apos}s names on that server. With a test server it does not help yet: it checks the server{apos}s certificate against the system{apos}s trust store and not `--cacert`, so the lookup fails and `curl` exits `6`, `Could not resolve host`. Installing a test certificate in the system store is a change to the machine, not to the test, so the script does the lookup itself.
