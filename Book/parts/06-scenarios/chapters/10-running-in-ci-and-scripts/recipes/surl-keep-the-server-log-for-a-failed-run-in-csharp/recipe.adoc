=== Keeping the Server Log for Failures

==== Problem

In a C# test: when a continuous integration (CI) run fails you want the server's log and trace kept as an artifact, with no password or token in it.

==== Solution

Give the in-process server a `StringWriter` as its `Log` at `LogLevel.Verbose`, run the tests, and when one fails write the log to `ci-logs/surl.log` as it is. The server has already put `+****+` where each password and token was:

==== Discussion

`SurlServerOptions.Log` is where `surl` would write its log, a `TextWriter` here held in memory, and `LogLevel.Verbose` is `surl -v`: a line for every exchange event, and every line sent (`#3 > 530 Login incorrect`) and received (`+#3 < PASS ****+`). That is the log and the trace in one. The server serves Hypertext Transfer Protocol Secure (HTTPS) and File Transfer Protocol (FTP) over Transport Layer Security (FTPS, <<rfc4217>>) on free ports, `BoundUrls` in the same order; `SelfSigned` makes a throwaway certificate, and `CurlTlsOptions` with an `Origin` `CurlTlsPeerOptions` whose `CertificateAuthorityBlob` is that certificate trusts exactly it, so verification stays on (<<rfc8446>>). `Accounts` holds two `SurlAccount` entries: a password account and a Bearer token, the account with an empty user name (<<rfc6750>>).

The tests are three fetches through `Curl.Api`, each a `CurlRequest` on its own `CurlClient`, its login a `CurlAuthenticationOptions`: Basic with the password (`HttpAuthenticationMethods.Basic`), the token as a Bearer (`HttpAuthenticationMethods.Bearer`), and the password over FTPS, whose `CurlResponse` has no status line and so a `StatusCode` of 0. `&&` ends the run at the first failure. With the wrong FTPS password, `SendAsync` throws `CurlException` with `Code` `LoginDenied`, the 67 `curl` would exit with; the test prints it, keeps the log and exits 1.

The log is fit to keep as written, because the server withholds what clients send to log in, in the `Log` writer as on the console. The `PASS` command is logged as `+PASS ****+`, and neither the Basic password nor the Bearer token is in the log at all; that withholding happens after TLS has been taken off, which is where a password would otherwise show. The test writes the log to `ci-logs/surl.log` and nothing else. What it holds is what is worth reading after a failure: the login lines, which name the method and the account and never the secret (`Login refused: ftps app`), and every line the server sent. A passing run keeps nothing. Not every protocol is withheld yet; <<surl-keep-the-server-log-for-a-failed-run>> shows one, LDAP, and how to keep its log.
