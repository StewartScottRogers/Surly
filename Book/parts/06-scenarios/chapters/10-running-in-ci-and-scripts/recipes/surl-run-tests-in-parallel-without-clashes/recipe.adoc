=== Running Tests in Parallel Without Clashes

==== Problem

==== Discussion

Three things can clash between workers, and each worker here owns all three. The port: `http://127.0.0.1:0/` lets the system pick a free one, and the worker reads it from the `Listening on` line `surl` writes once it has bound, so four workers got four ports that nobody chose. The store: `--directory work/<n>/site` is the worker{apos}s own folder, so every worker can upload under the same name, `result.txt`, and read back only its own. The process: each worker starts its `surl`, waits for it, and stops it with `kill` and `wait` when its tests end, so no worker depends on another{apos}s server being up, and a slow worker never finds its server stopped by a fast one.

Nothing else is shared. The account is the same in every worker, `--user tester:s3cret`, but each server holds its own copy, and `--allow-uploads` lets that account store files on its own server only. Every request needs the login because an account is configured; the tests send it with `-u`, and `--digest` makes it a Digest login (<<rfc7616>>). `-T` uploads, `-f` fails on an error status, `-s` keeps `curl` quiet and `-S` still prints an error.

A worker that fails stays its own business. With a wrong password in worker 2, its upload is answered 401 and `curl -f` exits 22; workers 1 and 3 pass and stop their servers all the same. The runner waits for every worker, prints each one{apos}s output in worker order rather than finishing order, and exits with the failing worker{apos}s code, naming it.

The two shared things a suite most often slips into are both refused, so they fail at once rather than corrupt a run. `surl` locks its data directory: a second `surl` on a directory another one serves exits 124 with `Directory shared is in use by another surl process`. A fixed port another worker holds exits 45, `Could not bind`. Port 0 and a directory per worker keep either from happening.
