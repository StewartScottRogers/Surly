=== Checking What a Build Supports

==== Problem

Before a run you want an artificial intelligence (AI) agent to ask the client which protocols and features it has, and skip the tests it cannot run.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `curl-mcp`{apos}s `version` tool once, then for each test checks the scheme against the protocols and any feature it needs against the features, skipping with a reason or running the test against a server from `start_server`:

==== Discussion

`version` takes no arguments and answers what `curl -V` prints, as JavaScript Object Notation (JSON) in text: `version`, `protocols` (the schemes upstream curl has), `extendedProtocols` (the ones this curl adds), `features` such as `IPv6` (Internet Protocol version 6) and `SSL`, and the Transport Layer Security (TLS) backend. The lists can differ from one build to the next, so the agent asks the build it is about to use instead of assuming; it reads both protocol lists as one set and the features as another.

Each test names the scheme it fetches and, if it needs one, a feature. A Hypertext Transfer Protocol (HTTP) page (<<rfc9110>>), the same page from a server on the IPv6 loopback address `[::1]`, a Dictionary Server Protocol (DICT) definition (<<rfc2229>>) and a Trivial File Transfer Protocol (TFTP) block (<<rfc1350>>) all run: their schemes are in the lists, and so is `IPv6`. The fifth test streams over `rtmp`, which this curl does not have, so the agent skips it and says which need was missing. A test whose feature is not listed is skipped the same way, naming the feature. Neither kind of skip starts a server or makes a transfer.

Each test that runs gets its own server: `start_server` with the test's listen URL and its file in `files`, then `curl-mcp`{apos}s `transfer` on the URL the server bound. `statusCode` is `200` for the HTTP tests and `0` for DICT and TFTP, which have no status line; the agent checks the code, that the call was not a tool error, and that the body holds what the test expects. What `surl-mcp` recorded agrees: `list_servers` lists one server per test that ran, each with one exchange, and nothing for the skipped ones.

A skip is not a failure. When the page's server lacks its file, that test is answered `404` and reported `FAIL`, the others still run, and the program exits 1; a run whose only gaps are skips exits 0. Report skips with their reasons, so a build that has quietly lost a protocol shows up as a list of skips rather than as nothing at all.
