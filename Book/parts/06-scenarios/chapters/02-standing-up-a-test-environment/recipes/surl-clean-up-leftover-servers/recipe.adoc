=== Cleaning Up Leftover Servers

==== Problem

Your artificial intelligence (AI) agent's earlier work left test servers running, and you want it to list them, stop each one and confirm that none is left.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `list_servers`, then `stop_server` once for each server listed, then `list_servers` again. The program first starts three Hypertext Transfer Protocol (HTTP) servers with `start_server` and leaves them running, as the earlier work did:

==== Discussion

`start_server` starts a server that answers as `surl` would with the same options; here each listens on port 0 of the loopback address, so each gets a free port. Nothing stops it but the agent, which is how servers get left behind: a step fails, a context is trimmed, a plan changes, and the server keeps running.

`list_servers` takes no arguments and answers, in structured content the SDK hands over as a JavaScript Object Notation (JSON) element, a `servers` list with each server's `server_id` and `bound_urls`, the URLs it listens on with their real ports. That list is the inventory: the agent does not need to remember what it started. `stop_server` takes one `server_id`, stops that server, and answers the exit code a `surl` process would have exited with when stopped: `exit_code` 0, `exit_code_name` `Ok`. A clean-up is one `stop_server` per listed ID, then `list_servers` again to confirm the list is empty; the program prints `left running: 0`.

Two checks make the clean-up trustworthy. After it, nothing listens on a URL a leftover served: `curl-mcp`{apos}s `transfer` to one fails to connect, `curl`{apos}s exit code 7, with no status code. And stopping an ID that is already stopped is a tool error, `no running server has ID`, so an agent that runs its clean-up twice is told so rather than left guessing.

`list_servers` knows only its own host's servers. A second `surl-mcp`, started by another client, lists none of the first host's three, so an agent cannot see, let alone clean up, servers another host started. The other side of that is reassuring: servers do not outlive the host that started them. When a `surl-mcp` host ends, its servers end with it, and a fetch from one fails to connect. So the leftovers this recipe cleans up are the servers of a host still running, typically in a long agent session; ending the session ends them too.
