=== Handing Bound Ports to the App

==== Problem

Your artificial intelligence (AI) agent starts every test server on port 0 so its runs never clash, and you want it to read the ports that were bound and hand them to the app under test.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `start_server` with Hypertext Transfer Protocol (HTTP) and Simple Mail Transfer Protocol (SMTP) listen URLs on port 0, hands the URLs in `bound_urls` to the app, and checks the mailbox with `list_messages`:

==== Discussion

`start_server` takes `surl`{apos}s listen URLs in `listen_urls` and any other `surl` options in `arguments`, in `surl`{apos}s own words: `--mail-domain example.com` and `--mailbox app@example.com:secret` make one mailbox and the account that logs in to it. `files` puts `greeting.txt` in the server's in-memory store. The answer is structured content, which the SDK hands over as a JavaScript Object Notation (JSON) element. It has two lists of URLs, and only one of them is an address. `listen_urls` echoes what the agent asked for, port 0 and all; `bound_urls` holds the same URLs, in the same order, with the port each listener got and a `/` at the end. The `listen-urls` scenario hands the app the wrong list: its first request goes to port 0 and `curl` exits 7, unable to connect.

The app under test here is `curl-mcp`{apos}s `curl` tool, which runs a `curl` command line in-process and answers in text, as JSON, with its `exitCode`, its `standardOutput` and its `standardError`. Standing in for an app it is deliberately ignorant: everything it knows about the servers is in the URLs the agent builds its arguments from. It fetches the greeting with `-fsS` (fail on an HTTP error, otherwise silent but for errors), then mails it: `-u` logs in, because the server takes mail only after a login, `--mail-from` and `--mail-rcpt` are the envelope, and `-T -` uploads the message the agent passes as the tool's `stdin`. A real app would get the same URLs through its configuration or its environment.

The agent then checks what the server recorded. `list_messages` reads a mailbox from the server's side, with no login and no client, and answers each message's unique identifier (UID) and size: one message, as sent.

An agent that has lost `start_server`{apos}s answer, because its context was trimmed or a step failed, does not need to start again: `list_servers` lists every server the host started and still runs, each with its `server_id` and the same `bound_urls`.
