==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties, and its `ConfigFiles` is `surl -K`: each file is read as `surl` reads one, one option per line, its name without the dashes, then `=` and its value, quoted when it holds a space. The same file serves a developer who runs `surl -K test-env.conf` at a prompt and the tests that start the server in process, which is what keeps them the same. `directory` serves `site` over HTTP and FTP; `user` adds the `tester` account they log in as; `mail-domain` and `mailbox` make the app's mailbox for SMTP; `allow-plaintext-auth` lets the tests log in over plain `http://` and `ftp://`, a loosening that warns on every start (<<surl-run-a-fixture-from-a-config-file>>).

The listen URLs are in the code here, though they need not be. A file{apos}s `url = ...` lines are listen URLs too: with `ListenUrls` empty, `SurlServer.StartAsync` listens on those alone, as `surl -K` would. Keeping the URLs in code lets the tests choose them, and costs little, since every one asks for port 0 and `BoundUrls` names the ports bound, in the order of `ListenUrls`.

The tests are `Curl.Api` requests. `CurlClient.Create()` makes the client and `SendAsync` sends a `CurlRequest` and returns a `CurlResponse`. `CurlAuthenticationOptions` with `UserName` and `Password` are `curl -u`. HTTP and FTP both find `hello.txt`, because they serve the one directory. The mail is a `CurlRequest` to the SMTP URL with `CurlMailOptions` for the envelope, `--mail-from` and `--mail-rcpt` in `curl`{apos}s words, and the message from `CurlContent.FromStream`; its `StatusCode` is the server's reply, `250`. Then the program asks the server what it recorded: `Mail.ListMailboxesAsync` answers a `SurlMailboxInfo` per mailbox, and the `INBOX` holds one message more than before. The directory keeps mail from run to run (<<surl-readme>>), which is why the program counts the difference rather than the total.

`AdditionalArguments` are read after the config files, so they override them, as options after `-K` do on the command line: one test can change one thing and leave the shared file alone. With `--no-allow-plaintext-auth` there, the server is back to its default. The HTTP login over plain `http://` is answered `403 Forbidden`, which to `SendAsync` is a response like any other, and the FTP login is refused, which is a failure: `SendAsync` throws `CurlException` with `Code` 67, the code `curl` exits with.

A file `surl` would refuse, `StartAsync` refuses the same way, before anything listens. It throws `SurlServerStartException`, whose `ExitCode` is `surl`{apos}s exit code and whose `Lines` are `surl`{apos}s messages: `FailedInit` (2) with `broken.conf:2: option --mail-domian: is unknown` for a misspelt option, `CouldNotReadFile` (37) for a file that is not there. A test that catches it can print the line and stop; one that does not fails with it.
