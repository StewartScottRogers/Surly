=== Adding an Account per Test

==== Problem

Your C# tests share one server. You want each test to log in as an account of its own, added when the test starts and removed when it ends, so no test can use another{apos}s login, and you want to know what an account does and does not keep apart.

==== Solution

Call `server.Accounts.Add` at the start of each test and, in a `finally` block, delete the files the test made with `server.Files.DeleteAsync` and remove the account with `server.Accounts.Remove`:

==== Discussion

The server serves Hypertext Transfer Protocol (HTTP) and Internet Message Access Protocol (IMAP) on free ports, with uploads on. `SurlServerOptions.Accounts` gives it one standing account, a `SurlAccount` named `fixture`, at start. That account matters: a server with no account needs no login, so if the test accounts were the only ones, removing the last of them would open the server to anyone (<<surl-readme>>). With `fixture` there, the server needs a login however many test accounts come and go.

`server.Accounts` is a `SurlServerAccounts`, the server{apos}s accounts while it runs. `Add` takes a user name and a password and the account may log in from the next login on, on every scheme the server serves; `Remove` takes it away again, one given at start included. Each test logs in with Digest (<<rfc7616>>) through `CurlAuthenticationOptions` on its `CurlRequest`, so the password never crosses the connection in clear; the `CurlClient` is shared and each `CurlResponse` body is disposed. After the `finally` block, test-1{apos}s login is refused `401 Unauthorized`, and `FindEvents` with a `SurlEventQuery` for `StoreKind.Accounts` returns one `StoreChangedEvent` per change, `AccountAdded` and `AccountRemoved`, in order: a record of the accounts each test had, to compare against the tests that ran.

For the served files, what an account keeps apart is the login, and nothing else: they are one store for every account, and while both accounts exist, test-2 reads the file test-1 uploaded, `200 OK`. So each test removes its files in the same `finally`, with `server.Files`, a `SurlServerFiles` that deletes without a client and without a login, and tests that must not see each other{apos}s files run in turn, not at once. Mail is different: `Add` gives the account mailboxes, so over IMAP (<<rfc9051>>) it logs in, lists them and reads its `INBOX`. After `Remove`, a new IMAP login is refused, `CurlException` `LoginDenied`, `Login denied`, but a connection already logged in as the account keeps its login until it ends, and a `CurlClient` keeps its connection open between requests. A test that must prove the account is gone asks on a new client, as the program does.

The `finally` is not decoration. An account a test fails to remove is still there when the next test starts, and adding the same name again throws `ArgumentException`, `User test-1 already has an account.`: the next test fails for a reason that has nothing to do with it. Removing in `finally` keeps the account to the test{apos}s lifetime even when the test throws.
