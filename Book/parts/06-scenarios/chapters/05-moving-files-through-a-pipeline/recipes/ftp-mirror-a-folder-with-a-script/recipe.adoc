=== Mirroring a Folder over FTP

==== Problem

You want a script to upload a nested folder over File Transfer Protocol (FTP), creating folders on the server as it goes, then list the server to prove the whole tree arrived.

==== Discussion

`surl` serves `site` (`--directory`) and takes uploads into it with `--allow-uploads`, which it refuses by default: a server that anyone can write to is a decision, not a default. `--allow-anonymous` lets `curl` log in without an account, and `--list-directories` lets a client list a folder, which `surl` also refuses unless asked.

The script walks the local tree with `find`, sorted so the order is the same everywhere, and builds one `curl` command line: a `-T` and a URL for each file, the file{apos}s path under the folder URL. One command is one process, however many files there are. `--ftp-create-dirs` makes each folder the server lacks before the upload into it: `curl` tries to change into it, and makes it only when the server says there is no such folder. `-w "put %{url.path} %{exitcode}\n"` prints a line after each transfer with its path on the server and its own exit code; `-s` hides the progress meter and `-S` still prints errors.

The listing is the proof. For each local folder the script asks the server for its names with `-l`, names only (<<rfc959>>), strips the carriage returns FTP ends lines with, and prints them sorted on one line. The four files and three folders are all there, and `cmp` finds the files byte for byte the local ones. Running the script again puts each file over its old copy and prints the same.

Without `--ftp-create-dirs`, an upload into a folder the server does not have is refused, exit `9`: FTP makes no folder unless asked.

`--fail-early` is what makes the script stop on the first failure. Against a server without `--allow-uploads`, making `/mirror` is refused, the first put ends with `9`, and `curl` stops there; `|| exit` passes the `9` on and the script lists nothing. Without `--fail-early`, `curl` tries every put that follows, each failing the same way, and exits with the last one{apos}s code, so a failure in the middle can be hidden by the puts after it.
