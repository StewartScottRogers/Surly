=== Checking the Mail an App Sent

==== Problem

As an artificial intelligence (AI) agent testing an app, you want the sign-up mail it sends over Simple Mail Transfer Protocol (SMTP) read back over Internet Message Access Protocol (IMAP), and the test failed if the subject, sender or recipient is wrong.

==== Solution

Write the agent{apos}s side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `start_server` for an SMTP and an IMAP listener serving your domain, sends the mail through `curl-mcp`{apos}s `curl` tool as the app would, fetches the recipient{apos}s `From`, `To` and `Subject` with the same tool, and compares them with what it expects:

==== Discussion

The program starts `surl-mcp` and `curl-mcp` by name from the path, over standard input and output, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`; `mcp.json` beside this recipe is the same configuration for an agent{apos}s own client. The argument picks the scenario.

`start_server` takes `listen_urls`, an `smtp://` and an `imap://` URL on port 0, and answers `bound_urls` with the real ports, in the same order, and a `server_id`. The two servers share one mail store (<<surl-readme>>). `arguments` is `surl`{apos}s own options: `--mail-domain example.com` serves mail for that domain, and each `--mailbox` adds a mailbox and the account that logs in to it by its whole address, one for the app and one for Ann.

The `curl` tool runs `curl`{apos}s own arguments and answers in text that is JavaScript Object Notation (JSON), with `exitCode` and the `standardOutput` `content`; the program prepends `-s` to keep the progress meter out. As the app, it logs in with `-u`, gives the envelope with `--mail-from` and `--mail-rcpt`, and uploads `signup.eml` from the folder with `-T` (<<rfc5321>>); `--crlf` makes sure each line ends in a carriage return and line feed. No loosening option is needed: without Transport Layer Security `surl` offers `CRAM-MD5`, a login that never sends the password, and `curl` uses it. As the test, it logs in as Ann and fetches `INBOX;UID=1;SECTION=HEADER.FIELDS%20(FROM%20TO%20SUBJECT)`: the three fields of the message whose unique identifier (UID) is 1, ending in the blank line that ends a header (<<rfc9051>>). The program prints them as a JSON string so the carriage returns show, and passes only if they are exactly the expected three.

A misspelt subject is delivered like any other mail, and only the comparison catches it. A mistyped recipient inside the domain, `an@example.com`, is quieter still: the send exits `0`, because the server accepts every address in its domain and discards the ones with no mailbox, so a sender cannot learn which exist (<<surl-readme>>). The fetch then exits `78`, remote file not found, with nothing on standard output. The agent can confirm it without a client. `list_mailboxes`, given the `server_id` and the `owner`, Ann{apos}s address, counts no message in her `INBOX`; `get_exchanges`, given the `server_id` and `scheme` `smtp`, returns what the app and server said, byte for byte, as `chunks` with a `direction`, and shows `RCPT TO:<an@example.com>` answered `250`. A recipient outside the domain is refused at that line instead, which is <<smtp-fail-a-test-on-a-wrong-recipient-from-an-agent>>.
