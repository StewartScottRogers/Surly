=== Catching Every Address in One Mailbox

==== Problem

As an artificial intelligence (AI) agent testing an app that mails many generated addresses over Simple Mail Transfer Protocol (SMTP), you want a catch-all to land them all in one mailbox that the agent reads and counts over Post Office Protocol version 3 (POP3).

==== Solution

Write the agent{apos}s side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `start_server` with a mail domain, two mailboxes and `--mail-catch-all`, sends one mail to each generated address through `curl-mcp`{apos}s `curl` tool, then counts the catch-all over POP3 with the same tool and in the store with `list_mailboxes`:

==== Discussion

The program starts `surl-mcp` and `curl-mcp` by name from the path, over standard input and output, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`; `mcp.json` beside this recipe is the same configuration for an agent{apos}s own client. The argument picks the scenario.

`start_server` takes `listen_urls`, an `smtp://` and a `pop3://` URL on port 0, which share one mail store, and answers the `server_id` and `bound_urls` with the real ports (<<surl-readme>>). `arguments` is `surl`{apos}s own options. `--mail-domain example.com` serves mail for the domain; each `--mailbox` adds a mailbox and the account that logs in to it by its whole address, `app@example.com` to send as and `catchall@example.com` to read; `--mail-catch-all example.com=catchall@example.com` delivers mail for any address of the domain that has no mailbox to the catch-all. A `--mail-catch-all` with no `--mail-domain` is refused before anything listens: `start_server` is a tool error whose structured content carries `surl`{apos}s `exit_code` `2`, `exit_code_name` `FailedInit`, and its message in `lines`.

The `curl` tool runs `curl`{apos}s own arguments and answers in text that is JavaScript Object Notation (JSON): `exitCode`, and `standardOutput` and `standardError` with their `content`. The program prepends `-s` to drop the progress meter and `-S` to keep `curl`{apos}s error line. As the app, each call logs in with `-u`, names the envelope with `--mail-from` and `--mail-rcpt` (<<rfc5321>>), and uploads `invite.eml` from the folder with `-T`, `--crlf` making each line end in a carriage return and line feed. As the test, one call lists the catch-all{apos}s maildrop: a POP3 URL with no message number answers one line per message, its number and size (<<rfc1939>>), so the count is the number of lines. `list_mailboxes`, given the `server_id` and the `owner`, the catch-all{apos}s address, answers its mailboxes with a `message_count`, the same count read with no client. The program exits 0 when the count equals the number of addresses mailed.

Without `--mail-catch-all`, mail to an unknown address inside the domain is accepted and discarded: each send exits `0` and both counts are `0`. That is the default because a server that told a sender which addresses exist would give away the list (<<surl-readme>>). An address outside the domain is not caught but refused `550` at `RCPT TO`, and `curl` exits `55` with `RCPT failed: 550` on standard error, so the agent can tell an address the catch-all cannot take from one it took.
