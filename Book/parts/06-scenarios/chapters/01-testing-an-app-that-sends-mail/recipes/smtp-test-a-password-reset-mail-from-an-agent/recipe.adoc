=== Testing a Password Reset Mail

==== Problem

As an artificial intelligence (AI) agent testing an app, you want the password reset mail it sends read back, the link pulled out of it and fetched from the same server, to prove the link works.

==== Solution

Write the agent{apos}s side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `start_server` for Simple Mail Transfer Protocol (SMTP), Internet Message Access Protocol (IMAP) and Hypertext Transfer Protocol (HTTP) listeners, plays the app with `put_file` and `curl-mcp`{apos}s `curl` tool, then reads the mail with `curl`, finds the link and follows it with `transfer`:

==== Discussion

The program starts `surl-mcp` and `curl-mcp` by name from the path, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`; `mcp.json` beside this recipe is the same configuration for an agent{apos}s own client. The argument picks the scenario.

`start_server` takes three listen URLs on port 0 and answers a `server_id` and `bound_urls`, in the same order, with the real ports. The three servers share one set of stores (<<surl-readme>>). `arguments` is `surl`{apos}s own options: `--mail-domain example.com` serves mail for that domain, and each `--mailbox` adds a mailbox and the account that logs in to it by its whole address, one for the app and one for Ann.

The app makes a token of 16 hexadecimal digits and publishes its reset page with `put_file`, which writes `text` at `path` in the server{apos}s content store as an upload would; the HTTP listener serves it at once. It writes the mail, link included, to `reset.eml` in the folder and sends it with the `curl` tool, which runs `curl`{apos}s own arguments and answers in text that is JavaScript Object Notation (JSON), with `exitCode` and the `standardOutput` `content`. The program prepends `-s`; `-u` is the app{apos}s login, `--mail-from` and `--mail-rcpt` the envelope, and `-T` the file (<<rfc5321>>). No loosening is needed: without Transport Layer Security `surl` offers `CRAM-MD5`, which `curl` uses.

The test reads `INBOX;UID=1;SECTION=TEXT` with the `curl` tool as Ann, the body of her first message without its header (<<rfc9051>>), and takes the first `http://` address with `/reset/` in it. `transfer` makes one request described by fields, here only `url`, with no login, as the person resetting their password would. It answers `statusCode` and the `body` `content` (<<curl-readme>>); the test passes on `200` and prints the page, which names Ann.

A link with a token the app never published is answered `404` (<<rfc9110>>). To `transfer` that is an answer, not a tool error, so the agent reads `statusCode` and fails the test. A mail with no link fails before any fetch. That the link needs no login is part of the test: the mailbox accounts log in over SMTP, IMAP and POP3 only, so the HTTP listener has no account and serves every page to anyone. An account that logs in on HTTP, such as one `add_account` adds, would put a login in front of the reset page too (<<http-require-a-login>>).
