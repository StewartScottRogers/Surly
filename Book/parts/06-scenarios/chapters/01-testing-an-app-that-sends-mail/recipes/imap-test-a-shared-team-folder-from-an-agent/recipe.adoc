=== Testing a Shared Team Folder

==== Problem

As an artificial intelligence (AI) agent, your team inbox is a shared Internet Message Access Protocol (IMAP) folder; you want two accounts sharing it and a test that both see, and one can flag, a message delivered to it.

==== Solution

Write the agent{apos}s side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it calls `surl-mcp`{apos}s `start_server` with a folder shared by Ann and Bob, uses `curl-mcp`{apos}s `curl` tool to append a notice as Ann, read and flag it as Bob and search for it as Ann, and reads the store with `list_messages`:

==== Discussion

The program starts `surl-mcp` and `curl-mcp` by name from the path, over standard input and output, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`; `mcp.json` beside this recipe is the same configuration for an agent{apos}s own client. The argument picks the scenario.

`start_server` takes `listen_urls`, here one `imap://` URL on port 0, and answers `bound_urls` with the real port and a `server_id`. Its `arguments` are `surl`{apos}s own options: `--mail-domain example.com` and three `--mailbox` entries make mailboxes for Ann, Bob and Carol, each with the account that logs in to it by its whole address, and `--shared-folder team=ann@example.com,bob@example.com` creates one folder that Ann and Bob both see as `Shared/team` (<<surl-readme>>). They use it as equals: the folder and its flags are stored once.

The `curl` tool runs `curl`{apos}s own arguments and answers in text that is JavaScript Object Notation (JSON), with `exitCode`, `standardOutput` and `standardError`; the program prepends `-sS`: `-s` keeps the progress meter out, and `-S` still writes an error. `-u` is each member{apos}s login. `-T notice.eml` on the folder{apos}s URL is an IMAP `APPEND` of that file from the program{apos}s folder (<<curl-manual>>); its lines already end in a carriage return and line feed, because an append states the size first and `curl` will not convert line ends for it. `-X "STORE 1 +FLAGS (\Flagged)"` selects the folder and flags message 1, and the server answers with the flags, `\Flagged` and `\Seen`. `Shared/team?FLAGGED` is a `SEARCH`, and `* SEARCH 1` is Ann{apos}s view of Bob{apos}s flag (<<rfc9051>>).

`list_messages` reads the store without a client and sets no flag. Given the `server_id`, an `owner` and a `mailbox`, it answers `messages`, each with its `uid` and `flags`; for owner `ann@example.com` and mailbox `Shared/team` it lists UID 1 with `\Seen` and `\Flagged`, so an agent can assert on the store as well as on what a client saw.

The folder is closed to everyone else by default. Carol is not a member: the `curl` tool{apos}s read as Carol exits `67`, `Select failed`, a tool error, and `list_mailboxes`, given the `server_id` and an `owner`, lists `INBOX` and `Shared/team` for Ann but only `INBOX` for Carol. The folder has no mail address either, so `seed_mail`, which delivers a `message` `to` an address as Simple Mail Transfer Protocol (SMTP) would, is a tool error for `team@example.com`: `NoSuchAccount`. Mail reaches the folder by an append, or by a member moving it from an inbox, which is <<imap-test-a-shared-team-folder>>.
