=== Reaching Test Services Through SOCKS

==== Problem

Your test network lets clients out only through a SOCKS5 proxy. You want Hypertext Transfer Protocol (HTTP) and File Transfer Protocol (FTP) calls made through it, and the proxy{apos}s record showing each one.

==== Solution

Run the services and a SOCKS5 proxy in one `surl` with a verbose log, give `curl` the proxy with `-x socks5h://`, and read the proxy{apos}s `Connected to` lines from the log:

==== Discussion

SOCKS5 is a proxy that relays a Transmission Control Protocol (TCP) connection: the client names a host and port, the proxy connects there and answers `05 00` for success, and from then on it passes bytes both ways without reading them as any protocol (<<rfc1928>>). That is why one proxy serves both HTTP and FTP. Here one `surl` plays the test network: an HTTP service and an FTP service on `localhost`, serving the folder `site` (`--directory site`), and the proxy on `socks5h://127.0.0.1` (<<surl-readme>>). `-v` logs every exchange in detail, and `--log-file socks.log` writes the log of all three to one file. `--allow-anonymous` lets the FTP service take `curl`{apos}s anonymous login; the proxy itself asks for no login.

In `curl` the proxy is `-x socks5h://127.0.0.1:<port>`, `-s` keeps it quiet and `-S` keeps an error message (<<curl-manual>>). The `h` hands the name `localhost` to the proxy to resolve, so the client needs no address for a host it may not be able to look up; plain `socks5://` would resolve it first. The same option, unchanged, fetches `hello.txt` over HTTP and over FTP.

The proxy{apos}s record is its log. For each connection it writes `Connected to <host>:<port>; answered 05 00.`, and the host and port are those the client asked for, so the record names each service by its port: one connection to the HTTP port and one to the FTP port. FTP needs a second connection for the file itself (<<rfc959>>). `curl` asks for passive mode, the FTP server answers `229 Entering Extended Passive Mode` with a port, and `curl` opens that connection through the proxy too: the third `Connected to` line names the port from the `229` reply.

The record holds refused calls as well. A second FTP service, started as `surl` starts by default, does not take anonymous logins; through the same proxy `curl` exits `67`, login denied, and the proxy{apos}s log still has its connection to that service{apos}s port. The proxy carried the call; the service refused it.
