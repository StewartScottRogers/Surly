=== Asserting a Client's Back-off Schedule

==== Problem

Your C# client retries a failing call with waits that should grow, and you want the test to check that. You want the start time of each request, as the server recorded it, so the waits between attempts can be compared with the design.

==== Solution

Start a `SurlServer` that answers `503` to the first three requests for a file, run the client with a new connection for each attempt, and read the start time of each attempt from the server{apos}s record. ==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties: an `http://` listen URL on port `0`, two files in `Files`, and `RecordExchanges`, which keeps what the test reads. `SurlFault.ProtocolError("503")` with `Path` `/hello.txt` and `Times` `3` is the spelling of `--fault "error;scheme=http;path=/hello.txt;reply=503;times=3"`: the first three requests for the file are `503 Service Unavailable` (<<rfc9110>>) and the fourth is served (<<surl-readme>>).

The client under test is a loop of up to four attempts with a `CurlClient` for each, so that each attempt is a connection of its own. `SurlServer.Exchanges` is the server{apos}s record, a list of `SurlExchangeRecord`, one for each connection, and the `StartedAt` of each is the moment that attempt reached the server. The gaps between the starts of attempts are what the test asserts on, and they are the client{apos}s waits plus the time of each attempt, measured on the server{apos}s side and not by the client{apos}s own stopwatch.

The assertions are ranges, because a loaded machine stretches a wait but does not shorten it. Each gap must be at least its designed wait, 250, 500 and 1000 ms, with 50 ms allowed for a timer that fires early; under its design plus five seconds, so a hung client fails; and each gap, stated as a range, is its design or more and under its design plus five seconds; the last gap must be longer than the first, which says the waits grew without naming exact times. A client that waits 250 ms every time fails the check on its second and third gaps. One untimed request for another file comes first and takes the process{apos}s set-up cost, several seconds on the first, out of the gaps.

The test waits, with `WaitForEventAsync` for a `SurlEventQuery` with `Kind` `SurlEventKind.ExchangeEnded`, for at most thirty seconds each, once for the warm-up and once for each attempt, so the record is complete when it reads it and a missing exchange fails the test instead of hanging it. The exchanges after the first are the four attempts, and their start times increase. The client makes three retries after the first attempt and ends on `200`. The server{apos}s own record agrees: three `FaultApplied` events, all on `/hello.txt`, and the rule has no uses remaining. A `CurlRequest` is sent for each attempt and the `CurlResponse` carries the `StatusCode`: `503`, `503`, `503`, `200`.
