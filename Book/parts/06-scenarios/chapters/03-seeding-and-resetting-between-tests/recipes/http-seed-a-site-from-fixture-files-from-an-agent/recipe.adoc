=== Seeding a Site from Fixture Files

==== Problem

You keep test fixtures as files in the repository; you want them served so tests can change them, and the next run to start from the originals again. You want your artificial intelligence (AI) agent to set that up and put it back.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it reads the fixtures folder, hands the files to `surl-mcp`{apos}s `start_server` on Hypertext Transfer Protocol (HTTP) and File Transfer Protocol (FTP), lets a test change one through `curl-mcp`, and calls `reset_server` before the next test:

==== Discussion

`start_server`{apos}s `files` maps a `/` separated relative path to UTF-8 text, and the server holds those in memory. The program walks `fixtures` and passes each file by its relative path, so `fixtures/orders/1.json` is served as `/orders/1.json`. The server holds copies, so a test's changes never reach the disk: after the test, `fixtures/users.json` has its contents. `arguments` takes `surl`{apos}s own options, and both listen URLs serve the one store.

The test is `curl-mcp`{apos}s `curl` tool running `curl` against the FTP listener (<<rfc959>>) with `-s`, quiet, and `-T new-users.json`, which uploads that file from `CURL_MCP_ROOT`; and the answer's `exitCode` is `curl`{apos}s. `transfer` then fetches `users.json` over HTTP (<<rfc9110>>) and gets the uploaded contents.

`reset_server` returns the server's files, mail, messages and accounts to their state at start, which here is the fixtures; call it between tests and every test starts from them. A new run reads the folder again.

Two options loosen `surl` for the test. `--allow-anonymous` accepts any login or none; without it `curl`{apos}s anonymous FTP login is refused, exit 67. `--allow-uploads` lets clients write; with `--allow-anonymous` alone, the upload fails with exit 25. In both cases `users.json` stays as seeded. Both are off by default so that a server nobody meant to open for writing is not writable.

Serving the fixtures folder itself, with `--directory fixtures` in `arguments`, is the mistake this recipe avoids: the upload lands in the repository's `fixtures/users.json`, and `reset_server` refuses with a tool error, since a store on disk is never reset, so a test never empties a real directory.
