=== Serving a PFX Certificate from an Agent

==== Problem

Your certificate comes as a password-protected PFX file from Windows, not as Privacy-Enhanced Mail (PEM) files. You want an artificial intelligence (AI) agent to serve it with Model Context Protocol (MCP) tool calls and no shell, to see the server refuse the wrong passphrase, and to read why.

==== Solution

The program is the agent's side: it starts `surl-mcp` and `curl-mcp`, calls `start_server` with the PFX named in `arguments`, then fetches over HTTPS with `curl-mcp`{apos}s `transfer` tool. The first `openssl` line makes a test certificate and the second packs it into a PFX, which stands in for the file Windows exported:

==== Discussion

A PFX file, also called a PKCS #12 or P12 file, is one file that holds a certificate and its private key under a passphrase. `StdioClientTransport` starts each host by name from `PATH`, and `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine both to the folder the program runs in, which is where `server.pfx` and `server.pem` are. The argument after `--` is the passphrase to try.

`start_server` starts a server that behaves as `surl` with the same options. `listen_urls` is `https://127.0.0.1:0`, port 0 for a free one, and `bound_urls` in the structured answer holds the real address. The certificate options have no arguments of their own: `arguments` takes any other `surl` option in `surl`{apos}s own words, one list item each, so `["--cert", "server.pfx", "--cert-type", "P12", "--pass", "s3cret"]` is the command line `--cert server.pfx --cert-type P12 --pass s3cret` (<<surl-readme>>). There is no key file, because the key is inside the PFX. `files` puts `hello.txt` in the server in memory.

`curl-mcp`{apos}s `transfer` tool fetches the file. Its `caFile` is `curl --cacert`: it names `server.pem`, the certificate alone, as one to trust, because it signed itself (<<curl-readme>>, <<rfc5280>>). The answer is text holding JSON; the program reads `statusCode` and `body.content`.

With a wrong passphrase nothing listens. `start_server` is a tool error, and its structured content carries `surl`{apos}s own exit code, `exit_code` `58` with `exit_code_name` `CertificateProblem`, the code for a certificate that cannot be used, and its text is `surl`{apos}s message: `'server.pfx' is a P12 file the --pass given does not open`. It names the passphrase, not the file, as the fault. Nothing here loosens a default.
