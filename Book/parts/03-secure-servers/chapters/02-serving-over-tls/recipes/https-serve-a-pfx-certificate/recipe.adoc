=== Serving a PFX Certificate

==== Problem

Your certificate comes as a password-protected PFX file from Windows, not as Privacy-Enhanced Mail (PEM) files. You want `surl` to serve it, to refuse to start with the wrong passphrase, and to say why.

==== Solution

Give `surl` the PFX with `--cert`, say it is a PKCS #12 file with `--cert-type P12`, and give its passphrase with `--pass`. The first `openssl` line makes a test certificate and the second packs it into a PFX, which stands in for the file Windows exported:

==== Discussion

A PFX file, also called a PKCS #12 or P12 file, is one file that holds a certificate and its private key, encrypted under a passphrase. Windows exports certificates in this form, and `surl` reads PEM unless told otherwise (<<surl-readme>>). `--cert-type P12` says the file is a PFX, and the type is read in any case, so `p12` does the same. `--pass` is the passphrase that opens it. There is no `--key`: the key is inside the file, and `--key` beside a P12 `--cert` is refused as an option badly used, exit `2`.

`--directory site` is the folder served, as in any file recipe, and `-s` on `curl` leaves out the progress meter so only the file is printed. `curl` sees an ordinary certificate. The server shows the certificate from the PFX in the handshake, and `curl` checks it as it would any other (<<rfc5280>>). Here `--cacert server.pem` names the same certificate as one to trust, because it signed itself; `server.pem` is the certificate alone, which is why a test needs the PEM as well. A certificate from a real authority needs no `--cacert` on a client that already trusts that authority (<<curl-readme>>).

The refusals all happen before `surl` listens, and all are exit `58`, the code for a certificate that cannot be used. A wrong passphrase is refused with `'server.pfx' is not a P12 certificate Surl can read`. Leaving `--pass` out of a protected PFX gives the same message. The message does not say whether the passphrase or the file is at fault, so when the passphrase is right and the message still comes, check the file. Without `--cert-type P12`, `surl` reads the PFX as PEM, finds no PEM certificate and says `holds no PEM certificate`: that is the error to expect when the type was forgotten. A `--cert` file that is not there is exit `58` too, naming the file. None of these options loosens a default.
