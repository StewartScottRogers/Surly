=== Refusing Clients below TLS 1.3

==== Problem

You want to prove your client still works when the server accepts Transport Layer Security (TLS) 1.3 only, and to see what an older client gets. You want a server whose lowest and highest TLS versions you choose, with the failing handshake shown as `curl` reports it.

==== Solution

Start `surl` with `--tlsv1.3`, so it takes nothing older than TLS 1.3, and fetch from it with `curl --tlsv1.3`. The `openssl` line makes the throwaway certificate both use:

==== Discussion

TLS is negotiated before the first byte of HTTP: the client lists the versions it can speak, the server picks one it accepts, and when they share none the handshake fails (<<rfc8446>>). `surl` accepts TLS 1.2 and 1.3 by default. `--tlsv1.3` raises the lowest version it accepts to 1.3, and `--tls-max` lowers the highest; `--tlsv1.2` and `--tls-max 1.3` are what you get without them (<<surl-readme>>). The options that reach below 1.2, `--tlsv1.0` and `--tlsv1.1`, are the ones that loosen security, because they let a peer use versions that are no longer considered safe; this recipe does not use them.

On the `curl` side, `--tlsv1.3` asks for TLS 1.3 or later and `--tls-max 1.2` sets the highest version `curl` offers, which makes it behave as an older client. Against the `--tlsv1.3` server the `--tls-max 1.2` client prints nothing and exits `35`, the code for a failed TLS handshake. A `curl` with no version option offers 1.3 as well as older versions and is served, so a server limited to 1.3 refuses old clients only. After the refusal the server keeps listening and answers the next client, so one old client does not stop the others.

The same options work in the other direction. A server started with `--tls-max 1.2` refuses a client that insists on TLS 1.3, again with exit `35`, and serves a client that accepts 1.2. A server started without `--tlsv1.3` serves the TLS 1.2 client the first server refused. The version range is checked before `surl` listens: `--tlsv1.3` together with `--tls-max 1.2` leaves no version to speak, and `surl` refuses to start with exit `2`.

The wording of the `curl: (35)` line depends on the TLS library `curl` was built with; the exit code does not. The certificate comes from `openssl` as in the recipe on serving with your own certificate: `--cert server.pem` is the certificate `surl` shows and `--key server.key` its private key, and `--cacert server.pem` makes `curl` trust it, so a failure here is always about the version and never about trust.
