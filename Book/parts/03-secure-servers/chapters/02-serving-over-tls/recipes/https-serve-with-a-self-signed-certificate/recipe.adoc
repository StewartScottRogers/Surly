=== Serving HTTPS with a Self-Signed Certificate

==== Problem

A test needs an `https://` server on your own machine, and you do not want to make or manage a certificate for it.

==== Solution

==== Discussion

Hypertext Transfer Protocol Secure (HTTPS) is HTTP inside Transport Layer Security (TLS), and TLS starts with a handshake in which the server shows a certificate (<<rfc8446>>, <<rfc9110>>). `surl` will not open an `https` listen URL without one. Given neither `--cert` nor `--self-signed`, it ends at start with exit code `58` and a line naming both ways to give one, rather than invent a certificate quietly (<<surl-readme>>).

`--self-signed` is the way for a test. `surl` makes a throwaway certificate when it starts and serves it, and writes `surl: warning: --self-signed: serving a throwaway certificate; clients must skip verification (curl -k)` on standard error, as every loosening option does (<<surl-readme>>). No client can verify that certificate, because nobody vouches for it, and that is what the option gives up: a client cannot tell this `surl` from anything else that answers on the same address. That is why it is not the default, and why it belongs on your own machine and nowhere else. `--self-signed` and `--cert` are two answers to the same question, so asking for both is refused as an option badly used, exit `2`.

On the `curl` side, `-k` (`--insecure`) skips verification of the server's certificate; the connection is still encrypted, only not authenticated. Without `-k`, `curl` does what it should with a certificate it cannot trace to a certificate authority it trusts: it refuses the connection, prints nothing and exits `60` (<<curl-readme>>). The wording of the `curl: (60)` line depends on the TLS library `curl` was built with; the exit code does not.

`--directory site` serves the files under `site`, as it does over plain HTTP. Over TLS, `curl` and `surl` agree on HTTP/2 during the handshake, with nothing asked for; `-w "%{http_version}"` prints the version used, with `-s` to keep `curl` quiet and `-o /dev/null` (`NUL` on Windows) to throw the body away. `--http1.1` makes `curl` offer only HTTP/1.1, and `surl` answers in it.

For anything that is not a throwaway test, give `surl` a real certificate with `--cert` and `--key`, and `curl` the means to verify it, so neither side has to skip anything (<<https-serve-with-your-own-certificate>>).
