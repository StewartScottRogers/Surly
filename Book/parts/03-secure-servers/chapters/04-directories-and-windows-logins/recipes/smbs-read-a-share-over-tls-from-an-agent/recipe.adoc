=== Reading Shares over SMBS from an Agent

==== Problem

Your client reads files from a Server Message Block (SMB) share and you want the session inside Transport Layer Security (TLS). You want an agent to start an `smbs` server with your certificate and a login it accepts, read from it, and see the failure when the client does not trust it.

==== Solution

The agent starts the server with `surl-mcp`, with the certificate and key that `openssl` wrote, and reads a file with `curl-mcp`, trusting the certificate:

==== Discussion

`start_server` has no TLS fields, so the certificate goes in `arguments`, surl{apos}s own options as words: `--cert server.pem --key server.key`, files inside the folder `SURL_MCP_ROOT` names. `-u alice:s3cret` adds the account and `--auth ntlmv1` accepts the login `curl` makes in an SMB session setup, NTLMv1, the first version of Windows NT LAN Manager{apos}s challenge and response. `files` serves content in memory, and the first folder of a path, `docs`, is the share. The answer{apos}s `bound_urls` has the port taken.

Without a certificate and without `--self-signed` the server is not started. The answer is a tool error: its text is surl{apos}s line, which says it needs a certificate and names both options, and its structured content has `exit_code` `58` and `exit_code_name` `CertificateProblem`. With `--self-signed` the server makes a throwaway certificate and warns; it is a loosening, and the read then needs `-k`.

The read uses the `curl` tool, which takes curl{apos}s own arguments in `args`, because the `transfer` tool has only `insecure` and no way to name a certificate. `--cacert server.pem` trusts the certificate, which is its own authority, and the read exits `0`. Without it `curl` exits `60`, and with a throwaway certificate it exits `60` until `-k` is given. A wrong password exits `67`, login denied, as on plain SMB. The answer is JSON with `exitCode` and `standardOutput` and `standardError`, each with a `content` or `null`; `-s` hides the progress meter and `-S` keeps the error, and the claims below match only the `(60)`, since the wording after it is the TLS library{apos}s.
