=== Uploading to SMB in C#

==== Problem

Your app saves reports to a Windows file share over Server Message Block (SMB). You want a test, in C#, against a share that refuses the upload until uploads are allowed and then keeps the file where you can read it back.

==== Discussion

`SurlServer` is the server in this process and `SurlServerOptions` is its command line as properties. `ListenUrls` lists `smb://` and `http://` on port `0`, which takes a free one, and `server.BoundUrls` has the ports it took, in the same order. `DataDirectory` is `--directory`, and each folder directly in it is a share, `docs` here. `Accounts` takes a `SurlAccount`, `-u alice:s3cret`. `AuthenticationMethods` is `--auth`: `ntlmv1` is the login `curl` makes in an SMB session setup, and `digest` is what the HTTP client logs in with; Basic over plain HTTP would need `AllowPlaintextAuthentication`.

`CurlClient` sends a `CurlRequest`. The upload is a `PUT` to the `smb://` URL whose `Body` is the bytes, which `Curl.Api` sends as `curl -T` does, and `Authentication` is a `CurlAuthenticationOptions` with only a user name and password, since the SMB login is NTLMv1 and needs no option. `SendAsync` returns a `CurlResponse`, whose `Body` stream is the file on a read. SMB has no status line, so the answer to an upload is that `SendAsync` threw nothing; the program prints `stored` for it. A second upload to the same name replaces the file. The read-back over SMB is a `GET` to the same URL. The read over HTTP is the same file on the second listener, for a reader that does not speak SMB, and its `HttpAuthentication` is `HttpAuthenticationMethods.Digest`, `curl --digest`.

`AllowUploads` is `--allow-uploads`, off by default and a loosening, since it widens what a peer may do. Without it the upload makes `SendAsync` throw a `CurlException` whose `Code` is `RemoteAccessDenied`, `curl`{apos}s exit code `9`, and nothing is written. `MaxFileSize` is `--max-filesize`; at `10` bytes the upload throws `UploadFailed`, `25`, and nothing is stored. In both, the read-back throws `RemoteFileNotFound`, `78`, since the share does not have the file. The program turns each exception into a line, so the cases show it.
