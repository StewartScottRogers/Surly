=== Filtering a Directory Search in C#

==== Problem

==== Discussion

`SurlServerOptions` asks for an `ldap://` listener on port `0`, so the system picks a free port, and `AllowAnonymous`, the option `--allow-anonymous`, which lets a search run with no password. It loosens the defaults, for a directory that holds nothing private, and `surl` warns on every start while it is on (<<surl-readme>>). The directory starts empty. `SurlServerDirectory`, reached as `server.Directory`, adds entries with `AddEntriesAsync` from LDAP Data Interchange Format (LDIF) text, all or none, to the running `SurlServer`: two branches under `dc=example,dc=com`, `ou=people` and `ou=groups`, each entry named by its distinguished name (DN). Nothing is written to disk.

The client is a `CurlClient`, and a search is a `CurlRequest`, a GET of an `ldap://` URL (<<rfc4516>>): the base DN, the attributes to return, the scope and the filter, separated by `?`. The answer is a `CurlResponse` whose body is the entries. `Authentication`, a `CurlAuthenticationOptions`, with `UserPassword` set to `":"` is an empty name and password, which `curl` sends as the anonymous bind. The base is where the search starts, and the scope says how far it goes: `base` is the base entry alone, `one` the entries directly under it, `sub` the base and everything below. Because the filter `(cn=staff)` finds the group two levels down only with `sub`, the same filter with `one` returns nothing, and that is an empty answer, not an error. `(&(objectClass=person)(mail=*example.com))` joins two tests with and, and `(!(cn=bob))` negates one.

The program prints each entry on one line, its DN and attributes separated by commas, rather than the text as it came: the layout of the LDAP library under `Curl.Api` differs between platforms, and this keeps the output the same. A base that is not in the directory is answered `noSuchObject` (<<rfc4511>>), and `SendAsync` throws `CurlException` with code `39`, `LdapSearchFailed`, which is how a missing base differs from an empty result. The last server leaves `AllowAnonymous` off and refuses the anonymous bind, and `SendAsync` throws code `38`, `LdapCannotBind`.
