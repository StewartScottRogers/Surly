=== Per-User Share Rights from an Agent

==== Problem

Two users share a server: one may only read the reports share, the other may write it. You want an agent to stand up that server and give each user their own rights, with the reader{apos}s upload refused and the writer{apos}s kept.

==== Solution

==== Discussion

`start_server` takes `listen_urls`, here one `smb://` URL on port `0` so it takes a free port, and `arguments`, surl{apos}s own options as a list of words. The answer{apos}s `bound_urls` has the port taken. `--share reports=grants/reports` serves a folder under the confined root as the share `reports`. `-u` adds an account for each person, and `--auth ntlmv1` accepts the login `curl` makes in an SMB session setup (<<ms-smb>>). `--share-access reports=reader:r,writer:rw` lets `reader` read and list the share and `writer` also upload, rename and delete.

The `curl` tool of `curl-mcp` takes curl{apos}s own arguments in `args`, so `-u writer:wr1te -T new.txt` uploads a file from the folder the host is confined to. The answer is JSON: `exitCode`, and `standardOutput` and `standardError`, each with a `content` or `null`. The program prints the exit code and the first of the two that has text; `-s` hides the progress meter and `-S` keeps the error message. The writer{apos}s upload exits `0` and the reader reads the file. The reader{apos}s upload exits `9`, access denied, although `--allow-uploads` is on, and reading the name back as the writer exits `78`, remote file not found, so nothing was written.

A grant is separate from `--allow-uploads`, which is off by default and a loosening because it widens what a peer may do. A write needs both: the `no-uploads` run starts the server without it, and the `rw` account{apos}s upload exits `9` too, while the reader still reads. A grant is also separate from the login: a wrong password exits `67`, login denied.

A share with a grant is closed to every account it does not name. `carol` has a valid login and is not named, so a read or an upload in `reports` exits `78`, as if the share were missing. The share `other` has no grant and stays open to every login, and with `--allow-uploads` on it takes `carol`{apos}s upload; give each share you care about a grant.

`--group editors=writer` names a group, and `@editors:rw` grants it. The `group` run shows the member uploading and the account outside the group refused with `9`.
