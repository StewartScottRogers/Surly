=== Reading a File from an SMB Share

==== Problem

A script fetches files from a Windows file share over Server Message Block (SMB), and you want a local share with known files that it can log in to and read.

==== Solution

Put a folder under `site`, start `surl` with an account and the login `curl` uses for SMB accepted, and fetch a file from the share:

Stop `surl` with kbd:[Ctrl+C]. The checked claims below also run two more `surl` on ports `8081` and `8082`, one with nothing loosened and one with `--auth ntlm`, to show what each refuses.

==== Discussion

`--directory site` serves `site`, and each folder directly under it is a share named after the folder (<<surl-readme>>). In `smb://127.0.0.1:8080/docs/readme.txt` the first path segment, `docs`, is the share, and the rest, `readme.txt`, is the path inside it, so `docs/notes/todo.txt` is fetched the same way. A file that is not there, a share that does not exist, and a folder named as if it were a file all make `curl` exit `78`, remote file not found. A URL with only one segment, such as `smb://127.0.0.1:8080/readme.txt`, names no share, and `curl` refuses it itself with exit `3`, URL malformed.

The share is read-only here. `-T report.txt` asks `curl` to upload `report.txt` instead of downloading, and `surl` refuses it; `curl` exits `9`, access denied. Accepting uploads takes `--allow-uploads` (<<surl-readme>>).

`-u alice:s3cret` adds the account on the server and gives `curl` the name and password for the session setup, SMB's login. `curl` speaks SMB version 1 (<<ms-smb>>) and logs in with NTLMv1, the first version of Windows NT LAN Manager's challenge and response (<<ms-nlmp>>), and with nothing else. A wrong password is refused at session setup, and `curl` exits `67`, login denied. With no `-u` the session setup carries no account and is refused the same way.

`--auth ntlmv1` is the loosening option, and the share cannot be read without it. By default `surl` refuses every NTLMv1 session setup, right password or not, and `curl` exits `67`. An NTLMv1 response is computed with the Data Encryption Standard (DES) from an unsalted hash of the password, so anyone who sees one can crack it offline; that is why it is not the default (<<surl-readme>>). `--auth ntlm`, which accepts the newer NTLM over Hypertext Transfer Protocol (HTTP) and the Lightweight Directory Access Protocol (LDAP), does not accept it. `surl` writes a `surl: warning:` line naming the methods it accepts whenever `--auth` is given. NTLMv1 sends no password, so `--allow-plaintext-auth` plays no part. The response is what needs protecting, and `smbs`, SMB inside Transport Layer Security (TLS), keeps it off the wire (<<surl-readme>>).

`-s` hides `curl`'s progress meter and `-S` still shows the error, which is where the checked claims read `curl`'s message. `curl` needs to have been built with SMB, and not every build is: `-V` makes `curl` print its version and the protocols the build supports, and this one lists `smb` and `smbs`.
