=== Uploading to SMB from an Agent

==== Problem

Your app saves reports to a Windows file share over Server Message Block (SMB). You want an agent to stand up a test share that refuses the upload until uploads are allowed, then keeps the file where a Hypertext Transfer Protocol (HTTP) client can read it.

==== Discussion

`start_server` takes `listen_urls`, here `smb://` and `http://` on port `0` so each takes a free port, and `arguments`, surl{apos}s own options as a list of words. The answer{apos}s `bound_urls` has the ports taken, in the order given. `--directory site-allow` serves a folder under the confined root, and each folder directly in it is a share, so `docs` is one. `-u alice:s3cret` adds the account. `--auth ntlmv1,digest` accepts the login `curl` makes in an SMB session setup, NTLMv1, the first version of Windows NT LAN Manager{apos}s challenge and response, and offers HTTP Digest for the second listener.

`--allow-uploads` is the loosening option, since it widens what a peer may do. The `curl` tool of `curl-mcp` takes curl{apos}s own arguments in `args`, so `-T report.txt` uploads a file from the folder the host is confined to, to `smb://.../docs/report.txt`. With the option the upload exits `0`, and a second upload to the same name replaces the file. Without it the upload exits `9`, access denied, and reading the name back exits `78`, remote file not found, so nothing was written. With `--max-filesize 10` the upload exits `25`, upload failed, and the partial file is deleted, so the read exits `78` again.

The answer to `curl` is JSON: `exitCode`, and `standardOutput` and `standardError`, each with a `content` or `null`. The program prints the exit code and the first of the two that has text; `-s` hides the progress meter and `-S` keeps the error message. The second listener is how the file is read by something that does not speak SMB: `--digest -u alice:s3cret` logs in to it, and the bytes are those that were uploaded.
