=== Filtering a Directory Search from an Agent

==== Problem

Your app looks people up by attribute in one branch of the directory. You want a Lightweight Directory Access Protocol (LDAP) search that narrows by base, scope, filter and attributes, and an empty result told apart from a missing base, with an agent driving `surl-mcp` and `curl-mcp`.

==== Solution

==== Discussion

The program starts `surl-mcp` and `curl-mcp` by name, each confined to the working folder through `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. `start_server` takes `listen_urls`, here an `ldap://` address on port `0`, and `arguments`, the other `surl` options in `surl`{apos}s own words. The first server has `--allow-anonymous`, which lets a search run with no password; it loosens the defaults, for a directory that holds nothing private, and `surl` warns on every start while it is on (<<surl-readme>>). The second has no arguments and is there to show the refusal. Both start with an empty directory.

`add_ldap_entries` puts LDAP Data Interchange Format (LDIF) text into the first server's directory, all or none, and answers how many entries it added: six, two branches under `dc=example,dc=com`, `ou=people` and `ou=groups`, each entry named by its distinguished name (DN). Nothing is written to disk.

The `curl` tool of `curl-mcp` runs `curl` with the arguments the agent gives, and answers in text, as JavaScript Object Notation (JSON), with the standard output and the exit code. `-u :` is an empty name and password, which `curl` sends as the anonymous bind, and `-s` and `-S` quiet the progress meter and keep the error message. The URL is the search (<<rfc4516>>): the base DN, the attributes to return, the scope and the filter, separated by `?`. The base is where the search starts, and the scope says how far it goes: `base` is the base entry alone, `one` the entries directly under it, `sub` the base and everything below. Because the filter `(cn=staff)` finds the group two levels down only with `sub`, the same filter with `one` returns nothing, and that is an empty answer with exit `0`, not an error. `(&(objectClass=person)(mail=*example.com))` joins two tests with and, and `(!(cn=bob))` negates one.

The program prints each entry on one line, its DN and attributes, and the exit code in place of the error message: the layout and the wording belong to the LDAP library under `curl`, which differs between platforms. A base that is not in the directory is answered `noSuchObject` (<<rfc4511>>) and `curl` exits `39`, which is how it differs from an empty result. On the second server, the anonymous bind is refused and `curl` exits `38`. Neither is a tool error: the `curl` tool reports the exit code, and the program prints it.
