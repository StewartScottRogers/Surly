# Review: ldap-bind-with-ntlm
Verdict: accept with fixes
Checked against local builds on 2026-11-18 (not releases): surl 1.0.0 (Surl commit a0236e175), Curl port 8.22.0 (Curl commit f4b30d981f): 7 of 7 cases pass on windows.
## Findings
1. Truth (4, 7): the default refusal of NTLM (`authMethodNotSupported`, exit 38) and the `--auth negotiate` behaviour are cases against two more `surl`, each with an empty directory; their cases read the root DSE, which needs no entries.
2. Truth (4): `--auth negotiate` does not accept `curl --ntlm` (WinLDAP's Sicily bind), only `--negotiate` (`GSS-SPNEGO`). `surl --aihelp ldap` says the NTLM binds are "accepted with `--auth ntlm` or `--auth negotiate`", which reads as either word accepting either option; the build does not, and the recipe states what it does. Worth tightening the help text upstream (not a defect: the ADR-0072 table maps Sicily to `ntlm`).
3. Truth (5): that `WinLDAP` seals every message after the bind is cited to <<surl-readme>> ("no password then crosses the wire in clear") and inferred from the search answering; it is not observed directly.
4. Platform: Windows only. The binds are `WinLDAP`'s; the prose says the recipe makes no claim about curl on Linux or macOS. Verify there before publishing.
5. Removed a sentence claiming `--auth ntlm,negotiate` accepts both, which had no case.
6. Updated 2026-11-19: CI on Linux and macOS failed 6 of 7 cases. The NTLM and Negotiate binds are `WinLDAP`'s, so `solution`, `root-dse-offers-ntlm`, `wrong-password`, `strict-refuses-ntlm` and `negotiate-binds` are `platforms: [windows]`, each claim saying why. `simple-bind-still-refused` now checks exit 38 only (Linux words it `LDAP: cannot bind`, Windows `Confidentiality Required`); the prose cites `confidentialityRequired` to <<ldap-search-a-directory>>, where it is a case on every platform. `negotiate-is-not-ntlm` passes everywhere and stays. Program findings (Curl port, Linux and macOS): `curl --ntlm -u alice:s3cret ldap://…` exits 67 `Login denied` against `surl --auth ntlm` and against a default `surl`, where upstream curl's OpenLDAP backend ignores `--ntlm` (an HTTP option) and would simple-bind (exit 38); and the same `confidentialityRequired` simple-bind refusal is worded `Confidentiality Required` when the server has no `--auth` but `LDAP: cannot bind` under `--auth ntlm`.
- Platform (2026-11-19, CI run 44662810792): negotiate-is-not-ntlm failed on Linux and macOS (exit 67 Login denied, not 38): now [windows]; new [linux, macos] case no-ntlm-bind-on-openldap shows --ntlm exits 67 even against --auth ntlm (the port's OpenLDAP dialect has SASL DIGEST-MD5 only, Curl BL-5435). Prose says so. Whether upstream curl on Linux does the same is not checked here (finding 6 above says otherwise).
