=== Keeping Passwords out of the Process List

==== Problem

You want a Hypertext Transfer Protocol (HTTP) server that needs a login, without the passwords on its command line where anyone on the machine can list them.

==== Solution

Put the accounts in a file, one `user:password` a line, and name it with `--user-file`:

==== Discussion

Every `--user alice:secret` on a command line is visible to other local users in the process list. `--user-file accounts.txt` reads the accounts from a file instead, here for the folder `--directory site` serves, so the command line holds only the file's name (<<surl-readme>>). The passwords are still in clear in the file: outside a test, let only the user `surl` runs as read it. On Linux and macOS `surl` warns at every start when the file can be read by group or others; Windows has no such warning (<<surl-readme>>).

Each line is one account, read as `--user` reads its value: split at the first colon. Blank lines are skipped, and so are lines starting with `#`. The first line of this file, `#carol:retired`, would otherwise be the account `#carol`; logging in as it is answered `401 Unauthorized`. Alice and Bob, on the lines that are accounts, log in; a request with no login is answered `401`, as on any server with an account.

`surl` is strict about the file when it starts. A line that is not `user:password` stops the start with exit `2` and names the file and the line. A file that cannot be read stops it with exit `37`. `--user` and `--user-file` may be given together, but a user name in both is given twice and stops the start with exit `2`.

`curl` logs in with HTTP Digest, `--digest` (<<rfc7616>>), which sends no password over the connection, as the account `-u alice:s3cret` names; `-s`, `-o` and `-w "%{http_code}"` print only the status code. The password on `curl`{apos}s own command line is as visible as one on `surl`{apos}s; in a test, both are throwaway.
