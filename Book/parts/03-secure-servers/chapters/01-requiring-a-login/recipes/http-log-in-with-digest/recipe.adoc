=== Logging In with HTTP Digest

==== Problem

==== Discussion

`--directory site` serves the folder `site`, and `--user alice:secret` gives it one account; once there is one, every request needs a login. HTTP Digest (<<rfc7616>>) is a challenge and a response. `surl` answers a request with no login `401 Unauthorized` and a `WWW-Authenticate: Digest` header carrying a fresh nonce; the client hashes the user name, password, nonce and request together and sends the hash back in an `Authorization` header. The password itself never crosses the connection, which is why `surl` accepts Digest over `http://` with no loosening option.

Over `http://`, Digest is the only method the challenge offers, and it offers it three times, once for each algorithm: `MD5` (Message Digest 5), then `SHA-256` and `SHA-512-256` (two forms of Secure Hash Algorithm 2). `-D -` writes the response headers to standard output, and `-o` throws the empty body away. `--digest` makes `curl` answer the Digest challenge as the account `-u alice:secret` names, and it answers the first, so its `Authorization` header says `algorithm=MD5` and carries a 32-digit hexadecimal `response`; `-v` shows the header, and `2>&1` brings it to standard output. The fields in it are the same on every platform, but their order and spacing are not: `curl` on Windows has the system's Security Support Provider Interface (SSPI) build the header, and `curl` elsewhere builds it itself. `surl` checks a response in any of the three, though this recipe shows only MD5 (<<surl-readme>>).

`--anyauth` makes `curl` send the first request without a login, reads what the `401` offers and picks the best method it can: here that is Digest, and Alice is in. A wrong password is answered `401` again; `curl` exits `0`, since a `401` is still an answer, unless `-f` asks it to fail on an error status, when it exits `22`. `-s`, `-o` and `-w "%{http_code}"` print only the status code.

`curl -u` with no method sends HTTP Basic, the password itself, Base64-encoded. Over `http://` `surl` answers that `403 Forbidden`, right password and all; see <<http-refuse-a-password-in-clear>>.
