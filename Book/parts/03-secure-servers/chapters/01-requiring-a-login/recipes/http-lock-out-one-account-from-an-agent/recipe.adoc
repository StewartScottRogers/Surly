=== Locking Out One Account from an Agent

==== Problem

Your app must show a clear message when one user's login is refused while other users carry on. You want the server to refuse exactly one account, with the right password, until the test lifts the refusal, with an artificial intelligence (AI) agent driving `surl-mcp` and `curl-mcp`.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts a server with two accounts, adds a `refuse-login` rule for one with `add_fault`, logs in as each through `curl-mcp`{apos}s `curl` tool, and lifts the rule with `remove_fault`:

==== Discussion

`start_server` takes `surl`{apos}s own options in `arguments`: each `--user name:password` adds an account, and once one exists every request needs a login. `add_fault` takes the text a `--fault` option would, `refuse-login;account=bob`, and answers its `fault_id`, `f1`. The agent adds it after the server is up, so it chooses when the lock-out starts. The rule is for tests only. With no rule, bob logs in with the same password and is answered `200`.

`curl` runs `curl` with the arguments given. `--digest -u bob:b2-secret` logs in with Digest access authentication (<<rfc7616>>), and `-w "%{http_code}"` puts the status in `standardOutput`. alice is answered `200`; bob, with his right password, is answered `401`, the same as with a wrong one, so the client cannot tell a lock-out from a typing mistake. A refused login is an answer, not a tool error.

`list_faults` answers each rule's `fault_id`, `item` and `remaining`, null when the rule has no limit. With `times=1` on the rule, bob is refused once and then answered `200`, and `remaining` reads `0`. `remove_fault` with the `fault_id` lifts the rule, without a tool error, and bob's next login is answered `200`. The agent needs no control endpoint, as the console recipe does; `surl-mcp` is the control.

`get_events` with `kinds` set to `login_judged` answers a login per event: `mechanism`, `account` and `is_accepted`, so alice is accepted and bob refused. With `fault_applied` it answers the rule that acted: `rule_id` `f1` and `fault_kind` `refuse_login`.
