=== Listing and Making SFTP Folders

==== Problem

Your sync client lists remote folders and creates the ones it needs over the Secure Shell (SSH) File Transfer Protocol (SFTP). You want listings refused until they are allowed, then a folder made with a quote command and seen in the next listing.

==== Discussion

`--directory site` serves the folder `site`, `--user alice:s3cret` gives it Alice's account, and `--throwaway-hostkey` makes the SSH host key an SFTP listener needs, for tests only; `surl` warns on every start while it is given, naming the hash a client can pin (<<surl-readme>>). `-k` makes `curl` skip checking that key, and `-u` logs in. Neither `--list-directories` nor `--allow-uploads` is on by default, and each widens what a client may do. `-s` keeps the progress meter quiet and `-S` still prints an error message.

A listing is the first of the two. With a URL that ends in a slash, `curl` lists the folder; `-l` asks for the names alone, one a line, and without it the listing is the long one, in the style of Unix `ls -l`, where the first column is `d` for a folder and `-` for a file. The `closed` server in this recipe leaves `--list-directories` off and answers the listing as if the folder were not there: `curl` exits `78`, `Could not open directory for reading`, and prints nothing.

Making a folder is the second. `-Q` sends an SFTP command to the server, and `mkdir /reports` makes the folder. Without a leading dash, `-Q` runs the command before the transfer, so the listing in the same call already shows `reports`; with a leading dash, as in `-Q "-mkdir /archive"`, it runs after the transfer, and that listing does not show the folder it made. The next call, on a new connection, shows `archive`: what `mkdir` made is kept, not a view of one session. A folder made inside another is reached through its path, `mkdir /reports/2026`, and listed with a URL that names the outer folder. Making a folder that exists fails, and `curl` exits `21`, the code for a quote command that failed.

`mkdir` is a change to what the server holds, so it needs `--allow-uploads`. The `listing-only` server has `--list-directories` and not `--allow-uploads`: its listing works, and its `mkdir` is refused `Permission denied`, exit `21`. Finally, a listing needs a login, as everything does once an account exists: without `-u`, `curl` exits `67`, login denied.
