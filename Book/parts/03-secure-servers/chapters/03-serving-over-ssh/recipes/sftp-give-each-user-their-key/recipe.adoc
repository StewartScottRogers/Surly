=== Giving Each User Their Key

==== Problem

Two deploy users log in to a Secure Shell (SSH) File Transfer Protocol (SFTP) server with their own SSH keys, and one must not be able to log in as the other. You want each key accepted for its own user and refused for the other.

==== Solution

Make a host key and a key pair for each user, and give `surl` one `--authorized-keys` option for each user, naming the user and the file of public keys that user may use. Here `deploy-a` logs in with its key:

==== Discussion

In a public-key login the client proves it holds a private key by signing with it, and the server checks the signature against the public keys it was told to accept for that user (<<rfc4252>>). `--authorized-keys deploy-a:a_keys` gives the user `deploy-a` the keys in `a_keys`, and `--authorized-keys deploy-b:deploy_b.pub` gives `deploy-b` its own; the option is repeatable, and splits at the first colon into the user name and the file (<<surl-readme>>). The files are in the OpenSSH `authorized_keys` format, one public key a line. A user may have more than one key: `a_keys` holds two, and the second logs in as `deploy-a` too.

The keys are bound to the user they were listed for. `deploy-a`{apos}s key offered as `deploy-b` is refused, `deploy-b`{apos}s key offered as `deploy-a` is refused, and so is `deploy-a`{apos}s second key offered as `deploy-b`. A user that has no `--authorized-keys` at all, here `deploy-c`, is refused whatever key it offers. Each refusal is `curl` exit `67`, login denied. The key pairs, `deploy_a`, `deploy_a2` and `deploy_b`, and the server{apos}s `host_key`, come from `ssh-keygen` in the `setup` lines of `recipe.yml`.

`--hostkey host_key` is the server{apos}s own key, which every SSH listener needs, and `-k` on `curl` skips checking it to keep this recipe about the users{apos} keys; <<scp-pin-the-host-key>> pins it instead. On the `curl` side, `--key deploy_a` names the private key, `--pubkey deploy_a.pub` its public half, and `-u deploy-a:` the user with an empty password. `--directory site` serves the files, and `-s` and `-S` hide the progress meter but keep an error message.

With `-v` and `--log-file surl.log`, each login is a line: `Login accepted: publickey deploy-a`, naming the method and the user. A refusal is a `Login refused` line naming the user that was claimed; after a refused key, `curl` tries a password and then keyboard-interactive, and those are the logins the log says were refused.
