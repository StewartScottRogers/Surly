=== Making SFTP Folders from an Agent

==== Problem

Your sync client lists remote folders and creates the ones it needs over the Secure Shell (SSH) File Transfer Protocol (SFTP). You want listings refused until they are allowed, then a folder made with a quote command and seen in the next listing, with an agent driving `surl-mcp` and `curl-mcp`.

==== Solution

The program is the agent's side of the conversation, over the official Model Context Protocol (MCP) software development kit (SDK). It starts three servers with `surl-mcp`, lists and makes folders on them with `curl-mcp`, and reads the result back from the server:

==== Discussion

The program starts `surl-mcp` and `curl-mcp` by name, each confined to the working folder through `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. `start_server` takes `listen_urls`, here one `sftp://` address on port `0`, and `arguments`, the other `surl` options in `surl`{apos}s own words: `--throwaway-hostkey` for the SSH host key an SFTP listener needs, for tests only, `--user alice:s3cret`, and for the first server `--list-directories` and `--allow-uploads`, each of which widens what a client may do and neither of which is on by default. `files` holds `hello.txt` in memory. The answer carries the `server_id` and the `bound_urls`.

The `curl` tool of `curl-mcp` runs `curl` with the arguments the agent gives, and answers in text, as JavaScript Object Notation (JSON), with the standard output and error and the exit code. `-k` skips the check of the throwaway host key, `-u` logs in, `-s` and `-S` quiet the progress meter and keep the error message, and `-l` lists names alone, one a line. `-Q "mkdir /reports"` sends an SFTP command before the listing, so the first answer already shows `reports`; the same call on a new connection still shows it, since the server keeps what `mkdir` made. A command with a leading dash, `-Q "-mkdir /archive"`, runs after the transfer, and its own listing does not show the folder; the next one does.

Making a folder that exists fails, and `curl` exits `21`, quote command error. The second server leaves out `--allow-uploads`: `mkdir` is a change, and it is refused `Permission denied`, also exit `21`. The third leaves out `--list-directories`, and a listing is answered as if the folder were not there, exit `78`. A refusal is `curl`{apos}s answer, not a tool error: the `curl` tool reports the exit code and the message, and the program prints them.

The last call goes the other way. `list_files` of `surl-mcp` reads a folder of the server{apos}s own store, bypassing the protocol: the file and the two folders the client made are there, each with its kind.
