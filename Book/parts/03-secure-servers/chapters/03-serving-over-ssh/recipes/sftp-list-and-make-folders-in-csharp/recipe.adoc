=== Making SFTP Folders in C#

==== Problem

Your sync client lists remote folders and creates the ones it needs over the Secure Shell (SSH) File Transfer Protocol (SFTP). You want listings refused until they are allowed, then a folder made with a quote command and seen in the next listing, from a C# test with `Surl.Api` and `Curl.Api`.

==== Discussion

`Start` builds a `SurlServerOptions` and starts a `SurlServer` on a free port of the loopback address. `ThrowawayHostKey` makes the SSH host key an SFTP listener needs, for tests only, and `Accounts` holds a `SurlAccount`, Alice's login. `ListDirectories` and `AllowUploads` are the options `--list-directories` and `--allow-uploads`; neither is on by default, and each widens what a client may do. The one file is held in memory, so nothing touches the disk.

`Run` makes one transfer with a `CurlClient`: a `CurlRequest` for the folder's URL, whose answer is a `CurlResponse`, the login in `CurlAuthenticationOptions`, and `VerifyPeer` set to `false` in `CurlTlsPeerOptions`, inside `CurlTlsOptions`, which is what `curl -k` does and here skips the check of the throwaway host key. A GET of a URL that ends in a slash is a listing, and the body is the long listing in the style of Unix `ls -l`; the program prints only the names, the last word of each line. The quote command goes in `Quote` of `CurlFtpOptions`, the one list of commands for FTP and SFTP alike, and runs before the listing, so the first `mkdir /reports` already shows the folder. A command that starts with a dash runs after the transfer, so `-mkdir /archive` does not show `archive` in its own listing and the next call does. The folder is kept by the server, not by the connection. A folder made inside another is listed through the outer path, `/reports/`.

Making a folder that exists throws `CurlException` with code `21`, `QuoteError`, the same code `curl` exits with. So does `mkdir` on the `listing-only` server, which lists but has no `AllowUploads`: a listing works, and making a folder is a change that needs the upload setting. On the `closed` server, where `ListDirectories` is off, the listing is answered as if the folder were not there, and `SendAsync` throws `CurlException` with code `78`, `RemoteFileNotFound`.
