=== Running Out of Space

==== Problem

Your backup tool uploads over File Transfer Protocol (FTP) and must report a full disk instead of claiming success. You want uploads to one folder refused as if the disk were full, the rest of the server working, and nothing half-written left behind.

==== Solution

Run `surl` with an `out-of-space` fault rule scoped to the backups folder, and upload into it:

Then list the folder to show nothing landed. The cases below try the other ways in, and the folders the rule does not cover.

==== Discussion

`--fault "out-of-space;path=/backups"` makes every store under `/backups` fail as a full disk would; the rest of the server has space. `--fault` loosens the server on purpose and is for tests only: a server that misbehaves looks broken to every other client. `--allow-uploads` turns on writing, which `surl` refuses by default; `--allow-anonymous` lets `curl` log in without an account; `--list-directories` lets a folder be listed; `--directory site` serves the folder that already holds last night{apos}s dump.

`-T db.dump` makes `curl` upload the local file under the name in the URL. `surl` answers its `STOR` with `552 Upload exceeds the size limit`, the reply File Transfer Protocol keeps for exceeded storage (<<rfc959>>), and `curl` exits `25`, `Failed FTP upload: 552`. `-s` hides the progress meter and `-S` still prints that error; `-v` shows the reply as it came. A backup tool that checks its exit code reports the failure; one that does not, claims a backup it never made.

Nothing half-written is left: `-l`, which lists names only, finds only last night{apos}s dump in `/backups`. `--append` to that dump is refused the same way, `552`, and the file is unchanged, so a full disk cannot corrupt a file already there either.

The rule covers a path and everything under it, by whole folder names. `--ftp-create-dirs` still makes `/backups/2026`, since a folder is not a store, but the file in it is refused and the new folder stays empty. `/staging` and `/backups-old` are not under `/backups`, and the same upload to either is stored whole, exit `0`.

A server that does not take uploads at all, here one started without `--allow-uploads`, also makes `curl` exit `25`. The reply is `550`, not `552`. The exit code alone cannot tell a closed server from a full one; a tool that wants to say which has to read the reply.
