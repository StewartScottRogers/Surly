=== Limiting the Size of an Upload

==== Problem

You want a Hypertext Transfer Protocol (HTTP) server that turns away an upload bigger than a size you choose, so you can see what your client does when its file is too large.

==== Discussion

`--max-filesize 10` is the largest upload `surl` takes, in bytes; a size may also end in `k`, `M`, `G`, `T` or `P`, each 1024 times the one before. `notes.txt` is 17 bytes, so its `PUT` is answered `413 Content Too Large` (<<rfc9110>>) with `Connection: close`, and nothing of it is stored: the path is `404 Not Found` afterward. `ten.txt` is exactly 10 bytes and is within the limit, so it is stored, `201 Created`. `curl` exits `0` on the `413`, since it is still an answer, unless `-f` asks it to fail on an error status, when it exits `22`.

The limit does not depend on the client saying how big the body is. `-T -` uploads standard input, here `notes.txt` through `<`, and since `curl` cannot know its length it sends the body in chunks (<<curl-manual>>). `surl` counts the bytes as they arrive and refuses this one `413` too, and stores none of it.

The rest of the command is what any upload to `surl` needs (see <<http-accept-uploads>>). `--directory site` is where an upload lands, `--allow-uploads` lets a client write there, and `--user alice:s3cret` gives the account a `PUT` must log in as. `-u alice:s3cret` is the login and `--digest` sends it with HTTP Digest, which never sends the password itself, so `surl` checks it over plain `http://`. `-s` keeps `curl` quiet, `-o` sends the response body nowhere, `-w "%{http_code}"` prints the status, and `-D -` prints the response headers.

The limit is not a loosening, and it is on whether you give it or not: the default is 100M, 100 mebibytes, as `surl --aihelp limits` prints, so the second server, `roomy`, the same command without `--max-filesize`, stores `notes.txt`, `201`. `0` turns the limit off. A test lowers it to see its client refused; a server that should accept large files raises it.

`curl` has a `--max-filesize` option too, and it means the other thing: the largest file `curl` will download (<<curl-manual>>). `surl` kept the name and turned it around. With `curl --max-filesize 10`, fetching the 16-byte `hello.txt` stops before a byte is written, and `curl` exits `63`.
