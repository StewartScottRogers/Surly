=== Refusing an Oversized Request Head

==== Problem

Your client sometimes sends huge cookies, and the real server refuses them. You want a Hypertext Transfer Protocol (HTTP) test server that answers `431` when a request head is over a size you choose, and serves the same request when it fits.

==== Solution

Give `surl` `--max-request-head 1k`, and have `curl` send a request carrying a 1,200-byte cookie, read from a file:

==== Discussion

A request head is the request line and every header line up to the blank line that ends them. `--max-request-head 1k` makes `surl` refuse a head longer than 1,024 bytes with `431 Request Header Fields Too Large`, whatever the request asks for: `hello.txt` is in `site`, which `--directory site` serves, and the answer is still `431`. The size takes the suffixes `k`, `m`, `g`, `t` and `p`, each 1,024 times the one before, and `0` means no limit. A size `surl` cannot read, such as `1x`, is refused at start with exit code `2`.

`-H @big-cookie.txt` makes `curl` read header lines from a file, one a line, instead of from its command line (<<curl-manual>>), which keeps a long cookie off the command line. `big-cookie.txt` holds one line, `Cookie: session=` and 1,200 `x`, so the head is over 1 KiB with nothing else in it; `small-cookie.txt` holds the same with 600, and that request fits and is served. `-w "%{http_code}\n"` prints the status, `-o` sends the body nowhere and `-s` keeps `curl` quiet.

The answer has a short text body that repeats the status line, `Content-Length: 36`, and `Connection: close`: `surl` does not keep the connection for another request, so a client that tries again with a smaller head connects again. `-D -` prints the response headers to show this. To `curl` a `431` is an answer like any other, so it exits `0`; with `-f` it exits `22`, as for any status of 400 or more.

The second server, `roomy`, serves a folder of its own, since one `surl` holds a folder at a time; it has no `--max-request-head` and serves the same 1,200-byte cookie. Its limit is `surl`{apos}s default, 100k, as `surl --aihelp limits` prints. A test that wants to match a stricter real server sets the limit that server has; neither setting loosens anything.
