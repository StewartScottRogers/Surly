=== Refusing Oversized Request Heads in C#

==== Problem

Your client sometimes sends huge cookies, and the real server refuses them. In a .NET test, you want an in-process Hypertext Transfer Protocol (HTTP) server that answers `431` when a request head is over a size you choose, and serves the same request when it fits.

==== Solution

==== Discussion

A request head is the request line and every header line up to the blank line that ends them. `surl` refuses a head over its limit with `431 Request Header Fields Too Large`, whatever the request asks for: `hello.txt` is in `Files`, and the answer is still `431`. `SurlServerOptions` has a property for many of `surl`{apos}s options but none for this limit, so the program puts the option in `AdditionalArguments`, as the two words `surl` takes on its command line. `1k` is 1,024 bytes.

`CurlClient.Create()` makes the client, and `CurlRequest.Headers` holds the extra headers its request sends, in order; the program builds one `Cookie` header of the length given as its first argument. With 1,200 bytes the head is over 1 KiB; with 600 it fits, and the file is served. `SendAsync` returns the `431` as an ordinary `CurlResponse` and throws nothing, as `curl` exits `0` for it on the console. The response has a 36-byte text body, `431 Request Header Fields Too Large` and a newline, and a `Connection: close` header: `surl` does not keep the connection for another request. The program exits `22` for any status of 400 or more, as `curl -f` would; that is the program's choice, not the library's.

With `default` as its second argument the program leaves the option out, and the same 1,200-byte cookie is served under `surl`{apos}s default limit. The default is a limit all the same: a 200,000-byte cookie is over it and gets the same `431`.
