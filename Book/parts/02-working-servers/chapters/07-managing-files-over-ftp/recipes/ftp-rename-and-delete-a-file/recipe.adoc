=== Renaming and Deleting over FTP

==== Problem

You want to rename a file on a File Transfer Protocol (FTP) server, say from `draft.txt` to `final.txt`, and delete another, from a script, and you want to know what the server says when it is not allowed to.

==== Solution

Serve a directory that accepts anonymous logins and uploads, and send the commands with `curl -Q`. Asking for a listing too shows the folder after the rename:

==== Discussion

FTP (<<rfc959>>) renames in two steps: `RNFR` names the file to rename and the server answers `350 Ready for RNTO`, then `RNTO` names the new name and the server answers `250`. `DELE` deletes a file and is answered `250`. `curl` has no option for either; `-Q` (`--quote`) sends any command you give it, one `-Q` for each, in the order given. The quoted commands are the whole task, but `curl` still has a URL to fetch, here the folder, so it lists it; `-l` asks for names only, and `-o` with a null device throws a listing away when you do not want one. `--directory site` serves the files under `site`, which is where the cases read a renamed file back, `-s` keeps the progress meter away, and `-v` shows the commands and their replies.

Where the command goes in the conversation is set by how it starts. A command with no prefix is sent before the transfer, so the listing in the solution already shows the new name. A command prefixed with a dash, as in `-Q "-DELE final.txt"`, is sent after the transfer, so the same listing still shows the file, and the next one does not. Use the dash when the command should follow the work; leave it off when the work should see the result.

A rename onto a name that is taken replaces that file, and `surl` does not ask. A file that is not there is answered `550 No such file`, whether it is the `RNFR` or the `DELE`; an `RNTO` without an `RNFR` before it is answered `503 Send RNFR first`. In each case `curl` exits `21`, quote command failed (<<curl-readme>>). `--list-directories` is on the server so that the cases can list; without it, `surl` refuses a listing.

`--allow-uploads` is what permits changing the store at all. It loosens the server, though `surl` prints no warning for it. A server started without it answers `RNFR` and `DELE` with `550 Not permitted`, `curl` exits `21`, and every file keeps its name. `--allow-anonymous` lets `curl`{apos}s anonymous login in and checks nothing, so it is for a test on your own machine only (<<surl-readme>>); a server started without it refuses the login and `curl` exits `67`, login denied.
