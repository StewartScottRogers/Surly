=== Appending to a File over FTP

==== Problem

You keep a log on a File Transfer Protocol (FTP) server and you want to add lines to the end of it, one upload at a time, without downloading it and without replacing what is already there.

==== Discussion

An FTP upload (<<rfc959>>) normally sends `STOR`, which makes the file the bytes that follow, replacing any file of that name. `--append` makes `curl` send `APPE` instead, which adds the bytes to the end of the file and creates the file when it is not there. `-T second.txt` names the local file whose bytes are sent, and `-s` keeps the progress meter away. `--directory site` serves the files under `site`; the cases read the file back from there, and by downloading it with `curl`.

Only the bytes you send are added. `APPE` does not look at what the remote file ends with, so a file that does not end in a newline has the new text joined to its last line; end each line you append with one. The server does not know your lines are lines either: two appends in a row are one file, and nothing marks where the first stopped.

`-v` shows the commands. With `--append` the line is `APPE audit.txt`, and without it `STOR replace.txt`, which is how to tell which of the two an upload used. `surl` completes an accepted `APPE` as it completes a `STOR`, with `226` when the transfer is done.

`--allow-uploads` is what lets a client write at all. It loosens the server, though `surl` prints no warning for it; without it, `APPE` is answered `550 Not permitted`, `curl` exits `25`, upload failed, and the file is as it was. `--allow-anonymous` lets `curl`{apos}s anonymous login in and checks nothing, which is for a test on your own machine and nowhere a stranger can connect (<<surl-readme>>); a server started without it refuses the login and `curl` exits `67`, login denied.

`--max-filesize` limits the size of a file a client may store. The limit counts the file as it would be after the append, not the bytes of the append: with `--max-filesize 15`, a 12-byte append to an 11-byte file is refused, `curl` exits `70`, remote disk full, and the file keeps its 11 bytes (<<curl-readme>>). A log that grows meets the limit sooner than the size of one line suggests.
