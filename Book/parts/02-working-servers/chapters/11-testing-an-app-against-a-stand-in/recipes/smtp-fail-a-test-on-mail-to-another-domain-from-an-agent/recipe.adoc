=== Failing on Foreign Mail from an Agent

==== Problem

You want an agent that tests an app{apos}s mail to notice when the app mails an address outside your domains, and to say so from the server{apos}s own record: which recipient was refused, and with what reply.

==== Solution

The program starts `surl-mcp` serving your two domains, sends the app{apos}s mails through `curl-mcp`{apos}s `curl` tool, and finds each `550` in `get_exchanges`:

==== Discussion

Both hosts start by name from the path, over standard input and output, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. `start_server` takes `listen_urls`, here one `smtp://` URL on port 0, and `arguments`, `surl`{apos}s own options (<<surl-readme>>): `--mail-domain` twice, for `example.com` and `example.org`, and a `--mailbox` per address, a mailbox and the login named by its whole address.

The `curl` tool runs `curl`{apos}s own arguments and answers in text that is JavaScript Object Notation (JSON), with `exitCode`, `standardOutput` and `standardError`. The app{apos}s send is `-u` its login, `--mail-from` and `--mail-rcpt` the envelope sender and recipient, `-T` a message file from the folder with carriage return and line feed line ends, and `-w "%{response_code}"` the last reply; `-s` and `-S` leave only `curl`{apos}s error line (<<curl-manual>>). Mailing `carol@elsewhere.org` is refused at `RCPT TO`: the tool reports `exitCode` 55 and `curl: (55) RCPT failed: 550`. The app has logged in, but `surl` delivers only to its own domains, so the mail cannot leave the test.

The reply text is in the record. After each send the agent calls `wait_for_event` with `kinds` `exchange_ended`, `scheme` `smtp`, `after_sequence` the last event{apos}s `sequence` and `timeout_ms` 10000, so it reads only a finished exchange. `get_exchanges` with `scheme` `smtp` answers each exchange{apos}s `chunks` in the order they crossed; the line after the app{apos}s `RCPT TO:<carol@elsewhere.org>` is `550 5.7.1 Relaying denied` (<<rfc5321>>). At the end the agent scans every exchange, `max_exchanges` 100, for a `RCPT TO` answered `550`, and has the list of every foreign recipient the app tried.

The match is on the whole domain. A subdomain, `ann@mail.example.com`, is another domain and is refused, as `--mail-domain` matches no subdomains (<<surl-readme>>), and so is a look-alike that merely begins with a served name, `ann@example.com.evil.org`. Letter case is no difference: `ANN@EXAMPLE.COM` is accepted, and `wait_for_event` with `kinds` `store_changed`, `store` `mail` and `name` `ann@example.com` answers the delivery into Ann{apos}s `INBOX`.

Only the envelope{apos}s recipients are judged. A foreign envelope sender, `noreply@elsewhere.org`, mailing Ann is accepted, and so is a message whose `Cc` field names `carol@elsewhere.org` but which is sent to Ann alone: header fields are text, and the server delivers to the envelope. An agent that wants to catch that reads the header of what was delivered (<<smtp-check-an-app-sent-the-right-mail-from-an-agent>>).
