=== Uploading over TFTP

==== Problem

==== Discussion

TFTP has no login, no folders and no listing: a client reads or writes one file by name, over the User Datagram Protocol (UDP), in blocks of 512 bytes, and the transfer ends with the first block shorter than that (<<rfc1350>>). A write is a request to create the file; with `curl -T file URL`, the name in the URL is the name the server keeps, and the local name does not matter. `surl` keeps it under `--directory`, here `site`, and the claim looks in that folder to see the file there with its content. The listener is UDP, so there is no TCP port to wait for; the claims use `ready: none`, and a read-back that would fail if the server were not up.

A write is a change to the server{apos}s files, so `surl` refuses it unless it is started with `--allow-uploads`. Without the option the server answers the write request with an error packet, TFTP error 2, access violation, which `curl` reports as `curl: (69) TFTP: Access Violation` and exit `69`; `-v` prints the packet as `TFTP error: Access violation`. The server keeps nothing: a read of the same name afterwards is TFTP error 1, `File Not Found`, and exit `68`. A read needs no such option, which is why a server meant only to be read from is safe to leave as it is.

With uploads on, `surl` still holds the line on names. A name in a folder, `configs/r1.cfg`, and a name beginning with a dot are both refused with error 2 and exit `69`: TFTP has no folders to make, and a dot file is one `surl` never serves. A name that exists is replaced, as an upload to a file server is. A file of 1,300 bytes, three blocks, goes up in whole and reads back as 1,300 bytes.

`--max-filesize 1000` limits what an upload may be: the 1,300-byte file is refused, `curl` exits `70` (`Disk full or allocation exceeded`), and nothing is kept, so a read of it is exit `68`. The third server in the claims has no `--directory`: two `surl` processes cannot share one directory, and a server without it keeps its files in memory.

On the `curl` side, `-T` is the upload, naming the local file to send; `-s` hides the progress meter and `-S` still shows an error; `-o` names the file a read is saved to, here the null device, and `-w` prints a value after the transfer, here `size_download`, the bytes read.
