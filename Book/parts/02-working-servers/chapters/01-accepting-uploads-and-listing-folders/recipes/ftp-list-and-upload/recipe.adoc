==== Discussion

A File Transfer Protocol (FTP) URL that ends in `/` names a folder, and `curl` asks for its listing instead of a file (<<curl-readme>>). `-l` asks for names only (`NLST`, <<rfc959>>): one name a line, folders without a slash. Without `-l`, `curl` asks for the long listing (`LIST`), which `surl` writes in the style of Unix `ls -l`: permissions, owner, size, date and name, a folder's line starting with `d`. A subfolder is listed by naming it with its trailing slash. Names that begin with a dot, `surl`{apos}s own `.surl` folder among them, are left out of every listing.

`-T notes.txt` uploads the local file to the path the URL names. A URL ending in `/` takes the local file's name, so `-T notes.txt` to `/sub/` stores `/sub/notes.txt`. The upload is the file `site/notes.txt` on disk, and the next listing shows it. Uploading into a folder that is not there fails with exit `9`, remote access denied; `--ftp-create-dirs` makes `curl` create the missing folders first.

Each of the four `surl` options loosens something, and each refusal is the default:

* `--directory site` serves the files under `site`, and takes the uploads.
* `--list-directories` answers listings. Without it, `surl` answers a listing `550 No such directory`, as if the folder were not there, and `curl` exits `19`. A listing tells whoever asks the name of every file, so it is off until asked for.
* `--allow-uploads` accepts uploads. Without it, an upload is answered `550 Not permitted`, and `curl` exits `25`, upload failed. Downloads work either way.
* `--allow-anonymous` logs in every `USER` and `PASS` unchecked, and here it lets in `curl`{apos}s own anonymous login, `USER anonymous`, which `curl` sends when the URL names no user. Without it, that login is refused like any password sent over `ftp://` in clear, `530 Login needs TLS first`, and `curl` exits `67`, login denied, before it lists or uploads anything. It is not the default because anyone who can reach the listener can then do, with no login at all, whatever the other options allow: here read, list and upload into everything it serves. It is acceptable for a test on your own machine; for anything else, use an account and a login protected by Transport Layer Security (see <<ftp-protect-the-login-with-tls>>). `surl` writes a `surl: warning:` line on every start while it is on (<<surl-readme>>).

In the claims below `-s` keeps `curl` quiet, `-v` shows the FTP conversation on standard error, where the `550` and `530` replies are read, and `-o` sends the listing nowhere while the conversation is read.
