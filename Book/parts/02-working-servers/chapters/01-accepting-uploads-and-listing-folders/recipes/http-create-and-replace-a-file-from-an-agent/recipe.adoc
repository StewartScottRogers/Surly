=== Creating and Replacing Files from an Agent

==== Problem

You want an artificial intelligence (AI) agent to upload a file over Hypertext Transfer Protocol (HTTP), replace it, and fail to upload into a missing folder, and to confirm each result from the server's own store rather than trusting the status.

==== Solution

Write the agent's side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts a server with uploads on and an account, uploads with `curl-mcp`{apos}s `curl` tool, and calls `surl-mcp`{apos}s `read_file` after each upload:

==== Discussion

`StdioClientTransport` starts `surl-mcp` and `curl-mcp` by name from `PATH`; `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine both to the folder the program runs in, which holds `report.txt` and `report-v2.txt`. The argument after `--` picks the scenario.

`start_server` takes `surl`{apos}s options in `arguments`: `--user alice:s3cret` is the account an upload logs in as and `--allow-uploads` turns uploads on. `files` seeds `drafts/outline.txt` in memory, which makes a `drafts` folder. The answer is structured: `server_id` names the server for later calls and `bound_urls` holds the real port.

The upload goes through the `curl` tool, which runs `curl` with the `args` list as its command line. The `transfer` tool has no field for a login, so the `curl` tool is the one that can send `--digest -u alice:s3cret` with `-T report.txt`. `-w "%{http_code}"` puts the status in `standardOutput`, after any response body, so the program takes the last line as the status and prints a body if there is one; `exitCode` is `curl`{apos}s exit code. A `-T` file is read from `CURL_MCP_ROOT`.

The three statuses say what happened (<<rfc9110>>): `201 Created` for a path with no file, `204 No Content` for one whose file the upload replaced, and `409 Conflict` for `/archive/report.txt`, whose `archive` folder does not exist; `surl` creates no folders on an upload, and its refusal carries the one-line body `409 Conflict`. To `curl` all three are a finished conversation: `exitCode` `0` and not a tool error, so an agent that only checks for tool errors never notices the `409`. With `-f` added, `curl` exits `22`, drops the body and the call is a tool error, `standardOutput` still holding `409`.

`read_file` reads the server's store directly, not over HTTP, so the agent sees what landed. After the `201` its `text` is the first file; after the `204` it is the second, whole, not appended. After the `409` it is a tool error, `No file at /archive/report.txt.`: nothing was stored.

Uploads are off by default, so a server an agent starts accepts no writes it was not told to. Started without `--allow-uploads`, the same logged-in upload is `405 Method Not Allowed`, with that line as its body, and `read_file` finds no file.
