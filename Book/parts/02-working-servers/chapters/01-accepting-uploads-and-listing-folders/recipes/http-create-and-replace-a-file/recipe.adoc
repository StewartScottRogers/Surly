=== Creating and Replacing a File

==== Problem

Your client uploads files with Hypertext Transfer Protocol (HTTP) `PUT`, and you want to see the three answers it has to handle: `201 Created` for a new file, `204 No Content` when it replaces one, and `409 Conflict` when the file's folder does not exist.

==== Discussion

`--allow-uploads` is what lets `surl` store a `PUT`; `--directory site` puts what it stores on disk, and `--user alice:s3cret` is the account an upload has to log in as. `curl -T <file> <url>` sends the file as the body of a `PUT` to that URL, and `--digest` with `-u alice:s3cret` logs in with Digest. Each `-T` pairs with the URL after it, so one command line makes three uploads, and `-w "%{http_code} %{url.path}\n"` prints one line for each; `-s` hides the progress meter. The other cases send any response body to nowhere with `-o` and print the status alone.

The status says what happened to the file (<<rfc9110>>). `201 Created` means there was no file at the path and now there is. `204 No Content` means there was one and the upload replaced it whole: the server then serves the second upload's bytes, not the first's. The upload does not append to the old file.

`409 Conflict` is `surl` refusing to make a folder for you. Its body is the one line `409 Conflict`, which `curl` prints before the `-w` line; `201` and `204` have no body. `/archive/report.txt` needs a folder `archive` that does not exist, and `surl` creates no folders on an upload, so it stores nothing and the path stays `404 Not Found` afterwards. A path into a folder that does exist, `/drafts/report.txt`, is created as usual. A `PUT` to a path that names a folder, `/drafts`, is `409` as well: a folder is never replaced by a file.

`curl` treats all three as a finished conversation and exits `0`, so a script that only checks the exit code never sees the `409`. `-f` makes `curl` exit `22` on the `409`; `-w` still prints the status.

Uploads are off by default, because a test server that accepts writes is one a stray client can fill. Without `--allow-uploads`, the same logged-in `PUT` is answered `405 Method Not Allowed`, and neither `201` nor `204` can happen.
