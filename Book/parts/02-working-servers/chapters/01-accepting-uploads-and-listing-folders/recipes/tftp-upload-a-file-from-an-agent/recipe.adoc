=== Uploading over TFTP from an Agent

==== Problem

An AI agent has to push a configuration file to a Trivial File Transfer Protocol (TFTP) server it started, check what the server kept, and understand what it said when it refused, using Model Context Protocol (MCP) tools and no shell.

==== Solution

Write the agent{apos}s side as a C# program on the official MCP software development kit (SDK): it starts `surl-mcp` with `--allow-uploads`, uploads with the `curl` tool of `curl-mcp` and `-T`, and reads the file back with `read_file`:

==== Discussion

The program starts both hosts from `PATH`, confined by `SURL_MCP_ROOT` and `CURL_MCP_ROOT` to the folder it runs in, which is where the local files to send are written. The argument after `--` picks the scenario. `start_server` takes `listen_urls` and `arguments`, `surl`{apos}s own words: `--allow-uploads`, with `--max-filesize 1000` for the limit; a server started with neither refuses writes. TFTP runs over the User Datagram Protocol (UDP), and the answer{apos}s `bound_urls` has the port.

The `curl` tool runs `curl` with the arguments given and answers in text, as JavaScript Object Notation (JSON), with `exitCode`, `standardOutput` and `standardError`. `-T r1.cfg tftp://.../router.cfg` is the write (<<rfc1350>>), and `-s -S` keeps the progress meter off the error stream. `surl-mcp`{apos}s `read_file` reads the server{apos}s store directly: `text` is the bytes it holds, and for a name it does not hold the call is a tool error, which the program prints as nothing stored. The `transfer` tool of `curl-mcp` takes only a URL; it reads the same file back, with `statusCode` `0` for TFTP and the bytes in `body`. Uploading to a name that exists replaces the file, and a file of 1,300 bytes, three blocks, is kept whole and downloaded whole.

Refusals come back as `curl` exit codes, so an agent can act on them as a script would. A write to a name in a folder or beginning with a dot, and any write to a server started without `--allow-uploads`, is exit `69`, `TFTP: Access Violation`; a file over `--max-filesize` is exit `70`, `Disk full or allocation exceeded`; and nothing is kept in either case. `get_exchanges` shows the refusal itself: each chunk of the exchange is one datagram, in base64, and the one the server sent with opcode 5 holds the TFTP error code, `2`, access violation.
