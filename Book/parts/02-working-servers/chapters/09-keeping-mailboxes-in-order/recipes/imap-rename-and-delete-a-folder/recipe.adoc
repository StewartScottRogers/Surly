=== Renaming and Deleting a Folder

==== Problem

You want to rename one Internet Message Access Protocol (IMAP) folder and delete another with `curl -X`, and to know what the server says when you rename `INBOX` or a folder that is not there.

==== Discussion

One `surl` with an `imap://` listen URL serves the mailbox. `--mail-domain example.com` serves mail for the domain, and `--mailbox` adds `ann` with the account that logs in by her whole address, which `curl` gives with `-u`; its `folders=Old,Drafts,Keep` option starts the mailbox with those three empty folders (<<surl-readme>>). Without Transport Layer Security `surl` offers only `CRAM-MD5`, which `curl` uses, so no loosening option is needed. The seed uses `-T file URL`, which sends an `APPEND` and returns once the message is stored, so no step waits for delivery.

`-X` sends its text as the IMAP command, and a URL ending in `/` sends it straight after the login, which is right for `RENAME`, `DELETE`, `CREATE` and `STATUS` (<<rfc9051>>). With no `-X`, the same URL is a `LIST`: one line a folder, `INBOX` first and the rest in name order. `--next` runs the second command as its own transfer in the same `curl`, and `-s` keeps the progress meter off. `RENAME Old Archive` prints nothing and the list shows `Archive` where `Old` was. The folder keeps its messages, two in `Archive`, and `STATUS Old (MESSAGES)` is now `NO [NONEXISTENT] Mailbox does not exist`, with `curl` exit `21`, its code for a command the server refused. `-v` shows the server{apos}s line, and `-S` keeps `curl`{apos}s own error line when `-s` is on.

`DELETE Drafts` removes the folder, and the list no longer has it. A second `DELETE Drafts`, like a `RENAME` of a folder that does not exist, is answered `NO [NONEXISTENT]`. A `RENAME` onto a name already in use, `Keep` to `Archive`, is `NO [ALREADYEXISTS] Mailbox already exists`, and neither folder changes. `DELETE INBOX` is refused with `NO [CANNOT] INBOX cannot be deleted`.

`RENAME INBOX` is not refused, and this is what the standard asks for: it moves the messages of `INBOX` into the new folder and leaves `INBOX` in place and empty. After `RENAME INBOX Mail2025`, `STATUS INBOX (MESSAGES)` answers `0` and `STATUS Mail2025 (MESSAGES)` answers `1`.

`DELETE` does not ask about what is inside. `Archive` holds two messages, `DELETE Archive` exits `0`, and `STATUS Archive` then answers `NO [NONEXISTENT]`: the messages went with the folder, and a test that cares must copy them out first.

A name with a slash is a folder under a parent. `RENAME Keep Work/Notes` lists `Work/Notes` and, above it, `Work` with the flags `\Noselect \HasChildren`: the parent is only implied by the path, not a folder of its own, so `DELETE Work` is answered `NO [NONEXISTENT]`.
