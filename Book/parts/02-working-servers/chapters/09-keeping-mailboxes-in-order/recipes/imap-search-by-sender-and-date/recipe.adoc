=== Searching by Sender and Date

==== Problem

You want the messages from one sender since a given date, over Internet Message Access Protocol (IMAP), and then to fetch just those messages.

==== Solution

Put the search in the query of the folder{apos}s URL, `INBOX?FROM%20shop%20SENTSINCE%2001-Jun-2026`, and fetch the numbers it answers with a second transfer:

The two seed lines stand in for the mail arriving: four messages come in one session, and the second line waits until the fourth is in.

==== Discussion

One `surl` with an `smtp://` and an `imap://` listen URL serves both over one mail store (<<surl-readme>>). `--mail-domain example.com` serves mail for the domain and `--mailbox` adds `ann` with the account that logs in by her whole address, which `curl` gives with `-u`. The first seed line sends the four files in one Simple Mail Transfer Protocol session: `-T "mail[1-4].eml"` is a `curl` glob, `--crlf` gives each line the carriage return and line feed mail needs, and `--mail-from` and `--mail-rcpt` are the envelope. Each file carries a `From:` and a `Date:` header, which is what the searches read. Delivery is asynchronous, so the second line waits with a bound instead of a fixed pause: `-o` sends the answer to the null device, and `FETCH 4 FLAGS` on a message that is not there is refused (`curl` exit `21`), `--retry 10` allows ten more tries, `--retry-all-errors` lets it retry an error that is not a network one, and `--retry-delay 1` spaces them a second apart. The login needs no loosening option: without Transport Layer Security `surl` offers only `CRAM-MD5`, which `curl` uses.

A query on an IMAP URL is a `SEARCH`, and the answer is `* SEARCH` and the numbers of the messages that match (<<rfc9051>>). `%20` is a space, because a URL has none. `FROM shop` matches part of the `From` header in any letter case: `shop` and `SHOP` both name messages 1, 3 and 4. It reads the whole header, display name included, so `FROM "Shop Team"` names message 4 alone, where the header is `Shop Team <shop@example.com>`.

Dates come in two kinds. `SINCE` and `BEFORE` compare the day the server received a message. All four messages arrived today, so `SINCE 01-Jan-2020` names all of them and `SINCE 01-Jan-2099` names none; the answer is the line `* SEARCH` with no numbers, and `curl` exits `0`, so a script reads the line and not the exit code. `SENTSINCE` and `SENTBEFORE` compare the `Date` header, which is the date the sender wrote: `01-Jul-2026` splits the mailbox into messages 3 and 4 on or after it and messages 1 and 2 before it. A message you want by when it was sent needs the `SENT` form. A date is day, month name and year; `SENTSINCE 2026-11-03` is answered `BAD Invalid arguments`, and `curl` exits `21`, its code for a command the server refused. `-v` shows the server{apos}s line, `-S` keeps `curl`{apos}s own error line when `-s` hides the progress meter, and `--next` runs the second command as its own transfer in the same `curl`.

Criteria in one search must all hold. `FROM shop SENTSINCE 01-Jun-2026 SENTBEFORE 01-Oct-2026` names message 3 alone. `OR` takes the next two criteria and names a message meeting either: `OR FROM bank FROM Team` names 2 and 4.

The solution does the two steps of the task. The search names 3 and 4, and the second transfer fetches `INBOX;UID=[3-4]`, a `curl` glob for two messages, with `;SECTION=HEADER.FIELDS%20(FROM%20SUBJECT)` to ask for those two headers only. Fetching sets the `\Seen` flag, because `curl` asks for `BODY[...]` and not `BODY.PEEK[...]`.

A search answers message numbers, and they change. After message 1 is marked `\Deleted` and expunged, the same `FROM shop` search answers `2 3`, the numbers having closed up. The `UID` form, sent with `-X "UID SEARCH FROM shop"`, answers UIDs, which never move: `3 4`. `;UID=3` in a fetch URL takes a UID, so a program that fetches what it searched should search with `UID SEARCH`; fetching `INBOX;UID=3` gives message 3{apos}s `Subject`, `Order 2`.
