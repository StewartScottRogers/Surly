=== Browsing a Queue

==== Problem

Your test needs a queue that already holds work, and you want an agent to put messages on a queue declared at start and list them with `browse_queue` without consuming any.

==== Solution

The program starts `surl-mcp` and a broker with `--queue jobs`, puts three jobs on the queue with `publish_message`, and lists them with `browse_queue`, twice:

==== Discussion

The program starts `surl-mcp`, the Model Context Protocol (MCP) server for `surl`, by name from the path, over standard input and output, confined to the program{apos}s folder by `SURL_MCP_ROOT` (<<mcp-spec>>). The agent here is its own client, so it needs no `curl-mcp`. `start_server` takes `listen_urls`, here one Message Queuing Telemetry Transport (MQTT) listener on a free port, and in `arguments` `surl`{apos}s own options: `--queue jobs` declares the queue `jobs` on the server{apos}s message bus from the start (<<surl-readme>>). It answers a `server_id`.

`publish_message` with `queue` puts one message on that queue, its `payload` the text, and answers `{"published":true}`; it is the test{apos}s own seed, so no client logs in. `browse_queue` takes the `queue`, and answers `messages`, each with a `position`, the `text` of its payload and its `headers`, in delivery order, with `ready_count`, the messages waiting, `in_flight_count`, those delivered and not yet acknowledged, and `has_more`. The three jobs are at positions `0`, `1` and `2`, `ready_count` `3` and `in_flight_count` `0`, and a second browse answers the same: browsing takes nothing off the queue.

A page is a window. With `limit` `2` the answer holds positions `0` and `1` and `has_more` is true; the agent passes the last position it saw as `after_position` and gets position `2` with `has_more` false. A payload that is not text, given as `payload_base64`, is listed with `base64` in place of `text`, here `AP8QgA==`.

A queue is not a topic. `publish_message` with `topic` `jobs` and `retain` true publishes to the MQTT topic of that name, and the queue stays empty, `ready_count` `0`; `read_retained_message` of `jobs` finds the message there, with its quality of service, `qos`, `0`.

The queue must be declared. On a broker started without `--queue jobs`, `publish_message` to it is a tool error, `Bus: A message for queue jobs was refused: UnknownQueue.`, and `browse_queue` is the tool error `No queue jobs.`, which is how an agent learns the name is wrong. `reset_server` returns the server to its state at start: the queue is still there, and empty, `ready_count` `0` and no messages, a result and not an error.
