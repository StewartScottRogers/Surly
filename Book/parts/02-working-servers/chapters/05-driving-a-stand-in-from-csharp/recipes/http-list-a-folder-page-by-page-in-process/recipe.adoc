=== Listing a Folder Page by Page

==== Problem

Your C# test checks a folder of hundreds of files on a stand-in server, and a listing of all of them at once is too much to read or to hold. You want to page through it with `Files.ListAsync`, `afterName` and `HasMore`, straight from the server{apos}s store with no client in the way.

==== Solution

Start a `SurlServer` with the files seeded, then ask `ListAsync` for a page and ask again, with the last name seen as `afterName`, until `HasMore` is false. The program takes the case to run as its argument; the first case, with none, is 250 files in pages of 100:

==== Discussion

`SurlServerOptions` is `surl`{apos}s command line as properties. `Files` seeds the store in memory before the server starts: here `logs/log-001.txt` to `logs/log-250.txt`. The program starts an `http://` listener on port `0` because a server needs one, and sends no request to it. `server.Files` is the `SurlServerFiles` view of the store, and `ListAsync` takes the folder{apos}s path with its leading slash, `afterName`, and a limit from 1 to 1000. It reads the store directly: it needs no listing option, publishes no event and asks no fault rule (<<surl-readme>>).

The result is a `SurlFolderPage`: `Entries`, a list of `SurlFolderEntry` with a `Name`, `IsFolder` and `ByteCount`, and `HasMore`. The first call passes `null` for `afterName` and gets the first 100 names. `HasMore` is true, so the test calls again with `Entries[^1].Name`, the last name on the page, and gets the next 100. The third page has 50 entries and `HasMore` false, and the loop ends. Over the three pages the test has seen 250 different names, in ordinal order. When the folder holds an exact multiple of the limit, 200 files, the second page already says `HasMore` false, so the loop makes no call for an empty page.

The order is ordinal: by code unit, not by language or case, so `10.txt` comes before `2.txt` and capitals before lower case. A test that compares a listing with its own list sorts it with `StringComparer.Ordinal`. A subfolder is an entry among the files, `IsFolder` true with no size, and a file{apos}s `ByteCount` is its size in bytes.

`afterName` is a position and not a count. A page that starts after `d.txt` holds the names that sort after it, whatever happened since the last call: a file added before the cursor does not show in the next page, and one added after it does. A limit of 0 or 1001 is refused with `SurlReadRefusedException`, and a folder that is not there throws `SurlNotFoundException`.
