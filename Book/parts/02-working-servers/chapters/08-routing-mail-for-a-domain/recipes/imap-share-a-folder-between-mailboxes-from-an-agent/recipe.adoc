=== Sharing an IMAP Folder from an Agent

==== Problem

You want an agent to log in as each mailbox on a test mail server in turn and confirm who sees a shared Internet Message Access Protocol (IMAP) folder and who does not.

==== Solution

The program starts both hosts and an IMAP server that shares a folder between two of three mailboxes, appends a message to it as one member, then logs in as each mailbox with the `curl` tool and reports whether the folder is listed and what `STATUS` says of it:

==== Discussion

`start_server` takes the listen URL and, in `arguments`, `surl`{apos}s own options (<<surl-readme>>): `--mail-domain example.com` serves the domain, each `--mailbox` adds a mailbox and the account that logs in to it by its whole address, and `--shared-folder team=ann@example.com,bob@example.com` shares one folder, `team`, with Ann and Bob. Carol has a mailbox and is not a member. It answers a `server_id` and the `bound_urls`.

The `curl` tool runs `curl`{apos}s own arguments and answers `exitCode`, `standardOutput` and `standardError` as JSON; a non-zero exit makes the call a tool error, with the same JSON. First Ann appends the rota: `-T rota.eml` on an IMAP URL is an `APPEND` to the folder the URL names, `Shared/team`, from a fixture in the folder both hosts are confined to (<<curl-manual>>). `-u` is the login, `-s` keeps the progress meter out and `-S` keeps an error in.

Then the agent takes each mailbox in turn, with two calls. A URL with no folder is a `LIST`, and the agent looks for a line ending ` Shared/team`. `-X "STATUS Shared/team (MESSAGES)"` asks for the folder{apos}s count without opening it. Ann and Bob both list it and both count the one message Ann put there: the folder is stored once for its members. Carol{apos}s `LIST` does not name it, and her `STATUS` is refused, `curl` exit `21`, quote command returned error; reading its first message instead exits `67`, `Select failed`. To her the folder does not exist, which is the default, and no option opens it to someone the list leaves out (<<rfc9051>>).

`list_mailboxes` is the same check from the server{apos}s side: it names each owner{apos}s mailboxes, and `Shared/team` appears under Ann and Bob and not under Carol. An agent that only reads the store can check membership without logging in as anyone; one that logs in, as here, checks what each user{apos}s client will be shown.

Membership is fixed when the server starts, and `surl` checks it then. With Bob{apos}s address misspelt as `bobb@example.com`, `start_server` is a tool error whose structured content has `exit_code` `2` and, in `lines`, `option --shared-folder: member bobb@example.com names no account or group`, so an agent can read which member to fix and start again.
