=== Serving Two Mail Domains

==== Problem

You want one `surl` to take mail for two domains, keep `ann@one.test` and `ann@two.test` apart in mailboxes of their own, and refuse a third domain with `550`.

==== Solution

Give `--mail-domain` once for each domain and a `--mailbox` for each address, then send each brand{apos}s mail and read each Ann{apos}s mailbox over Internet Message Access Protocol (IMAP). The one command sends both and reads both subjects once the mail has arrived:

==== Discussion

`--mail-domain` is repeatable, and each one adds a domain the server takes mail for (<<surl-readme>>). `--mailbox` adds a mailbox and the account that logs in to it, and both are named by the whole address, so `ann@one.test` and `ann@two.test` are two mailboxes with two passwords that share nothing but a first name. Each brand sends as its own `noreply` mailbox. `-v` and `--log-file surl.log` keep the verbose log in a file, which two cases read with a short script that waits, at most ten seconds, for the line it wants.

The sends are `curl` with `-u` for the login, `--mail-from` and `--mail-rcpt` for the envelope (<<rfc5321>>), `-T` for the message and `--crlf` for its line ends; `-s` keeps `curl` quiet and `-S` lets it still print an error, `-o` throws a body away and `-w "%{response_code}"` prints the last reply, and `--next` starts the next transfer with its own options. Delivery is asynchronous, so each read retries until the message exists, `--retry 10` more tries, `--retry-all-errors` to retry the error a missing message gives, `--retry-delay 1` a second apart. `INBOX;UID=1;SECTION=HEADER.FIELDS%20(SUBJECT)` fetches the message{apos}s subject alone (<<rfc9051>>): One{apos}s welcome in `ann@one.test`, Two{apos}s in `ann@two.test`, and `STATUS INBOX (MESSAGES)`, sent with `-X`, counts one message in each.

A login names the whole address too. `ann@two.test` with the password of `ann@one.test` is refused, and so is `ann` with no domain, both with `curl`{apos}s `67`, `Login denied`. One message may name addresses in both domains: Bo has a mailbox in each, and each gets its own copy.

A recipient outside every `--mail-domain` is refused at `RCPT` with `550`, and `curl` exits `55` with `RCPT failed: 550`; the log gives the reason, `outside every --mail-domain`. A server that took mail for any domain would be an open relay, passing on whatever a stranger gave it, so the refusal is the default. A domain is matched whole: `mail.one.test` is not `one.test`, and `ann@mail.one.test` is refused the same way. An address of a served domain that has no mailbox is a different case: it is answered `250` and the message discarded, which the log records as `discarded: no such account`, so a sender cannot use the server to learn which addresses exist.
