=== Starting Mailboxes with Folders from an Agent

==== Problem

You want an agent to start a mail server whose mailboxes already hold Sent, Drafts and Archive, and to confirm the folders are there with `list_mailboxes` and over Internet Message Access Protocol (IMAP).

==== Solution

The program starts `surl-mcp` and `curl-mcp`, starts a server with `folders=` on the mailbox, and lists the folders from the store and over IMAP:

==== Discussion

Both hosts start by name from the path, over standard input and output, each confined to the program{apos}s folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. `start_server` takes `listen_urls`, one `imap://` URL on port 0, and `arguments`, `surl`{apos}s own options, one array element each (<<surl-readme>>). `--mail-domain example.com` serves the domain. `--mailbox ann@example.com:annpass;folders=Sent,Drafts,Archive` adds a mailbox whose whole address is the login, and the key after `;` creates the three folders beside `INBOX` before the server listens; no shell is involved, so the `;` needs no quoting. `bob` gets the same list, `carol`{apos}s mailbox has no `folders=`, and `dave` and `erin` show what a name may hold. The answer carries the `server_id` and the `bound_urls`.

`list_mailboxes`, given the `server_id` and the `owner`, answers each folder with its `name` and `message_count`, in ordinal order of name: `Archive`, `Drafts`, `INBOX`, `Sent`, all empty. The `curl` tool runs `curl`{apos}s own arguments and answers in text that is JavaScript Object Notation (JSON); an IMAP URL with no folder lists the account{apos}s folders, one `* LIST` line each in `standardOutput`, with `INBOX` first (<<rfc9051>>). `-s` drops the progress meter, `-S` keeps any error, and `-u` logs in; without Transport Layer Security `surl` offers only `CRAM-MD5`, which `curl` uses. `carol` lists `INBOX` alone, and `-X "STATUS Sent (MESSAGES)"` answers `MESSAGES 0` for `ann`.

Names may hold more than letters. `dave`{apos}s `Sent Items` keeps its space and `LIST` quotes it; `Archive/2026` is nested, since `/` is the separator, and its parent `Archive` appears though `dave` never named it, marked `\Noselect \HasChildren`, a name that only holds other folders. A `,` would end a name, so `erin`{apos}s `folders=Paid%2CUnpaid` writes it `%2C` and makes one folder, `Paid,Unpaid`.

The folders are ordinary folders, and each mailbox{apos}s own. The program writes `sent.eml` into the folder, with the carriage returns and line feeds mail needs, and `-T sent.eml` on `.../Sent` files it in `ann`{apos}s `Sent` with an IMAP `APPEND`: her count is `1`, and `bob`{apos}s `Sent` is still `0`. A client may delete a start folder too: after `-X "DELETE Drafts"` her list is `INBOX`, `Archive`, `Sent`.

A reset starts the mailboxes over. `seed_mail` delivers a message to `ann`{apos}s `INBOX`; `reset_server` then empties every mailbox and puts the start folders back, the deleted `Drafts` included, for `ann` and `bob` alike. An agent can run test after test on one server and each starts with the same folders, whatever the last test did to them.

`surl` checks the list before it listens. Naming `Sent` twice makes `start_server` a tool error whose structured content carries `exit_code` `2`, `exit_code_name` `FailedInit`, and the message `option --mailbox: member Sent is given twice` in `lines`; `folders=` with nothing after it fails the same way with `key folders needs a value`.
