=== Sharing a Folder Between Mailboxes

==== Problem

You want a team folder that two mailboxes on your test mail server can both read, with `--shared-folder`, and to check that a third mailbox cannot see it.

==== Solution

Name the folder and its members with `--shared-folder` when `surl` starts, then append a message to it as one member and read it back as the other:

==== Discussion

The server serves the Internet Message Access Protocol (IMAP) for `example.com`: `--mail-domain` is the domain and each `--mailbox` adds a mailbox and the account that logs in to it by its whole address, Ann{apos}s, Bob{apos}s and Carol{apos}s (<<surl-readme>>). `--shared-folder team=ann@example.com,bob@example.com` creates one folder, `team`, and gives it to the two members named. A member can also be a group: `--group oncall=bob@example.com,carol@example.com` names one, and `--shared-folder ops=@oncall` shares a second folder with everyone in it. The leading `@` matters; `ops=oncall` is looked up as an account, and `surl` refuses to start.

The solution is two transfers joined by `--next`, each with its own `-u` login. `-T rota.eml` on an IMAP URL is an `APPEND` to the folder the URL names, `Shared/team` (<<curl-manual>>). The second transfer logs in as Bob and fetches `Shared/team;UID=1`, and gets Ann{apos}s message: the folder is stored once, not copied into each mailbox. `-s` keeps `curl` quiet and `-S` still shows an error. The fixture{apos}s lines already end in a carriage return and line feed, which mail needs, because an append states the message{apos}s size before sending it.

A member sees the folder under `Shared`. A `curl` with no folder in the URL is a `LIST`: Ann{apos}s shows her `INBOX`, a `Shared` folder marked `\Noselect`, which holds folders and no mail, and `Shared/team`. Bob, a member of both, sees `Shared/ops` and `Shared/team`; Carol, through the group, sees `Shared/ops` only. An IMAP client learns where shared folders live from `NAMESPACE` (<<rfc9051>>). `-X "STATUS Shared/team (MESSAGES)"` asks for the count without selecting the folder: one, for Bob.

To Carol, `Shared/team` does not exist. Her read of it fails with `curl` exit `67`, `Select failed`, and `-v` shows the server{apos}s answer to her `STATUS`, `NO [NONEXISTENT] Mailbox does not exist` (exit `21`, quote command returned error): the answer for a folder that is not there at all, so a non-member cannot tell a folder she may not open from one that was never made. That is the default and no option changes it; membership is what `--shared-folder` says when the server starts.

`surl` checks the list at start. A member that names no mailbox or group, a misspelt `bobb@example.com` here, stops it with exit `2` and the member named, so a typo cannot quietly leave someone out. A folder named twice is refused too, `shared folder team is given twice`; its members go in one list.
