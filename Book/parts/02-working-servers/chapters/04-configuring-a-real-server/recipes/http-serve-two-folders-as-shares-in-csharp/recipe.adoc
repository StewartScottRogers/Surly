=== Serving Two Folders as Shares in C#

==== Problem

Your C# test needs two real folders served over Hypertext Transfer Protocol (HTTP), one readonly and one that takes uploads, and it needs to see that a second server is let onto one of them and not the other.

==== Discussion

`SurlServerOptions` is the options of `surl` as properties. `Shares` is the list behind `--share`, one `name=folder` string each, with the flags after a `;`: `"docs=" + docs + ";readonly"` is `--share "docs=docs;readonly"`. `AllowUploads` is `--allow-uploads` and `AllowAnonymous` is `--allow-anonymous`. `SurlServer.StartAsync` starts the server, `ListenUrls` of `http://127.0.0.1:0` takes a free port, and `server.BoundUrl` is the address it got. The folders are in the system temporary folder under a name no other run uses.

`CurlClient` and `CurlRequest` are the client. A `GET` is read through `CurlResponse.Body`; a `PUT` is a `CurlRequest` with a `Body` of bytes. A `403` or a `201` is a response, not an exception, so the program reads `StatusCode`. An upload into the readonly share is refused `403 Forbidden` although `AllowUploads` is on, and no file is made; the same upload into `/data/` is `201 Created` and the file is in the folder on disk.

`surl` keeps a lock on a folder it may write to. A second `SurlServer` on the writable folder fails to start with a `SurlServerStartException`, whose `Lines[0]` is what `surl` would write after `surl: `, `(124) Directory data is in use by another surl process`; as a process it would exit `124`. A second server on the readonly folder starts and serves the same file, since a readonly share takes no lock. Both servers here live in one process and still exclude each other, so the lock is not a matter of processes.
