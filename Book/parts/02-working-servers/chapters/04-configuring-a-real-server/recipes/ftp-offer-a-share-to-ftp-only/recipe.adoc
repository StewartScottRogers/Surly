=== Offering a Share to FTP Only

==== Problem

You want a folder served as a share to File Transfer Protocol (FTP) clients only. The same `surl` also answers Hypertext Transfer Protocol (HTTP), and a drop folder meant for an FTP job should not be reachable there.

==== Solution

Name the folder with `--share` and limit it with `protocols=ftp`; the quotes keep a shell from ending the command at the `;`:

==== Discussion

`--share "drop=drop;protocols=ftp"` serves the folder `drop` on disk as the top-level folder `/drop/` of the served files, so `drop/report.txt` is `ftp://127.0.0.1:2121/drop/report.txt`. The folder must already exist; `surl` creates none. `protocols=` lists the schemes that may reach the share, and every other scheme is answered as though the share were not there (<<surl-readme>>). Over HTTP the path is `404 Not Found`, as for a path that never existed. The folder itself, `/drop/`, is answered `404` too.

A share with no `protocols=` is reached by every server that serves files. `public` is one: its file is read over FTP and over HTTP, which also shows that the `404` for `drop` is the share{apos}s limit and not a fault in the HTTP listener. The three listen URLs, FTP, HTTP and FTPS, are on one `surl`, so `--share` applies to all of them; each is TCP and needs its own port.

`protocols=` admits the secure twin of each scheme it names. `protocols=ftp` therefore also serves `ftps`, FTP over Transport Layer Security (TLS), and the case reads the same file from the FTPS listener. `--self-signed` makes `surl` generate a throwaway certificate for it, and `curl` needs `-k` to accept one; both are for a test on your own machine only.

A value that names no scheme stops the start with exit `2`: `surl: option --share: unknown scheme nope`. Nothing is served until the command line is right.

`--list-directories` lets the FTP server list folders, which `surl` does not do unless asked; with `-l`, `curl` prints the names of the root one a line, `drop` and `public`, the two shares, since a share is a top-level folder. `--allow-anonymous` lets `curl`{apos}s anonymous login in and checks nothing, so it is for a test on your own machine only. `-s` keeps the progress meter away, and `-o` with `-w "%{http_code}"` prints only the HTTP status.
