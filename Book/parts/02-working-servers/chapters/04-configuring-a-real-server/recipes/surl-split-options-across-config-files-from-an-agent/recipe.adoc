=== Splitting Config Files from an Agent

==== Problem

An AI agent wants to start a server from a base set of options plus the changes for one test and a last set of overrides, and to know which setting wins, using Model Context Protocol (MCP) tools.

==== Solution

`surl-mcp` takes no config file, so the agent keeps each layer as a list of arguments, as a file{apos}s lines would be, and passes them to `start_server` in order, base first. A C# program on the official MCP software development kit (SDK) does it and reads the result with the `curl` tool:

==== Discussion

`start_server` refuses `-K`: a config file could name paths the host never checks, so the call is a tool error and nothing listens. The layers are the file{apos}s lines as arguments instead: `--user tester:secret`, `--max-filesize 100` and the rest for the base, `--max-filesize 10 --user second:pw` for the test. The rule is the one of the console recipe: arguments are read in order and the last one on an option that takes one value wins. The files of the other recipes are not needed. The server serves the one file the agent gave in `files`, from memory, and HTTP and FTP share its store.

With the base then the test layer, the later limit, 10, wins: a 21-byte `PUT` through the `curl` tool is `413` and an 8-byte one `201`, and over FTP the 21-byte upload is exit `70`. The layers the other way round give the base{apos}s 100, and the 21-byte upload is accepted. A last layer, `--max-filesize 5`, beats both; the same arguments placed before the others lose to them. `--no-allow-uploads` in a last layer cancels the base{apos}s `--allow-uploads`: `405`. Not everything is replaced: `--user` adds an account, so `second` logs in beside `tester`, and with an account configured a request without a login is `401`. An 8-byte file uploaded over FTP is found by `read_file` in the store the HTTP server serves.

`curl` runs with `-s -S -u tester:secret -T mid.txt -o copy.txt -w "%{http_code}"`, the local files written into the folder both hosts are confined to by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`, and the status is the standard output. A mistake in a layer, `--max-filesise`, is a tool error whose text is `surl`{apos}s own line.
