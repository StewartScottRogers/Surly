=== Offering FTP-only Shares from an Agent

==== Problem

You want an artificial intelligence (AI) agent to find out by trying which schemes reach a share that is offered to File Transfer Protocol (FTP) only, and to report the ones that do not.

==== Solution

Write the agent{apos}s side as a C# program on the official Model Context Protocol (MCP) software development kit (SDK): it starts `surl-mcp` and `curl-mcp`, calls `start_server` with an FTP, an HTTP and an FTPS listener and a share limited to FTP, then calls `curl` on the same path through each:

==== Discussion

`surl-mcp` and `curl-mcp` are the two programs{apos} MCP servers; the program is the agent{apos}s MCP client, and `StdioClientTransport` starts each by name from `PATH`. `SURL_MCP_ROOT` and `CURL_MCP_ROOT` confine each to the folder the program runs in, as environment variables rather than arguments because on Windows the SDK starts a host through `cmd.exe`, which mangles a path with a space in it. The argument after `--` picks the scenario; with none, the program runs the solution. Before it starts either host the program makes the two folders the shares serve, `drop` and `public`, in that folder.

`start_server` starts a server that answers as `surl` with the same options would. `listen_urls` holds an FTP, an HTTP and an FTPS URL, port 0 for a free port each, and the answer is structured content with `server_id` and `bound_urls`, the real addresses in that order. `arguments` is `surl`{apos}s other options in its own words: `--share "drop=drop;protocols=ftp"` serves the folder as `/drop/` to FTP only, and `--share public=public` serves another to every scheme. The folders must exist; `surl` creates none. `--self-signed` is a throwaway certificate for FTPS, `--allow-anonymous` lets an anonymous login in and checks nothing, and `--list-directories` lets the FTP server list folders; all three are for a test on your own machine only.

`curl` runs `curl` with `args` as its command line, and the answer is JSON text with `exitCode` and `standardOutput`. An agent that wants to know whether a scheme reaches a path needs a plain test, and `-f` gives one: a `404` makes `curl` exit `22` and a missing FTP file exits `78`, where a success is `0`. `-s` keeps the progress meter out and `-k` accepts the throwaway certificate. Over FTP and FTPS the file is read; over HTTP the same path is a refusal, so the program reports `http` as the one not reached. `protocols=` admits the secure twin of each scheme it names, which is why FTPS reaches a share named for `ftp`.

Without `-f`, the status is plain: `-o got.txt -w "%{http_code}"` prints `404` for `/drop/report.txt` and for the folder `/drop/`, as for a path that never existed. The other share, with no `protocols=`, is read over HTTP and over FTP, which is how the agent knows the `404` is the share{apos}s limit and not a fault in the HTTP listener. `-l` on the root URL lists names one a line, `drop` and `public`, so the share is visible to FTP clients, which is what it is for.

A value that names no scheme is a mistake in the arguments, and `start_server` answers with a tool error whose first line is `surl: option --share: unknown scheme nope`. No server runs, and so the agent reads the error before it asks for a URL.
