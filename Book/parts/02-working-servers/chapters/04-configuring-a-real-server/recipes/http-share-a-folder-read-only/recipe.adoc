=== Sharing a Folder Read-Only over HTTP

==== Problem

You want one folder on disk served over Hypertext Transfer Protocol (HTTP) as a read-only share that only named accounts can see, beside a served root that takes uploads.

==== Discussion

`--share "docs=docs;readonly"` serves the folder `docs` on disk as the top-level folder `/docs/` of the served files, so `docs/guide.txt` is `http://127.0.0.1:8080/docs/guide.txt`. The folder must already exist; `surl` creates none, and a share whose folder is missing stops the start with exit `37`. The `;` separates the share from its flags, which is why the argument is quoted: a shell would otherwise end the command there.

`readonly` refuses every write into the share, whatever else is allowed. Here `--allow-uploads` is on and Alice's grant is `rw`, and an upload into `/docs/` is still answered `403 Forbidden`, with nothing written; the same upload to the served root, `--directory site`, is accepted `201 Created`. `--allow-uploads` turns uploads on for the whole server, and `readonly` takes them back for one share.

`--share-access docs=alice:rw` says who may use the share: `r` grants reading and `rw` writing too, though a write still needs `--allow-uploads` and a share without `readonly` (<<surl-readme>>). A share with a `--share-access` is closed to every account it does not name. Bob, logged in with a good password, is answered `404 Not Found` for `/docs/guide.txt`, as if the share were not there, which tells him nothing about what it holds; he still reads `/hello.txt` from the root, which no `--share-access` closes. A member that names no account stops the start with exit `2`.

Two `--user` accounts are configured, and once any account is, every HTTP request needs a login: a request with none is answered `401 Unauthorized`. `curl` logs in with HTTP Digest, `--digest`, as the account `-u alice:secret` names; Digest sends no password in clear, so it is accepted over plain `http://`. `-T notes.txt` uploads a file with `PUT`; `-s`, `-o` and `-w "%{http_code}"` print only the status code.
