=== Serving Two Folders as Shares

==== Problem

You have two folders on disk and you want them served over Hypertext Transfer Protocol (HTTP) at `/docs/` and `/data/`, one of them readonly. You also want to know what happens when a second `surl` is pointed at the same folders.

==== Solution

Give each folder to `--share` as `name=folder`, and add `readonly` after a `;` for the one that must not change:

==== Discussion

`--share "docs=docs;readonly"` serves the folder `docs` as the top-level folder `/docs/` of the served files, and `--share data=data` does the same for `data`. The option is repeatable, one for each share, and `docs/guide.txt` is `http://127.0.0.1:8080/docs/guide.txt`. A share needs no `--directory`; the shares are all there is to serve. The `;` separates a share from its flags, which is why the first is quoted: a shell would otherwise end the command there.

`readonly` refuses every write into the share. Here `--allow-uploads` is on for the whole server and `--allow-anonymous` lets the upload in without a login, and still an upload into `/docs/` is answered `403 Forbidden` and nothing is written, while the same upload into `/data/` is answered `201 Created` and the file appears in the folder on disk. `--allow-anonymous` makes `surl` write a `surl: warning:` line on start; this recipe uses it only to keep the login out of the way (<<http-share-a-folder-read-only>> puts accounts and grants on the same shares).

`surl` keeps a lock on a folder it may write to, so that two servers do not change one folder at once. A second `surl` asked for the writable `data` is refused at start with `surl: (124) Directory data is in use by another surl process`, and exits `124`. A readonly share takes no lock, since it cannot change anything, so a second `surl` serves `docs` while the first does, and answers the same file. The lock is for the writable case; a folder the first server holds only for reading is free to read from a second.

`curl` fetches two URLs in one command, `-T` uploads a file with `PUT`, and `-o`, `-w "%{http_code}"` and `-s` print only the status code. The second server in the Solution is a separate `surl` on its own port.
