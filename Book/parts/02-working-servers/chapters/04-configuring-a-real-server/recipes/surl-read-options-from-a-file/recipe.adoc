[[surl-read-options-from-a-file]]
=== Reading surl's Options from a File

==== Problem

Your `surl` command line has grown accounts, a mail domain and a mailbox, and you want them in a file you can keep and edit, the way `curl -K` reads its options.

==== Solution

Write the options into `surl.cfg`, one per line, and start `surl` with `-K surl.cfg` and the listen URLs:

==== Discussion

`-K surl.cfg` (long form `--config`) reads options from the file in curl's config-file syntax: one option per line, `#` starting a comment, the option name with or without its leading dashes, and the value after an `=` or a space. This `surl.cfg` uses both spellings on purpose:

----
# Options for surl -K surl.cfg, one per line.
# The dashes are optional, and so is the = between name and value.
directory = site
user = alice:secret
mail-domain = example.com
--mailbox ann@example.com:secret
----

Every line is in force once `surl` starts. `--directory site` serves the files under `site`. `--user alice:secret` adds an account, so a request with no login is answered `401 Unauthorized`, and `curl` logs in with `--digest`: Digest sends no password in clear, which is why `surl` accepts it over plain Hypertext Transfer Protocol (HTTP); see <<http-log-in-with-digest>>. `--mail-domain example.com` and `--mailbox ann@example.com:secret` set up a mail domain with one mailbox on the Simple Mail Transfer Protocol (SMTP) listener; Ann logs in, and mail she addresses outside the domain is refused `550`, so `curl` exits `55`. <<smtp-serve-a-mail-domain>> has the details. On the `curl` side, `-s` keeps it quiet and `-S` still shows the error line, `-o` and `-w "%{http_code}"` print only the status code, `-u` gives the login, and `--mail-from`, `--mail-rcpt` and `-T mail.txt` give the sender, the recipient and the message.

A file can also hold the listen URLs, as `url = <listen URL>` lines, one per URL. The cases prove it indirectly: a file holding only `directory = missing` leaves `surl` with nothing to listen on, and it exits `2` with `no URL specified`; the same file with a `url = http://127.0.0.1:0/` line gets past that and stops at the missing directory, exit `37`. In this recipe the listen URLs are on the command line rather than in `surl.cfg`, for a reason of the book's own: the test harness picks a free port for each run and writes it into commands, but writes fixture files exactly as they are, so a port in the file could not follow it. On your own machine, with ports you choose, put the `url =` lines in the file and run `surl -K surl.cfg` alone.

The file is read in place, where `-K` stands on the command line, so a line in it overrides the same option given before `-K`: `--directory site -K no-url.cfg` ends up with the file's `missing` directory and exits `37`.

A mistake in the file stops the start. A name `surl` does not know, such as `directroy`, is refused with the file name and line number and exit `2`; it is never ignored, since a server that started without the option you meant would be worse than one that did not start. A file that cannot be read exits `37`.
