=== Listing and Uploading over FTP

==== Problem

You want an artificial intelligence (AI) agent to start a File Transfer Protocol (FTP) server, list a folder and upload a file into it through Model Context Protocol (MCP) tool calls, and then confirm from the server{apos}s side that the file is there.

==== Solution

Write the agent{apos}s side as a C# program on the MCP software development kit (SDK): it starts a server with `start_server`, lists and uploads with `curl-mcp`{apos}s `curl` tool, and confirms with `list_files` and `read_file`:

==== Discussion

The program starts both hosts by name with `StdioClientTransport`, each confined to the folder it runs in by `SURL_MCP_ROOT` or `CURL_MCP_ROOT`; `notes.txt` is written there, so that `curl -T` can read it. `start_server` takes the listen URL, `ftp://127.0.0.1:0`, where port `0` takes a free port, and answers in structured content with `server_id`, which every other `surl-mcp` tool takes, and `bound_urls`. `arguments` are `surl`{apos}s own options in its own words: `--allow-anonymous`, `--list-directories` and `--allow-uploads`, each of which loosens something and is off by default. `files` seeds the store in memory, here a file, a folder and a hidden file.

The `curl` tool runs a `curl` command line in-process and answers its `exitCode`, `standardOutput` and `standardError` as JavaScript Object Notation (JSON) text; `-s` keeps the progress meter out of the way. A URL that ends in a slash names a folder. With `-l` the answer is names only, one to a line, in the order `surl` lists them, and the hidden file is not among them (<<rfc959>>). Without `-l` it is the long listing, a line a name in the style of Unix `ls -l`, a folder{apos}s line starting with `d`. A subfolder is listed by naming it with its trailing slash. `-T notes.txt` uploads the local file to the path in the URL, and the next listing shows it.

The server{apos}s side confirms without a client. `list_files` answers a folder{apos}s `entries`, each with a `name` and a `kind`, `folder` or `file`, and `read_file` answers the stored file{apos}s `byte_count` and `text`: `uploaded by curl`, 17 bytes. They read the store directly, so they need no login and no listing option.

The refusals are surl{apos}s defaults, and each is a `curl` exit code that the tool also marks as a tool error. Without `--list-directories` a listing is answered `550 No such directory`, as if the folder were not there: exit `19`. Without `--allow-uploads` the listing works and the upload is exit `25`. Without `--allow-anonymous` the login `curl` sends, `USER anonymous`, is refused, and both are exit `67`, before anything is listed or uploaded.
