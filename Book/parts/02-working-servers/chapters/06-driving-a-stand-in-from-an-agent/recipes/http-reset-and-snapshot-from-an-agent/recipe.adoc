=== Resetting a Server Between Tests from an Agent

==== Problem

Your artificial intelligence (AI) agent runs several tests against one stand-in Hypertext Transfer Protocol (HTTP) server, and each test must start from the same files, whatever the test before it left behind.

==== Solution

A C# program on the Model Context Protocol (MCP) software development kit (SDK) starts a server through `surl-mcp`, sets up its files, calls `snapshot_server` once they are set up, and calls `restore_server` with the snapshot's ID when a test is done, then fetches through `curl-mcp` to show what is served:

==== Discussion

The program starts `surl-mcp`, the MCP server for `surl`, and `curl-mcp`, the one for `curl`, by name from the path, over standard input and output, each confined to the program's folder by `SURL_MCP_ROOT` and `CURL_MCP_ROOT`. The argument picks the scenario. `start_server` starts the server with `hello.txt` in memory; the program keeps its `server_id` and its `bound_urls` entry in two variables. `put_file` adds `fixture.txt`, the set-up a test wants, and `transfer`, from `curl-mcp`, is the client that checks what is served; the program prints the status and, for a 200, the body.

`snapshot_server` takes the server's ID and copies its stores, the files among them, and answers a `snapshot_id`, which the program keeps. Whatever a test then does, here `put_file` leaving `scratch.txt` and `delete_file` removing `hello.txt`, `restore_server` with the server's ID and that `snapshot_id` undoes. It answers both IDs back, which the program checks, and from the next request on, `scratch.txt` is `404 Not Found` (<<rfc9110>>) and `hello.txt` is served again. The server is not restarted: same ID, same URL, no new port to learn.

`reset_server` goes further back, to the state `start_server` gave: `hello.txt` is served and `fixture.txt`, put after the start, is 404 too. It takes only the server's ID and answers it. A snapshot outlives a reset, and restoring it after one brings `fixture.txt` back, as `read_file` shows without a client. Neither tool touches the record of what clients sent: after restores, a reset and four requests, `list_servers` still counts the four in the server's `exchange_count`, so an agent can reset between tests and still read every exchange afterward.

Only a server's newest four snapshots are kept. After four more, restoring the first is a tool error that says so, `only its newest 4 snapshots are kept`; an agent that snapshots often keeps the one it means to restore among the newest four.

A server whose files are a real folder, given with `surl`'s `--directory` option in `start_server`'s `arguments`, refuses `reset_server` and `snapshot_server` outright: `The content store is on disk (--directory)`, and the refusals are there so a test never empties a real directory. A stand-in that tests reset belongs in memory, with `files`.
