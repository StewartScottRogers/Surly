=== Uploading over FTP, Fetching over HTTP

==== Problem

You want an artificial intelligence (AI) agent to upload a file over File Transfer Protocol (FTP) and fetch the same file over Hypertext Transfer Protocol (HTTP) from one server, with Model Context Protocol (MCP) tool calls and without wiring two servers to one folder.

==== Solution

Write the agent{apos}s side as a C# program on the MCP software development kit (SDK): it starts one server that listens for both protocols with `start_server`, and makes one `curl` tool call that uploads over FTP and, after `--next`, fetches over HTTP:

==== Discussion

`start_server` takes two listen URLs, `ftp://127.0.0.1:0` and `http://127.0.0.1:0`, and answers `bound_urls` in the same order, each with the port the system chose. One server holds one store, so a file stored over one listener is there for the other; nothing is copied. `arguments` are `surl`{apos}s own options in its own words: `--allow-anonymous`, which lets in `curl`{apos}s anonymous FTP login, and `--allow-uploads`, which accepts the upload. Both loosen something and both are off by default.

The `curl` tool runs a `curl` command line in-process and answers its `exitCode`, `standardOutput` and `standardError` as JavaScript Object Notation (JSON) text. `-T notes.txt` to the FTP URL stores the file (<<rfc959>>), `--next` starts a second transfer with its own options, and the HTTP `GET` for the same name prints `uploaded over ftp`, in one call. Before the upload the same `GET` is `404`, which `-w %{http_code}` shows (<<rfc9110>>). `read_file` reads the store from the server{apos}s side and finds the same text, with no client at all.

The other direction works too: `-T` to an HTTP URL is a `PUT`, answered `201 Created` for a new file, and a plain FTP `GET` then downloads it. The server was given no account, so the `PUT` is accepted only because of `--allow-anonymous` and `--allow-uploads`.

`get_exchanges` takes a `scheme`, and answers only what came through the listeners of that scheme. The `received` chunks of the `ftp` listener hold the `STOR notes.txt` command, and those of the `http` listener the two `GET /notes.txt` requests, one before the upload and one after, so an agent can show which protocol carried what.

Each refusal is a `curl` exit code that the tool also marks as a tool error. Without `--allow-uploads` the FTP upload is answered `550` and `curl` exits `25`. Without `--allow-anonymous` the anonymous login is refused and `curl` exits `67`, login denied.
