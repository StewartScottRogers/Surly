=== Accepting Uploads from an Agent

==== Problem

You want an artificial intelligence (AI) agent to start a Hypertext Transfer Protocol (HTTP) server that accepts uploads from one account, put a file into it, and read the file back to check what the server stored, all with Model Context Protocol (MCP) tool calls.

==== Solution

Write the agent{apos}s side as a C# program on the MCP software development kit (SDK): it starts a server with `start_server`, uploads with `curl-mcp`{apos}s `curl` tool and `--digest -u`, and reads the stored file with `read_file`:

==== Discussion

`start_server` takes `arguments`, which are `surl`{apos}s own options in its own words. `--allow-uploads` is the one that makes the server accept a `PUT`, and `--user alice:s3cret` gives it an account, so that an upload has a login to be judged by. `files` seeds the store in memory. The answer holds `server_id`, which every other `surl-mcp` tool takes, and `bound_urls`.

The `curl` tool runs a `curl` command line in-process and answers its `exitCode`, `standardOutput` and `standardError` as JavaScript Object Notation (JSON) text. `-T notes.txt` makes the `PUT`, `--digest -u alice:s3cret` is the login, and `-w "%{http_code}"` with `-o` sends the answer{apos}s body to a file and leaves the status code, `201 Created` for a new file (<<rfc9110>>). `notes.txt` is written to the folder `curl-mcp` is confined to, so that `-T` can read it. Putting to the same path again replaces the file and is answered `204 No Content`.

`read_file` checks the server{apos}s side without a login: `byte_count`, `content_type`, which comes from the extension, here `text/plain`, and the exact `text` stored. A path with nothing at it is a tool error, `No file at /anon.txt.`, which is how the program shows that a refused upload stored nothing.

The refusals are the defaults, and each is a status, not a `curl` failure, so `curl` exits `0` and the program reads the code. A path whose folder does not exist is `409 Conflict`: `surl` creates no folders. An upload with no login is `401 Unauthorized`, and so is a wrong password. Without `--digest`, `curl` sends the password in clear with Basic, and `surl` refuses it unchecked with `403 Forbidden`. Without `--allow-uploads`, a logged-in upload is `405 Method Not Allowed`. With no account at all, an upload is still `401`, even with `--allow-uploads`, because no login can succeed; `--allow-anonymous` is what lets an upload through with no login, and it loosens the server for everyone who can reach it, so it is a choice made on purpose.

`get_events` with `kinds` `store_changed` lists what happened to the store, and the upload is one event: `written`, with the name `/notes.txt`.
