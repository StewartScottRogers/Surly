What it is

Every recipe is two commands facing each other: a surl that listens and a curl that talks to it. Surl is the server-side mate of curl, built to answer every scheme curl can request; Curl is a drop-in replacement for the curl command-line tool. Both are open source, both written in C# on .NET 10 as a matched pair, so each recipe shows a protocol conversation from both ends. Hypertext Transfer Protocol, File Transfer Protocol, Secure Shell, the three mail protocols, WebSocket, Lightweight Directory Access Protocol, and less common ones such as DICT and Gopher.

Recipes that run

A recipe is an executable specification. Every claim the text makes is a test case that is run against the two programs, and the book prints the result beside the claim. Where a claim can’t be tested, the recipe says so and cites its source.

Simple to hard

Ordered by difficulty, not by protocol: serve one file first; Kafka, gRPC and the other new protocols last. Open at any page; each recipe stands alone.

Readable by machines

An index of every recipe, by key, problem, protocol, option and exit code, so an AI finds the one it needs and reads nothing else. The recipes' own test specifications can also serve as a conformance suite for other implementations.

How it is written

Written and checked with AI agents following a published method: every recipe passes three checks (shape, truth, review), and the author decides what is published. Every decision and its reasons are in the repository.
