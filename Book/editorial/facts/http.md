# http facts
Checked against: surl 1.0.0 (Surl 763754785), curl (Curl b9ca725077), 2026-11-19, windows.
Only the limits and timeouts part so far; others add the rest.

## Listen URLs and readiness
`http://127.0.0.1:{{port}}/`, TCP, `ready: port`. `--directory <folder>` serves a folder; one surl holds a folder at a time, so give each server its own.

## Server options that matter
None of these loosens security. Each is 0 for no limit (`surl --aihelp limits`).
- `--idle-timeout <s>`: closes an exchange idle this long; default 120. Counts only silence the peer causes: while a `delay` fault holds the server the idle clock is stopped (decided in 763754785).
- `-m, --max-time <s>`: longest one exchange may take, from accept, idle or busy; default 3600. For HTTP an exchange is a connection, kept-alive requests included.
- `--head-timeout` 30 s, `--max-request-head` 100k, `--max-filesize` 100M, `--max-connections` 1024, `--max-connections-per-address` 100.
- A limit reached ends only that connection; surl keeps serving. Over HTTP/2, idle and max-time end with GOAWAY NO_ERROR.

## Secure by default
Login is judged before the method (ADR-0180): no account and no `--allow-anonymous` serves GET and HEAD, other methods 401; after a login, other methods are 405 `Allow: GET, HEAD` (`surl --aihelp http`).

## Served content
- Content-Type from the extension only, no charset: .html/.htm text/html, .css text/css, .js/.mjs text/javascript, .png image/png, .svg image/svg+xml, .json application/json, .jpg image/jpeg, .ico image/vnd.microsoft.icon, .woff2 font/woff2, .wasm application/wasm, .pdf application/pdf, .txt text/plain; unknown or no extension application/octet-stream.
- No index page: `/` and any folder are 404 with no Content-Type. Every 404 (and 401, and `--fault error` replies) has `Content-Length: 0`, so `--fail-with-body` has nothing to keep.
- Header order, 200: Date, Server: surl, Last-Modified, Content-Type, Content-Length. 404: Date, Server, Content-Length: 0.
- `--fault "error;scheme=http;path=/x;reply=503"` answers 503 with no `--directory` needed; quote it (`;`). Two surl processes on one `--directory`: the second exits 124.
- Ranges, always on: `bytes=100-199` 206 with `Content-Range: bytes 100-199/300` (header after Content-Type); `290-` to the end; `-20` last 20; an end past the end is cut (`280-999` -> `280-299/300`). Start past the end: 416 Range Not Satisfiable, `Content-Range: bytes */300`, Content-Length 0. Several ranges: 206 `multipart/byteranges; boundary=SURL_BYTERANGES`, each part `Content-Type`, `Content-Range`, CRLF ends, no top-level Content-Range. Invalid (`200-100`, `bytes=x`): ignored, 200 whole file.
- Any request header is accepted and served 200; `--trace-ascii` shows the head line by line (`0030: X-Api-Key: k123`), CR dropped, written before the response, so `curl -s -o NUL -H ... URL/x URL/trace.txt` (trace in the served folder) reads its own request in one command.

## Client: curl
- `-o`, `-O`, `--out-null` apply to one URL each; `--remote-name-all` gives every URL an `-O`. `-O` keeps only the last path segment; a trailing slash takes the folder name (`/docs/` -> `docs`); bare `/` -> `curl_response`. Existing files are overwritten.
- Missing folder for `-o` or `--output-dir` without `--create-dirs`: exit 23, `curl: (23) client returned ERROR on write of N bytes`.
- 404 without `-f`: exit 0 and `-o` writes an empty file. With `-f`: exit 22, no file, `-w` still prints; `-S` gives `curl: (22) The requested URL returned error: 404`. `%{url.path}`, `%{filename_effective}` (with output-dir: `dir/name`, `/` on Windows too) work.
- `--rate 1/3s` spaces the transfers of one command line, so a kept-alive connection sits idle between them.
- `-w "%{http_code} %{num_connects}\n"`: `num_connects` 1 is a new connection, 0 a reused one; shows a server close without reading a clock.
- A request unanswered when `--max-time` runs out is closed with no bytes: curl exit 52.
- Request head order: Host, User-Agent (`curl/8.22.0`), Accept `*/*`, then `-H` headers as typed (no space added after `:`). `-H` with a default's name replaces it (Host in place; User-Agent/Accept move to the end of the defaults); `-H "Accept:"` drops; `-H "X;"` sends `X:` empty; two `-H` of one name both sent.
- `-r 100-199` (both ends, from 0); 416 exits 0, with `-f` 22. `-w "%header{content-range}"` and `%{content_type}` work.
- Globbing `report-[1-12].csv` (quote it), `{a,b}` too; `-o "dir/report-#1.csv"` names from the glob. Over one connection (`num_connects` 1,0,0...). With `-f` the exit code is the last transfer's (0 if the last exists, despite earlier 404s); `--fail-early` stops at the first failure, exit 22. `-w "%{onerror}missing %{url.path}\n"` prints only for failed transfers (needs `-f` to count a 404 as failed).
- Awkward names (percent-encoding): surl decodes each %XX once. `my%20file.txt`, `caf%C3%A9.txt` (UTF-8 bytes; hex may be lower case), `a%23b.txt` all 200. Raw space in a URL: curl exit 3, nothing sent; raw `#` is the fragment, so `a#b.txt` requests `/a` (`-v` shows `GET /a`); `caf%E9.txt` (Latin-1), `my+file.txt`, `a%2523b.txt` (double-encoded) are 404. A raw é on a Windows command line reaches curl as Latin-1 (404): do not show raw non-ASCII in a console case.
- IPv6: `surl http://[::1]:P/` works; `127.0.0.1:P http://[::1]:P` listens on both at one port (log `Listening on` twice). IPv4 client to an IPv6-only surl: exit 7. Bare `http://::1:P/`: curl exit 3, surl exit 3 `URL rejected`. curl needs no `-g` for the bracketed host (it skips an IPv6 literal), `-g` only matters for `[1-2]`/`{}` in the path (`f[1-2].txt` globs without it, 404 with it). `-w "%{remote_ip}"` prints `127.0.0.1` / `::1`; request head `Host: [::1]:P`. A `[::]` listen URL is accepted by the surl CLI (not loopback) but refused by surl-mcp.
- Resume: `curl -C - -o f URL` sends `Range: bytes=<size of f>-`; surl answers 206 `Content-Range: bytes N-299/300`, `size_download` the missing part. Whole file already there: 416, exit 0, file untouched, `size_download` 0. No file: no Range, 200 whole. The partial file is not checked (wrong prefix joins silently, exit 0). surl honours `If-Range` against `Last-Modified` (HEAD gives it): a different date gets 200 and the whole file, and `-C -` then exits 33 and writes nothing. `-C -` with a 404 also exits 33.

- `--limit-rate 25k` (k = 1024): 100000 bytes took ~3.0 s and `%{speed_download}` ~33500, above 25600: the port lets about one second's worth through before pacing (200000 at 50000: ~3.0 s; at 100k: ~1.0 s). Unlimited, 100 kB over loopback ~0.1-0.3 s. The limit holds per transfer (two URLs each ~3 s). Claim ranges: time >= 2 s, speed < 50000. With `--max-time 1` exit 28, `-w %{http_code}` still 200, but `%{size_download}` and `%{speed_download}` print 0 although 51200 bytes were written (upstream reports bytes received).
- `-w` timings: `time_namelookup` ... `time_total` are moments from the start, six decimals; plain http `time_appconnect` `0.000000`; https > 0. A `--fault "delay;stage=command;ms=1500"` server: `time_pretransfer` < 1 s, `time_starttransfer` >= 1.5 s. Second URL on one command line reuses the connection: `time_connect` `0.000000`.
- Large test files: `setup: dd if=/dev/zero of=site/big.bin bs=1000 count=100` (a fixture must create `site/` first; `setup:` needs `schema: 2`).
- `--http1.0` request reaches surl as `GET ... HTTP/1.0`; `-w %{http_version}` prints `1.1` (surl answers 1.1). `--http2` over http:// upgrades (h2c) and prints `2`.

## Checks the programs do not do
- No HAR anywhere: no curl `--har`, no surl or MCP export. Build it from curl `-v` (request lines `> `), `-D`, `-o`, `-w` (see http-save-a-session-as-a-har-file). `-w` output on Windows can carry CR: pipe it through tr -d with a CR (backslash-r) before `read`.
- No digest header from surl (no Digest/Repr-Digest); a checksum check is the client's: `sha256sum` (Git Bash, Linux) or `shasum -a 256`.
- curl-mcp `transfer` body: check `isTruncated` before hashing `content` (base64 when `isBase64`).

## MCP
- `start_server(listen_urls*, arguments, files, files_base64)` answers structured `{server_id, listen_urls (as given, port 0 kept), bound_urls (real port, trailing /, same order), log_lines ["Listening on ..."]}`. Refusals: tool error with `{exit_code, exit_code_name, lines}` and text `surl: (N) ...` (path in a listen URL: 3 MalformedUrl); a non-loopback host, 192.0.2.1 included, is refused before binding: `{refused: "the listen host ... is not loopback; ..."}`, so 45 for an absent address cannot be shown through surl-mcp.
- `list_servers()` answers `{servers: [{server_id, listen_urls, bound_urls, started_at, exchange_count, dropped_exchange_count}]}`.
- `list_files(server_id*, path*, after_name, limit)`: `{entries: [{name, kind: folder|file, byte_count (files only)}], has_more}`, ordinal order, one level, dot files left out. `limit 2` + `after_name` pages. Errors (text only, tool error): `No folder at /nope.` (also for a file path); `docs` without `/` is `The path is not one a request may name (NotRooted).`
- `read_file(server_id*, path*)`: `{path, byte_count, modified_at, content_type, text | base64}` (text when valid UTF-8). Errors: `No file at /x.` for missing, a folder, and a dot file.
- content_type from the extension: .txt text/plain, .png image/png, .md text/markdown, .html text/html; matches the served Content-Type.
- curl-mcp `transfer(url*)` answers text JSON `{statusCode, headers [{name,value}], body {content, isBase64, totalBytes, ...}, info, failure}`; binary bodies come back base64.
- curl-mcp `curl(args*)`: `--output-dir`, `--create-dirs`, `-O` work inside CURL_MCP_ROOT. `--output-dir ..` or `-o ../x` is `PathRefused` (exitCode, streams null, tool error), text `Refused <opt>: <opt> '<given>' resolves to '<abs>', which is outside CURL_MCP_ROOT ('<root>').` Quirk: `-o` is resolved against the root, ignoring `--output-dir`, so `--output-dir downloads -o ../x` (inside for real curl) is refused. `-f` on 404: exitCode 22, failure kind CurlExit, tool error; standardOutput still holds `-w`.
- `start_server` accepts `files: {"empty.txt": ""}` (served 200, empty body); `transfer` of it and of a 404 both give body content "" and failure null.
- `transfer` `headers: [{name, value}]` are sent after Host and Accept, in order, duplicates kept; `userAgent` goes after Host. An empty value sends `Name:`; an empty `Accept` replaces the default with `Accept:` at the end (cannot drop it). No range field: put `Range` in headers; 416 is failure null, not a tool error. `transfer` does not glob (brackets sent, 404). From C#, pass `headers` as `JsonArray`/`JsonObject` (cast to `JsonNode` on `Add`): a `List<Dictionary<..>>` throws NotSupportedException in the SDK's serializer.
- `curl` tool accepts `-o "reports/report-#1.csv"` with a glob (Curl 7d167fa10a, BL-5597); it checks the name against `CURL_MCP_ROOT` with `#1` read as file-name characters, so `-o "../report-#1.csv"` is PathRefused before curl runs: `Refused -o: -o '../report-_.csv' resolves to '<path>', which is outside CURL_MCP_ROOT (...)`, `exitCode` null. Under verify, `standardOutput` came back with CRLF line ends on Windows; trim lines.
- `get_exchanges`: the first chunk with `direction` `received` holds the whole request head as text (`data`), CRLF kept.
- curl-mcp `build_url(scheme, host, port (string), path, query, fragment, flags ...)` answers text JSON `{url, failure, isError}`. It sets the path as given: a space or `#` stays raw. With `flags: ["UrlEncode"]` (libcurl CURLU_URLENCODE, name without prefix) the path is percent-encoded (`/my file.txt` -> `/my%20file.txt`, `é` -> `%C3%A9`, `#` -> `%23`, `?` -> `%3F`, `%` -> `%25`, `+` kept). `transfer` of a raw-space URL: tool error, failure `{kind: CurlExit, exitCode: 3}`; of a bare IPv6 `http://::1:P/x`: failure `InvalidRequest`, text `Invalid url: '...' is not an absolute URL with a scheme.`, exitCode null. `transfer` answers `info.primaryIp` (the address that answered).
- surl-mcp `start_server` with `http://::1:0`: tool error `{exit_code: 3, exit_code_name: MalformedUrl}`; `http://[::]:0`: `{refused: "the listen host :: is not loopback; ..."}`. `get_exchanges` (no cursor) gives the exchanges; the last one's first `received` chunk is the request head (use it to show a `Range:` the server saw). curl-mcp `curl` with `-C - -o dl/f` works inside CURL_MCP_ROOT; exit 33 is a tool error (CurlExit) with `-w` still in standardOutput.

- curl-mcp `transfer` has no HTTP version field (`info.httpVersion` "1.1"); choose a version with the `curl` tool (`--http1.0`, `--http2-prior-knowledge`, `-w %{http_version}`). `get_exchanges` chunk for HTTP/2 has `encoding` `base64` (decode: `PRI * HTTP/2.0`); HTTP/1.x `text`.
- `build_url` with `flags: ["UrlEncode"]` encodes the query's `=` too (`region%3Dnorth+east`, space as `+`); add `AppendQuery` to keep the first `=` (`region=north+east`). Refusals are tool errors `{url: null, failure: {kind: UrlRefused, text: "The URL parser refused <part>: CURLUcode N (Name)", exitCode: null}}`: port `eighty` or `99999` 4 BadPortNumber (part `port`), no scheme 10 NoScheme (part `url`), scheme `htp` 5 UnsupportedScheme, host with a space 21 BadHostname. Port is a string; `80` is kept in the URL.
- `parse_url(url, flags)` answers `{url, parts: {scheme, user, password, options, host, port, path, query, fragment, zoneId}, failure, isError}`; no port gives `port` null unless `flags: ["DefaultPort"]` (then "80"). Refusals (tool error, `parts` null): `:99999` 4 BadPortNumber, `htp://` 5 UnsupportedScheme (accepted with `NonSupportScheme`), no scheme 27 BadScheme (accepted with `GuessScheme`, giving http). Text: `The URL parser refused url: CURLUcode N (Name)`.
- curl-mcp `curl` answer: `{exitCode, standardOutput {content, isBase64, totalBytes, ...}, standardError {...}, failure, isError}`. `list_servers` `exchange_count` counts at once after a `transfer`.
- In a C# MCP program, `JsonSerializer.Serialize` of a string throws (reflection serialization is off in file-based apps); escape by hand.

## Surl.Api (in-process, C#)
- `SurlServer.BoundUrls` is `IReadOnlyList<Uri>`, `BoundUrl` a `Uri` (the first); `ListenUrls` stays as given.
- `SurlServerStartException.ExitCode` prints as its name (`BindFailed`); `Message` is `(45) Could not bind ...: <platform reason>` (Windows: `Address not available`); path in a listen URL: `(3) URL rejected: A listen URL cannot have a path, query or fragment`.
- `DataDirectory` keeps `<dir>/.surl/lock` while running; `/.surl/...` is 404. Second server on the same folder: 124 `DataDirectoryInUse`. `DataDirectory` + `Files`: `ArgumentException: DataDirectory and Files cannot both be given. (Parameter 'options')`.
- `Files` key errors (ArgumentException): `Files holds '<key>', which is not a '/' separated relative path with bytes.` for `/x`, `../x`, `a\b`, `a//b`, `c:x`; `Files holds 'docs' and a file inside it.` for a folder key. A dot-name key is accepted and 404.
- `StopAsync` returns `SurlExitCode` (namespace `Surl.Protocol.Abstractions`) `Ok`; again returns the same. With a `CurlClient` still holding a kept-alive connection it takes about 7 s; with clients disposed, a few ms. After stop: `CurlException` 7 `CouldntConnect`.
- Curl.Api `CurlRequest.Headers` and `RemovedHeaders` are init-only `IReadOnlyList`s (build the list first); Headers are sent as given, duplicates included, empty value as `Name:`; `RemovedHeaders = ["Accept"]` drops the default Accept. Curl.Api sends Host and Accept only. No client-wide default headers, no range option (use a `Range` header). One client over a series: one connection, one recorded exchange.
- Curl.Api `CurlResponse`: `Version` is `System.Version` (prints `1.1`), `Headers` is `IReadOnlyList<KeyValuePair<string,string>>` in received order and casing; `Trailers`, `Info` too. A 404 never throws from `SendAsync`.
- `CurlException` is in `Curl.Api.Errors`; `.Code` prints `UrlMalformat` (3) for a raw space or a bare IPv6 URL, `CouldntConnect` (7). `response.Info.PrimaryIp` is the address that answered (`127.0.0.1`, `::1`). `new Uri(base, "a#b.txt")` keeps `#` as the fragment (use `Uri.EscapeDataString`); `Uri.Host` of `[::1]` keeps the brackets, `IdnHost` is `::1`. A bare IPv6 listen URL: `SurlServerStartException.ExitCode` `MalformedUrl` (3). Two listen URLs with port 0 get two different ports. A raw é in a `CurlRequest` URL was 404 on Windows: not shown. `CurlResponse.StatusCode` is an int (`206`), `ReasonPhrase` `Partial Content`; `HttpMethod.Head` works and gives `Last-Modified`.
- Curl.Api versions: `CurlRequest { Http = new CurlHttpOptions { HttpVersion = HttpVersion.Http10 } }` (`Curl.Api.Options.Http`; values None, Http10, Http11, Http2, Http2Tls, Http2PriorKnowledge, Http3, Http3Only). `Response.Version`: Http10 -> 1.1 (with `Connection: close`), Http11 1.1, Http2 2.0 (h2c upgrade, request has `Upgrade: h2c`), Http2PriorKnowledge 2.0 (exchange starts `PRI * HTTP/2.0`), Http3 on http:// -> 1.1. HTTP/2 `ReasonPhrase` empty, header names lower case. `response.Info.HttpVersion` is 0 when read right after `SendAsync` (Info not final).
- `CurlClientOptions { UserAgent, Timeout, ConnectTimeout }` (TimeSpan); a client with no options sends no User-Agent. Per request `Http = new CurlHttpOptions { UserAgent = ... }` overrides it for that request only; a `User-Agent` in `Headers` replaces it and moves after Accept. `Timeout` 2 s against a 5 s `SurlFault.Delay(...) with { Stage = FaultStage.Command, Path = "/slow.txt" }` (`using Surl.Protocol.Abstractions;`): `CurlException` `OperationTimedOut`, `Operation timed out after 1007 milliseconds with 0 bytes received`. `CurlRequest` is a record (`with` works); `SurlFault` properties are init-only (use `with`).
- `Body` streams: 64 MiB served from `DataDirectory`, copied with `ReadAsync` to a FileStream, live heap (`GC.GetTotalMemory(true)`) rose ~0 MiB; buffering into a MemoryStream ~100 MiB. A 64 MiB copy over loopback plus writing takes ~10-20 s on Windows.
- Two `SurlServer`s in one process on port 0 get different ports; separate `Files`; a second on the first's `BoundUrl` throws `SurlServerStartException` `ExitCode` `BindFailed`.

## Gotchas
- Port 0: `surl` writes `Listening on <scheme>://<host>:<port>/` to stdout, one per listen URL; `-s` (and `--log-level none`) suppresses it, so a script waiting for it must not pass `-s`. Exchange log lines go to stderr. A console recipe that reads the port runs its own script (`run: sh find-port.sh`, the script as a fixture); `sh` is found on Windows through Git.
- `run:` lines run under `cmd.exe` on Windows; only a leading `surl`/`curl` is replaced by the pinned binary, so a script finds them on PATH.
- `--fault "delay;stage=command;ms=3000"` holds every request: with `--max-time 1` curl exits 52, with `--idle-timeout 1` it is answered 200.
- Margins of a second or more either side keep timing cases deterministic.
- verify's `ready: port` probe opens one exchange per listener (`#1 * Exchange 1 opened: http from ...`, then `No request head was read`), so a `--trace-ascii` record counted by exchange includes it; count requests (`#N * GET /path: 200, ...` lines, scheme from the matching `opened:` line) instead. In-process (Surl.Api) and surl-mcp have no such probe.
- `--trace-ascii` is written as it happens: a case can read it while the server runs.
- A C# program printing a non-ASCII name (é) prints it in the console code page on Windows: print the encoded path instead. `ready:` in recipe.yml is `port` (waits on 127.0.0.1) or anything else (a 0.2 s pause): `stderr-contains` is not implemented, so an IPv6-only server uses `ready: none`. `expect.stderr-contains` does not substitute `{{port}}`. Case-level `fixtures:` are rewritten before each case; cases share one folder, so a case that needs the partial file restores it. Bash heredocs in the harness shell lose backslashes: write generators with the Write tool.

## Seeding, resetting, snapshots
- `--allow-anonymous --allow-uploads`: anonymous HTTP PUT 201 (new) / 204 (over); FTP `curl -T` works. `--allow-anonymous` alone: PUT 405 `Allow: GET, HEAD`, FTP upload exit 25. Neither, no account: PUT 401, FTP anonymous login exit 67. Only `--allow-anonymous` warns at start. HTTP DELETE with both on: 405.
- A served `--directory` gets `<dir>/.surl/lock` (`ls -A` shows `.surl`). PUT to `/.surl/x` (logged in, uploads on): 409 Conflict.
- `setup:` lines run under cmd.exe on Windows; Git's `rm`, `cp`, `ls`, `grep` are on PATH there, and `&&` works.
- A script may start and `kill` its own surl, then `wait`; the lock is released and the next `rm -rf` of the folder works on Windows.
- surl-mcp: `reset_server` answers `{server_id}`; `snapshot_server` `{snapshot_id: p1}` (p1, p2 ... per host); `restore_server` `{server_id, snapshot_id}`. Newest 4 kept: older or another server's id is a tool error `server s1 has no snapshot p1; only its newest 4 snapshots are kept`. On `--directory`: tool error `Content: the store could not be snapshotted.` (or `reset.`) `The content store is on disk (--directory): reset, snapshot and restore are refused so a test never empties a real directory.` `get_events(kinds:[store_changed], store: content)`: `change` `seeded` (put_file), `written` (upload), `deleted`, `restored` (name `/`).
- curl-mcp `curl -T` into a missing FTP folder: exit 9. `curl -Q "DELE x" ftp://h/` deletes but then exits 19 (the listing of `/` is refused without `--list-directories`).
- Surl.Api seeds: `SurlSeedRefusedException` (an `InvalidOperationException`), `Store` (`StoreKind` `Mail`, `Content`), `Refusal`: `NoSuchAccount`, `InvalidAddress` (mail), `NotPermitted` (`/.surl/...`), `TooLarge` (`MaxFileSize`, which also caps mail: `MessageTooLarge`). `Message`: `Mail: Mail for bob@example.com was refused: NoSuchAccount.` A relative path is `ArgumentException ... (NotRooted)`. A refused seed publishes no event; a taken mail seed is `StoreChanged Mail Seeded ann@example.com/INBOX/;UID=1`. `Mailboxes` needs `MailDomains`.
- (Superseded at Curl 7d167fa10a, BL-5594: `HttpMethod.Put` with a body to `ftp://` is `STOR`, see ftp.md.) Before, Curl.Api PUT to `ftp://` sent RETR.
- Restart with state kept (surl-restart-a-fixture-with-state-kept, 2026-11-20): with `--directory data`, mail is kept under `data/.surl/mail/` (`index`, `messages/`) beside the lock; verify's `restart:` kills the process outright and the restarted surl (same command, ports) serves the files and mail, the stale lock no obstacle. IMAP `STATUS INBOX (MESSAGES UIDNEXT)` unchanged across a restart (UIDVALIDITY too, in a probe); new mail continues the UIDs. Without `--directory` a restart empties files and mail; `--mailbox` mailboxes come back (command line). SMTP with an account needs `-u` (CRAM-MD5 over plain smtp works); no login is 530, exit 55.
- Seeding every store from an agent (surl-seed-every-store-for-a-demo): one `start_server` with http, smtp, imap, mqtt, redis, ldap, dns listen URLs (port 0) works; `put_file`, `seed_mail`, `publish_message(retain)`, `set_key`, `add_ldap_entries` (a root `dc=example,dc=com` entry with no parent is accepted), `add_dns_zone` need no login. Refusal texts: `Mail: Mail for bob@example.com was refused: NoSuchAccount.`; `Directory: The LDIF entries was refused: line 7: a parent DN that is not in the file.` (all or none). Clients without login: redis exit 67, ldap `-u :` 38, mqtt 8.

## Uploading several files (http-upload-several-files-at-once, Surl 9ad60d80c / Curl 7d167fa10a, 2026-11-20)
- `curl -T "{a,b,c}.txt" URL/dir/` (or `"[a-c].txt"`) makes one PUT per file, name appended because the URL ends in `/`; `-w` prints one line each; one connection (`num_connects` 1,0,0). Without the slash all go to the one path (201, 204, 204; last wins). Missing folder: 409 each, exit 0. A missing local file in the list: curl uploads the ones before, prints `000` for it, stops with exit 26 (`curl: cannot open 'x'`), later files not sent. With an account and no `--allow-anonymous`: 401 each; `--digest -u` works per file.
- `--next ws://.../dir/` after the uploads lists the folder (needs `--list-directories`, ws on its own port); `-w` does not carry past `--next`. ws listing with an account: `--digest` over ws is not retried (401), Basic over ws 403: list over ws only with `--allow-anonymous` (or no account).
- Curl.Api: `Task.WhenAll` of PUTs on one `CurlClient` runs them side by side: `server.Exchanges.Count` (needs `RecordExchanges = true`, else InvalidOperationException) was 3; awaited in turn, 1. `server.Files.ListAsync("/reports")` returns `SurlFolderPage` (`Entries`, name order).
- curl-mcp `curl` refuses `-T` with `{}` or `[]`: `Refused -T: -T '{a,b,c}.txt' names files with glob characters ({}, []), whose expanded paths cannot be checked before curl runs.` (exitCode null, tool error). Pass `-T f URL` pairs. One `-T ../b.txt` anywhere refuses the whole call (`resolves to ... outside CURL_MCP_ROOT`). A missing local file: exitCode 26, tool error, earlier files uploaded. `list_files` entries have `byte_count`.

## Multiplexing, HTTP/3 fallback and Alt-Svc (batch-07: http-multiplex-requests-over-http2, https-fall-back-when-http3-is-missing, https-move-a-client-to-http3, each + twins; Surl 9ad60d80c / Curl 7d167fa10a, 2026-11-20, windows)

- Curl.Api: `Task.WhenAll` of five `SendAsync` on one `CurlClient` with `HttpVersion.Http2PriorKnowledge` and `CurlHttpOptions.PipeWait = true`: `server.Exchanges` grew by 1; without PipeWait 5; `Http11` with PipeWait 5. h2 exchange chunks have `Layer` Wire only, no `StreamId`.

- HTTP/3 fallback: `--http3` to a TCP-only https server: HTTP/2 (`-v`: `ALPN: server accepted h2`); `--http3-only`: exit 56 (CI agrees). A UDP listener that is not QUIC on the same port number (`tftp://H:P/` beside `https://H:P/`) logs each QUIC datagram as `opened: tftp`; `--http3` falls back to h2 in ~0.6 s, `--http3-only` without `--connect-timeout` waits the full 300 s and exits 28 (finding: ADR-0144 says a silent peer is 55 after ~10 s); with `--connect-timeout 2`: 28. Curl.Api `Http3Only` there with `CurlNetworkOptions.ConnectTimeout` 2 s: `OperationTimedOut`; against nothing on UDP: `CurlException` `RecvError` (56), message `QUIC: recvfrom() unexpectedly returned -1 (errno=10054; ...)` (Windows wording). curl-mcp: 56 `curl exit code 56 (RecvError)`, 28 `curl exit code 28 (OperationTimedOut)`, both tool errors.

- `--fault delay` at accept holds QUIC connections too (cannot slow TCP alone to make QUIC win).
- The `--http3` race: give QUIC time with `--happy-eyeballs-timeout-ms 4000` (Curl.Api `CurlNetworkOptions.HappyEyeballsTimeout`, a TimeSpan; on the request's `Network`). In Curl.Api the first QUIC handshake in a process is slow (JIT) and lost the race to TCP, or hung past 60 s, until the program warmed up with one `HttpVersion.Http3Only` request on a separate client.
- Alt-Svc: answers over HTTP/1.x and HTTP/2 carry `alt-svc: h3=":P"; ma=86400`; HTTP/3 answers carry none. `curl --alt-svc f` writes two comment lines and `h2 127.0.0.1 P h3 127.0.0.1 P "YYYYMMDD HH:MM:SS" 0 0`. - QUIC in the server's record: `--trace-ascii` QUIC exchanges have `Decrypted bytes ..., stream N` lines and end `closing the flow.`, TCP ones `TLS handshake completed: Tls13, ..., ALPN h2` and `closing the connection.`; Surl.Api `SurlExchangeChunk.StreamId` non-null and `Layer` Decrypted/Decoded; surl-mcp `get_exchanges` chunks with `stream_id` and `layer` `decrypted`/`decoded`.

## Parallel, conditional, cancel, progress (batch 7, Surl 9ad60d80c / Curl 7d167fa10a, 2026-11-20, windows)
- Conditional requests in this build: no `ETag` header; `If-Modified-Since` (even the exact Last-Modified) and `If-None-Match` are answered 200 with the body. curl `-z f` then discards the body and reports `%{http_code}` 304 itself (`-v`: `The requested document is not new enough`, `Simulate an HTTP 304 response`), file untouched. So write cases that hold either way (curl's 304 and the untouched file), not "surl answers 304" or "surl ignores it". `--etag-save` writes an empty file. `-R -z` after a skipped fetch still sets the local mtime to the server's (possibly older) Last-Modified. `-z` on a missing local file fetches unconditionally (warning silenced by `-s`). Without `-f`, a 404 with `-o local` truncates the existing local copy.
- `--max-connections-per-address N`: a connection past N is answered `503 Service Unavailable`, `Content-Length: 0`, `Connection: close`, no Date or Retry-After; log `#- * Refused a connection from 127.0.0.1:P: past --max-connections-per-address N.` curl `--parallel` (default 50) over `f[1-50]` against N=8: 11-26 of 50 get 503 (100 kB files); `--parallel-max 8`: all 200 (but curl may open a 9th connection, closing one; never saw a 503). `--retry 10 --retry-delay 1` recovers all (~10 s). With -f the exit is 22; without, 0 and empty files.
- `--parallel` with `--next` blocks: each block needs its own `-s -f -w -o -r`. Four ranges in parallel reuse connections unless `--parallel-immediate` (even against a 1 s delay server, without it the second transfer reused one).
- Curl.Api: `CurlClientOptions.MaxConnectionsPerHost` caps connections per host for concurrent `SendAsync`; 0 (default) = none (50 concurrent vs per-address 8: ~38 503s). `CurlNetworkOptions` is in namespace `Curl.Api` (MaxConnects). `CurlRequest.Progress` (`IProgress<CurlTransferProgress>`: UploadNow/Total, DownloadNow/Total, speeds, `Phase` Connecting/Uploading/Downloading) is called on the engine thread; 16 MiB PUT gave ~259 reports, non-decreasing, last 16777216/16777216. A 405 PUT: reports stay Connecting 0/0. No time-condition option: send headers.
- Cancel: a `CancellationToken` cancelled during a `SurlFault.Delay` (Stage Command) throws `OperationCanceledException` (~1.0 s); `Timeout` throws `CurlException` `OperationTimedOut`. Next request on the same client: new connection (`Info.NumConnects` 1), 200 at once. surl keeps the delayed exchange open (no ExchangeEnded within 10 s after the client closed), so with `MaxConnectionsPerAddress = 1` the next request is 503. `StopAsync` then ~5-7 s.
- `SurlFault.DropConnection() with { AfterBytes = n }` is accept stage: `Path` is refused at start (`key path cannot be given at stage accept`); add it with `server.Faults.Add` after a warm-up. Mid-body drop: body `ReadAsync` throws `CurlException` `RecvError` (Windows, `Connection was reset`).
- `SurlServerOptions.TimeProvider` drives `Date` and in-memory files' `Last-Modified` (`PutAsync` takes the clock's now), so a frozen clock makes same-second rewrites deterministic. `server.Files.ReadAsync` returns `SurlFileContents` (`Bytes`, `ByteCount`, `ModifiedAt`, `ContentType`); `SurlExchangeRecord.Received` is `byte[]`.
- surl-mcp `start_server` with ~5 MB of `files` (50 x 100,000 chars) never returned (killed after minutes); 50 x 50,000 works. curl-mcp `curl` tool takes `--parallel`, `--parallel-max`, `-o "out/f#1.txt"` with a glob, and `-R -z local/f -o local/f` (304 on the second call).
- Windows `setup:`/`run:` lines go through cmd.exe: `mkdir -p x` is cmd's mkdir (makes `-p`); make folders with a fixture file (`site/.keep`) or inside an `sh` script. `diff -r -x .surl site out`, `cmp`, `touch -t`, `head -c` work there.

## Links, replay, HttpClient, download cancel and progress (batch-09: http-follow-links-inside-the-served-folder, http-replay-exchanges-without-the-server, http-plug-curl-into-httpclient, http-cancel-a-download-midway, http-report-download-progress; Surl 9ad60d80c / Curl 7d167fa10a, 2026-11-21, windows)
- `--follow-symlinks` (widens, no start-up warning): a link to a file or a folder inside the root is served at the link's path; a link that resolves outside (`../outside/x`), or a link to such a link (chain judged by its end), is 404 with no bytes sent.
